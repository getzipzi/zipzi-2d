# 对象删除与依赖清理方案

日期：2026-10-29。状态：设计方案，尚未实施。现有入口、快捷键及菜单反馈已提交到 `9347bb20`。

正常删除应自动处理已知引用，保留没有要求删除的业务对象，并在提交前说明连带影响。
删除一个被当作 Mask 的 Mesh，应解除其他对象对它的 Mask 引用；删除 Part，应清理它的
Pose 和动画记录。上述引用不应成为必须手工逐项解除的障碍。

“安全”指结果结构一致、影响范围明确、操作原子且可撤销。删除 Mask、Glue 或动画轨道
本来就可能改变外观或运动，不能把安全删除解释为画面完全不变。

## 已有实现与需要替换的行为

当前 `SceneEdit::Delete` 和 `OrganizationEdit::Delete` 能计算子树，删除所属绑定，
更新部分组织与绘制记录；范围外引用统一返回 `OBJECT_REFERENCED`。事务、版本检查、
候选结构校验、句柄失效及撤销已有基础。纹理替换删除、顶点依赖清理、Offscreen keyform
重映射也已有局部能力。

Editor 的 `TreeDeletionPlan` 仍按树投影选择组织删除或变形删除。因此，同一个 Deformer
从不同入口删除，可能得到不同范围。当前确认框只列出要删除的对象，不能解释或选择
保留对象上的修改。

本方案用共同的删除规划器替换这些入口上的整批引用拒绝。普通 Delete 就执行依赖清理；
不另设一个跳过校验的 `force: bool`。底层仍可保留严格拒绝引用的原始操作，供要求
“不修改任何外部对象”的调用者使用，但不能再作为 Editor 正常删除的默认策略。

## 删除目标与范围

删除请求保存明确的根对象及每个根的范围选项。快捷键、tree、viewport、Edit 菜单和
Python 使用同一套规则；入口名称、当前展开状态、搜索过滤、可见性及相邻行不决定范围。

| 根对象 | 普通 Delete 的默认范围 | 可选操作 |
| --- | --- | --- |
| Mesh | Mesh 及其所属绑定和内部身份 | 无需额外范围选项 |
| Part | 组织子树及其中的场景对象 | 解散 Part，保留并迁移内容 |
| Deformer | 变形子树及其中的 Mesh | 只移除该 Deformer，保留并迁移子节点 |
| Offscreen | 合成对象及其所属形状和绑定，保留所属 Part 和 Mesh | 需要迁移时使用已有显式迁移操作 |
| Glue | 连接、顶点对及所属绑定，保留两侧 Mesh | 删除部分 pair 仍走内容编辑 |
| 参数 | 参数及按下文规则处理的引用 | 可指定轴降维取值 |
| 参数文件夹 | 解散文件夹，内容迁移到保留的上级 | 明确选择删除文件夹及参数 |
| 纹理或附件 | 资源及其明确的引用处理 | 替换引用或解除可选引用 |
| Motion、Expression、Pose、Physics 及其子对象 | 对象自身的所属内容和对应注册记录 | 保留既有业务域的迁移、替换选项 |

范围首先按每个显式根计算，再求并集、去重并记录来源。不能先把“处于选中 Part 内的
Deformer”判为冗余根，否则会丢失用户明确请求的变形子树范围。目标顺序不影响最终结果。

删除 Part 时，不能因为其中一个 Deformer 还控制着另一个 Part 的 Mesh，就静默扩大到
另一个 Part。对于仅因组织归属而被删除的 Deformer，范围外的变形子节点按保留对象处理，
迁移到最近保留的变形祖先。显式选择该 Deformer 删除变形子树时，则按用户的范围请求
纳入这些节点，并在确认框中清楚列出其不同 Part 归属。

所属资源和共享资源必须分开处理。删除 Mesh 会删除它的普通绑定和 BlendBinding；
不会顺手删除纹理、参数、仍被使用的 Blend key table、constraint 或其他业务资源。
即使共享资源因此不再被使用，本次也不做全局垃圾回收。

## 各种引用的默认处理

规划器区分所有权、可移除连接、可移除记录、需要转换的结构关系和共享资源使用关系。
不能沿所有反向引用递归删除引用方。下表的“删除记录”始终指具体子记录，不是它所在的
整个 Motion、Pose、Physics 或 Mesh。

| 引用关系 | 默认处理 | 保留对象及需要说明的影响 |
| --- | --- | --- |
| Mesh 或 Offscreen 的 Mask 来源被删 | 从 Mask 列表移除该来源，保留其余来源及顺序 | 保留使用 Mask 的对象；说明裁剪效果改变。最后一个 Mesh Mask 被移除时规范化无效的反向裁剪状态 |
| Glue 的任一 Mesh 端点被删 | 删除该 Glue 连接、全部 pair 和所属绑定 | 另一侧 Mesh 及其自身绑定保留；说明接缝或联动消失 |
| 仅 Glue pair 的顶点端点被删 | 显式选择清理依赖时只删除受影响 pair 和相关拓扑内容 | 保留 Glue 和两侧 Mesh；复用已有顶点删除报告 |
| 普通绑定或 BlendBinding 的宿主被删 | 删除所属绑定及其 axes、samples 等内部身份 | 保留驱动参数与共享表；保留对象的无关绑定不变 |
| 保留对象的变形父级被删 | 迁移到最近保留的变形祖先，优先执行参数域保留转换 | 保留整个对象；转换保证、成本及外观影响进入报告，不能只清空 parent 字符串 |
| 解散 Part 后的组织成员 | 迁移到最近保留的组织祖先，维持相对顺序 | 组织归属、变形父级及绘制归属分别处理；Offscreen 必须有合法 Part 所有者 |
| 绘制组所有者被删但仍有组外成员 | 把保留成员归入最近保留的绘制组，按原展开顺序插入 | 不删除这些成员；组范围、动态顺序和合成效果不能完整保留时报告具体影响 |
| Pose member 的 Part 被删 | 删除指向该 Part 的 entry 及其所属 links；清理其他 entry 中指向它的 link | 保留其他 member、group 和 Pose；空 group 可保留 |
| Motion 中 Part opacity 轨道的 Part 被删 | 删除该轨道及所属 keys、segments | 保留 Motion、注册项、事件和其他轨道；Expression source scene 中的同类轨道也处理 |
| Hit Area 的 Mesh 被删 | 删除对应 Hit Area 记录 | 保留其他 Hit Area 和 Model3 配置 |
| CDI Part 显示记录的目标被删 | 删除相应解析记录，清理相应 EditorState 与各类排序表 | 既有未解析导入记录不因本次操作被批量清空 |
| 纹理被删 | 用户已选择替代纹理时重定向；否则可明确确认把使用者设为未配置纹理 | Mesh 保留；未配置纹理会影响渲染和导出，必须确认 |
| 声音附件或 UserData 附件被删 | 清除可选 sound／UserData 引用 | 保留 Motion 注册项和项目；说明声音或导出内容减少 |
| Motion 被删 | 删除 Clip 的所属内容以及指向它的注册项 | 保留 Motion group、其他 Clip、注册项引用的声音附件 |
| Physics 输出引用被删的节点 | 用户指定保留节点时重定向，否则删除该 output 记录 | 保留其他 output；不能创造非法物理链 |

空记录容器是否允许保留，由该业务域的原生不变量决定。允许为空的 Motion／Pose group
可以保留；不允许的容器不得靠填入假的 ID 或未解析引用维持结构。

### 导入扩展与导出可用性

带 opaque 扩展的 Motion、Pose、Expression、Physics 和 CDI 保存了导入时的命名空间，
部分域还保存内容 hash。删除 Part 或参数即使没有直接引用，也可能因全域命名空间变化
触发 `OPAQUE_NAMESPACE_CHANGED`；清理轨道、entry 等已知内容也可能触发
`OPAQUE_CONTENT_CHANGED`。结构合法且没有新增悬空引用，不代表这些资源仍可导出。

完整规划必须比较冻结来源与最终候选的导出可用性，枚举受影响的保留资源、格式及原生
错误类型。检查包含没有直接引用删除目标的 opaque 资源；既有导出问题与本次新增问题
分开报告。复用原生导出前置校验，不为分析编码整份导出文件。

本次新增的 opaque 导出失效进入必要选择：用户可显式接受所列资源暂时无法导出并保留
原扩展及 provenance，或取消删除。只有已有原生转换明确支持时，才提供丢弃指定扩展
等有损修复选项，列出实际改写并重新规划、校验锁和导出结果。接受导出失效不解除未知
引用阻碍，也不改变后续导出的校验行为。不能刷新 `opaque_source_ids` 或内容 hash，
不能自动删除扩展、未解析导入记录或整个资源来伪造新的安全基线。

### 参数删除

删除一个参数会影响模型的控制自由度，需要完整报告，但不应该要求用户逐个删除所有
使用它的绑定、动画、表情和物理通道。

普通 Mesh、Scene、Glue 绑定中的该参数轴，默认在参数的 `default` 值降维，复用
`AxisReduction::Slice` 或 `Resample` 的原生转换。默认值来自冻结文档，不取决于当前
Editor 的临时滑块、播放或 Physics 状态。用户可以显式改用一个有效坐标重新规划。
其他参数轴和绑定宿主必须保留；删除最后一维时需要把结果落实到合法静态数据。

由该参数驱动的 Blend key table 及其 BlendBinding 纳入删除；以该参数为条件的 constraint
从保留的 BlendBinding 上解除，并删除该 constraint。保留其他参数的表和绑定，不删除
宿主 Mesh。移除 Blend 贡献属于明确的行为损失。额外提供“冻结默认值贡献”的转换选项时，
必须由转换器证明所覆盖的通道和参数范围，不能承诺所有组合姿态的画面等价。

Motion 参数轨道、Expression 参数 entry、Physics input／output、Model3 参数组成员和
CDI combined member 等分别删除对应记录。若操作使 Physics 等容器不再满足原生约束，
报告具体容器及合法选择，例如删除该设置组或取消参数删除。不能把不合法的空输入、
输出或链条静默发布。

### 无法完整保留的迁移

保留子节点时优先复用 `ReparentStrategy::PreserveParameterDomain`，沿用现有误差、
预算及转换范围报告。非线性父级、奇异变形、受影响参数域和合成通道都可能限制保证。

无法证明全域保留时，进入明确选择，提供实际可用的方案：

- 采用可证明的当前编辑状态保留，并说明其他参数姿态的限制。
- 保留局部数据后重新挂接，说明外观和运动可能改变。
- 用户主动扩大为删除相应子树，并重新展示新增删除对象。
- 取消操作。

不能静默从“保留”降级成“删除”，也不能把转换器不支持直接表述成“存在引用不能删”。
Offscreen 找不到合法 Part 所有者、绘制角色无法满足原生范围等情况也采用同一选择流程。

## 锁和真正的阻碍

锁保护的是实际删除和改写的对象，包括被解除 Mask 的 Mesh、将被删除的 Glue、
Pose member、Motion track、绑定内部身份和继承锁来源。

被锁的受影响对象会列入阻碍清单，用户可以定位并显式解锁后重新规划。不能在删除
实现中跳过锁，也不能为了改写一个后代而自动解锁整个外部祖先。仅被读取的纹理、
参数、祖先和没有实际变化的共享资源，不应被当作写入对象而要求解锁。

真正不能直接提交的情况限于：目标或来源已过期、实际写入受锁保护、用户尚未选择
必要的替代／有损方案、没有合法的结果结构、预算不足或取消。普通已知引用本身是
清理任务，不是阻碍。

未知引用类型必须作为带地址和原因的阻碍返回；不能忽略或转成假的未解析对象。
新增关系类型必须补齐删除规则，避免未来又退化成全局引用拒绝。

## 共同规划器与接口

领域关系、默认清理规则和最终结构校验属于 `zipzi-core`；身份、版本、事务和历史属于
`zipzi-sdk`。Runtime 管理来源、PlanId、预算及取消，Python 只映射类型和调用。
Editor core 保存选择与上下文，Editor 展示报告和确认。不能在 GPUI 或 Python 中
另写一份依赖遍历器。

导出可用性规则属于 `zipzi-project`。SDK 在 Core 候选上协调来源与结果的导出前置
校验，将类型化的新增导出失效及必要选择合入报告；该校验完成前不能生成可执行的 SDK
计划。Core 不依赖 Project，客户端也不自行推断 opaque 扩展是否安全。

新增原生 `deletion` 模块，结构概念如下，具体类型需要复用各域已有身份和字段地址：

```text
DeletionRequest
  roots                  明确的类型化根对象及范围
  resolutions            针对具体关系的处理选择
  conversion_context     冻结的取值和参数域，仅在需要转换时携带
  conversion_source      可选的取值来源身份，用于当前编辑状态保留

DeletionAnalysis
  requested              用户请求的根及范围
  removed                删除项，区分显式根、所属内容及依赖记录
  rewritten              保留对象上将改写的字段
  relations              原因、来源、目标及原生字段地址
  decisions              需要用户选择的关系及可用选项
  blockers               锁、未知关系、结构或预算等阻碍
  effects                外观、动画、合成和导出的影响
  cost                   影响数量和转换成本估计

DeletionPlan
  source_identity        精确的原生快照、SDK 版本及适用的转换来源身份
  request                产生本计划的目标与选择
  prepared_change        已验证的跨域修改，内容不对调用者开放
  report                 已验证的影响、转换保证和损失
```

Core 使用删除专用的原生类型化目标及关系，不依赖 SDK 的 `ObjectKind` 或 Editor 的
`ObjectRef`。SDK 把 `ObjectHandle` 映射到原生目标。身份包含对象种类与 ID；Part
及其 DrawOrderGroup 可能共享 owner ID，不能仅按字符串 ID 合并成一个删除对象。

当前 `references_to()` 返回字符串列表，里面既有对象 ID，也有格式化的轨道说明和
元数据路径，不能据此执行清理。新增统一的类型化关系枚举，涵盖反向使用者和所属子身份。
关系至少包含所有者身份、原生字段或子记录地址、关系种类及目标身份。已有稳定 ID 的
轨道、entry、pair、sample 使用稳定 ID；没有独立身份的存储槽采用冻结来源下的原生地址，
不能在文档变化后继续按旧索引执行。

现有字符串诊断和 Editor 关系展示逐步由同一枚举派生。不要把删除专用规则塞入名称解析，
也不要使用 Editor 当前关系面板作为领域数据来源。

SDK 提供 `analyze_deletion`、`plan_deletion`、`execute_deletion_plan`，并把删除接入
`ModelingIntent`／`ModelingPlan`。预检查区分可执行、需要确认、需要选择和受阻；
`CapabilityState` 不再因为普通可清理引用就返回不可用。UI 的确认需求由删除报告表达，
不需要给所有业务域增加新的全局 capability 变体。

`DeletionReport` 的对象、关系、处理方式、保证和阻碍都采用类型化字段，文字由客户端
本地化。不能依靠 `losses: Vec<String>` 或解析错误句子决定是否可以提交。报告同时区分
删除所属内容、删除依赖记录、改写保留对象和需要用户选择的有损转换；后两者也必须
进入 SDK change receipt。API shape、Runtime 调度、Python DTO、公开目录和帮助由
现有生成流程同步更新，Local 与 Connected 消费同一份类型和计划语义。

## 规划与提交算法

1. 冻结来源，校验每个根的身份，按原生顺序计算每个请求范围，求并集并保留原因链。
2. 纳入所属绑定和内部身份；枚举从保留对象指向删除集合的关系，按领域规则产生改写
   或依赖记录删除。新加入的删除记录继续处理其所属内容，直到集合稳定。
3. 若引用方也在删除集合中，不再为它生成无意义的解绑；有存活引用方时才生成必要改写。
   同一字段的修改必须在原始来源上合并，检测冲突，而不是靠多个操作最后写入者获胜。
4. 确认存活的共享资源、迁移目的地和实际写集合，收集锁来源及必要选择。关系循环按
   受影响集合统一处理；Mask 循环或互相引用不要求用户寻找一个不存在的删除顺序。
5. 在私有候选中构造跨域修改，执行必要的绑定／变形／绘制转换。删除与清理在最终结果
   上统一校验，不允许中间态暴露给 Runtime、Editor 预览或正式文档。
6. 验证所有被删除身份不再被保留对象解析引用，检查各业务域结构、排序、内部身份和
   共享资源约束；SDK 完成来源与候选的导出前置校验。新增导出失效未获明确处理前，
   仅返回分析与必要选择；完成选择后产生精确的结果报告和可执行计划。
7. 用户确认报告后，核对来源、编辑身份、版本、适用的转换来源身份和取消状态，发布计划
   所持有的那份修改。清理依赖和删除对象形成一个提交、一个撤销步骤及一份完整 receipt。

不能通过依次调用现有严格删除方法拼装算法：每一步的引用检查会把合法的最终结果
误判为失败，而且循环关系没有合法的逐项顺序。可以复用领域记录构造和转换器，但需要
删除专用的组合修改边界。当前组织 `Delta` 没有覆盖所有动画／Pose 等域，不能假定它
直接容纳全部改动。使用删除专用的各域 patch，在同一私有 fork 中完成最终校验；
借鉴已有持有已验证候选的计划安装方式，发布时不重新遍历并选择另一套删除结果。

执行时若来源变化，返回过期并要求重新查看计划，不能悄悄重新规划后执行扩大过的范围。
在 SDK／Runtime 事务内先清理其他内容再规划删除时，计划也必须绑定精确的 Edit 身份
和候选序列。不能只比较正式文档 revision，更不能复用撤销后恢复的旧对象句柄。

选择“保留当前编辑状态”时，Editor 必须同时冻结实际送入转换器的参数取值、时间及
预览来源身份，并沿用现有 reparent 的 `preview_revision` 校验。滑块、播放或 Physics
改变相关预览来源，即使正式文档和 Edit 序列未变，也使旧计划过期；提交前重新校验，
要求重新捕获取值并审阅。该检查由拥有预览状态的 Editor core 执行，Core 接收原生
冻结取值，不依赖 Editor 类型。Runtime 对其管理的取值来源使用对应的来源身份；
Python 显式传入的固定取值以完整上下文作为请求身份，不隐含读取某个客户端的当前预览。
仅使用文档 default 的参数降维不绑定临时预览 revision。

撤销恢复删除内容、被解除的引用、所有排序和元数据；重做复用原结果。已退役的句柄、
字段地址和 PlanId 不因 Undo 恢复同一字符串 ID 而重新有效。既有未解析导入记录保持
原样；不能用“转成 unresolved”掩盖本次新产生的悬空引用。

发布后，Editor 统一协调场景选择、inspector、绑定轴和 Timeline 选择，移除已删除身份，
优先保留仍有效的多选，再按发起操作的上下文选择保留的同级或祖先。不要为了选中一个
回退对象而切换到另一种工作区。Mask、Glue、Offscreen、绘制和动画变化必须覆盖相应
缓存与预览失效；仅删除一条轨道时，仍存在的 Motion 和播放时钟按现有规则保留。
待返回的旧预览或 Job 不能重新写回已删除目标。

删除资源只改变模型／项目拥有的资源记录，并沿用项目的内容留存与历史规则。删除 Mesh
不删除其共享图片，删除图片或附件也不能直接 unlink 用户导入来源文件；撤销仍需能够
恢复相应项目内容。

## Editor 交互

继续使用现有 `Delete Object` 命令和 Delete／Backspace。tree 右键保存行目标或原多选；
viewport 删除当前选择；输入框、Timeline、Mesh Edit 保持各自的编辑语义。
范围来自上述对象规则，所有入口使用同一份报告。

菜单只显示短名称、快捷键和必要的短状态。没有选择或暂时受阻时仍可点击，由 status bar
显示短原因；完整的关联和选项进入删除审阅，不把长原因拼到菜单标题。

| 规划结果 | 交互 |
| --- | --- |
| 单个对象及所属内部内容，无外部改写或扩大范围 | 直接提交；status bar 短反馈，可撤销 |
| 删除多个可见业务对象、删除子树或修改保留对象的关系 | 打开一次影响确认，使用推荐处理，不要求逐条勾选 |
| 需要替代对象或转换降级选择 | 在同一个审阅里选择并重新规划；有效结果出现前不开放确认 |
| 锁或其他实际阻碍 | 显示对象、锁来源和可定位操作；解锁或修改条件后重新规划 |

审阅内容分为“删除”“保留并修改”“外观与动画影响”“需要处理”四组。每项说明
“对象、关系、处理方式”，例如“保留 Mesh B，解除对 Mesh A 的 Mask 引用”。所属
axes、samples、keys 默认折叠；不能把几千个内部 ID 平铺成主列表。

普通依赖清理的主按钮为“删除并清理”，范围删除显示主要对象数量，确认默认聚焦取消。
需要显式接受有损转换的内容单列，不能藏在“强制”复选框里。取消、关闭、预算拒绝及
重新选择过程都不能写正式文档。确认后不再弹第二轮同类确认。

## 性能与能力查询

轻量分析复用类型化反向关系索引及子树索引；不得在菜单绘制或每帧 command state 查询中
执行完整候选复制、全域重采样或大型计划构造。缓存按精确文档版本、根目标及选项失效；
涉及转换时还必须包含完整的冻结上下文及适用的取值来源身份。
已有引用字符串扫描替换成共同索引时，同时移除重复的独立扫描逻辑。

完整规划冻结一次来源，计算成本并做预算准入；大型转换使用已有取消控制和 Runtime
任务机制。修改选项或相关预览来源取消旧计划，迟到结果按请求序列及转换来源身份丢弃。
导出前置校验同样受预算和取消控制。需要计入源快照、候选、转换临时内存、报告和历史
成本。大型影响报告分页或按种类聚合，精确地址由计划持有，
不能为了生成一次 UI 清单把整份模型通过 Python／IPC 来回复制。

## 实施顺序与完成条件

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| 一 | Core 类型化关系及删除规划器，SDK 原子计划；支持 Mesh、Part、Deformer、Offscreen、Glue 根对象及所有指向这些类型的已知引用 | Mesh 的 Mask、Glue、Hit Area 引用可自动处理；Part 的 Pose／Motion 引用可处理；变形与组织跨树关系有明确迁移或有损选择 |
| 二 | Runtime／Python 接入与 Editor 全部删除入口切换，影响审阅、短状态反馈及轻量能力查询 | 所有入口对相同根和选项得到相同计划；具有普通可清理引用的对象不再被菜单和快捷键拒绝 |
| 三 | 参数、资源、附件和其余业务对象统一接入；复用已有纹理替换、轴降维、物理节点替换及动画迁移能力 | 参数能一次清理绑定／Motion／Expression／Physics／元数据使用者；所有有损和非法容器情况都有明确选择 |

阶段二完成才算场景对象删除交付，不能停在“SDK 已有新 API，Editor 仍旧一律拒绝引用”。
阶段三完成前，其他域维持现有行为，能力报告必须准确反映其尚未接入的范围。

正式执行入口必须在提交前接入 Runtime 来源和预算管理。Editor 与 Python 都不直接绕过
Runtime 修改 SDK 文档；阶段一只提供原生及 SDK 能力，不在 UI 中暴露一条临时旁路。

## 验收场景

- 删除 A，B 的 Mask 指向 A，Glue 连接 A 和 C，Hit Area 指向 A：保留 B、C 及其无关
  绑定和纹理，解除 B 的该项 Mask，删除 Glue 及 Hit Area，报告外观影响，一次撤销完整恢复。
- 同一多选的不同顺序、同时选择父子、互相引用的 Mask、共享 Glue 和重复清理路径，结果
  去重且一致；选择外部引用方不会改变未明确指定的范围规则。
- 删除 Part，清理 Pose entries／links 和 Motion Part opacity 轨道，同时保留 Motion、
  Pose 其他成员、注册项、事件和共享资源。
- 使用含 opaque 扩展的 Motion、Pose、Expression、Physics 和 CDI 合成数据，覆盖删除
  无直接引用的 Part／参数导致命名空间变化，以及清理轨道／entry 导致内容 hash 变化。
  报告准确区分既有和新增导出问题；新增失效未经选择不能提交，显式接受后仍保留原扩展
  和 provenance，导出继续返回对应原生错误，一次撤销恢复原内容及原导出可用性。
- 同一个 Deformer 从 Part tree、Deformer tree、viewport 和 Python 发起，默认范围一致；
  删除一个 Part 内的 Deformer 时，外部 Part 成员按显式根和隐含删除规则区分处理。
- 保留子节点时测试线性可保留、非线性无法全域证明、奇异父级、绘制外部成员、Offscreen
  无合法所有者等情况；不会静默扩大删除或谎报完整外观保留。
- 被删对象未锁但 Mask 使用者、Glue pair、绑定 sample、Motion track 或其锁来源被锁时，
  报告实际阻碍并保持整个文档、History、Redo 不变；只读共享资源的锁不误拦截。
- 规划和确认期间修改字段、改锁、切换文档、撤销再恢复相同 ID、推进候选 Edit，旧计划
  全部失效；修改选项的迟到计算不能替换当前审阅。
- 当前编辑状态保留覆盖滑块、播放和 Physics 改变相关预览来源而文档版本及 Edit 序列
  不变的情况：旧计划、缓存及迟到结果失效，重新捕获后才能确认。Python 固定上下文
  的不同取值不能命中同一缓存；文档 default 降维不因无关临时预览变化而失效。
- 删除并清理一次提交，失败不发布任何部分结果，撤销／重做覆盖所有关系和内部身份；
  旧句柄和地址仍失效，保存重开及渲染结构无新增悬空引用。
- 参数阶段覆盖默认值不在样本点、多轴降维、最后一维、普通／Scene／Glue／Blend 绑定
  组合、空 Physics 设置和共享 constraint；保留其他参数与所有非目标 Mesh。
- GUI 验证文本、Timeline 和 Mesh Edit 的 Delete 语义；菜单保持短名称，反馈不写入
  Problems 错误记录，取消和重规划不增加撤销步骤。
- 固定合成大模型，检查命令状态查询不会触发全域转换；计划预算拒绝、取消、报告分页和
  Runtime／Python 结果恢复均保持同一计划身份，不重放删除操作。

从 Core／SDK 关系和计划的模块测试开始，再运行 Editor core 协调、受影响 UI 模块及
Runtime／Python 定向测试。采用合成数据固定复现，不依赖私人模型或昂贵完整套件。
