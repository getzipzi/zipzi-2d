# Editor 专用工具光标方案

状态：设计方案，尚未实施。创建：2026-11-08。

为 Zipzi Editor 的网格编辑、变形器操作和选择工具提供可辨识的专用光标，
让用户在操作前看到将要执行的动作，并在拖动期间保持准确反馈。
采用自定义图形与原生光标对象：应用决定图形和热点，操作系统负责显示与移动。
笔刷范围、连线和角度等动态预览继续由画布绘制。

首批建议覆盖加点、删除、连边、固定边、旋转和骨骼显示长度六类操作，
同时补齐 Windows 的张手与握手光标。后续扩展套索、笔刷选择和控制点移动。
本方案以当前工作区实现为基线；独立的变形、扩展收缩和 Warp 整形笔刷
沿用[笔刷交互方案](cubism-brush-interaction.md)，待对应操作落地后再扩充光标。

## 1 当前实现与问题

画布的主要光标选择位于
[`viewports/modeling.rs`](../../crates/zipzi-editor/src/viewports/modeling.rs)，
网格连边与固定边的覆盖逻辑位于
[`ui/manual_mesh.rs`](../../crates/zipzi-editor/src/ui/manual_mesh.rs)，
平移、弹窗和画布元素样式由
[`viewports/mod.rs`](../../crates/zipzi-editor/src/viewports/mod.rs)协调。

当前旋转使用张手或握手，加点和套索通常使用十字，删除工具使用箭头，
连边和固定边共用指向手形。缩放会依据手柄方向选择四种双箭头。
这些样式能表达基本交互，但对“将创建还是删除”“将旋转还是平移”等操作区分不足。

底层使用仓库内的 `gpui-fast` 补丁。
[`CursorStyle`](../../vendor/gpui-fast/src/platform.rs)只有固定枚举，
还没有通用的自定义图片或资源 ID 入口。实现需要贯通 GPUI 光标请求及两个平台后端，
不能仅在应用层增加 SVG 后调用现有 `.cursor(...)`。

| 平台现状 | 影响 | 对应源码 |
| --- | --- | --- |
| Windows 的 `OpenHand`、`ClosedHand`、`DragCopy` 回退为箭头，`DragLink` 映射为指向手形 | 相同应用代码在两端的操作反馈不同 | [光标映射](../../vendor/gpui-fast-windows/src/util.rs) |
| Windows 的光标变更处理只在句柄由有到无或由无到有时立即调用 `SetCursor` | 两个有效光标之间切换可能依赖后续消息；静止鼠标按修饰键的显示时机需实机确认 | [事件处理](../../vendor/gpui-fast-windows/src/events.rs) |
| macOS 的对角缩放使用私有 selector | 可在后续以公开接口加载自有双箭头资源替换 | [光标注册](../../vendor/gpui-fast-macos/src/window.rs) |

Windows 静止鼠标换形问题属于静态检查发现的风险，尚未实机复现。
张手与握手缺失是当前后端映射的问题，Windows 本身支持显示相应的自定义图形。

## 2 操作清单与优先级

以下按操作语义统计为 11 类，不等同于最终资源文件数量。
方向、按下状态、加减角标可以组合或复用，不为每一种组合单独设计图形。

| 编号 | 优先级 | 操作 | 当前表现 | 建议光标 |
| --- | --- | --- | --- | --- |
| 1 | 首批 | 网格加点 | 通常是十字 | 精准十字加小加号 |
| 2 | 首批 | 删除顶点或边 | 删除工具为箭头，快捷操作缺少明确区分 | 指针加小减号；目标类型由悬停高亮说明 |
| 3 | 首批 | 顶点连边 | 指向手形 | 两点连线；新建终点并连接时增加加号角标 |
| 4 | 首批 | 固定自动边 | 与连边共用指向手形 | 短线加固定标记，与创建连接区分 |
| 5 | 首批 | 对象和变形器旋转，包括骨骼旋转 | 张手或握手 | 弧形旋转箭头 |
| 6 | 首批 | 调整骨骼显示长度 | 与骨骼缩放共用方向箭头 | 长度标记加轴向双箭头 |
| 7 | 第二批 | 套索选择 | 十字 | 小套索加精准热点；普通画布与 Mesh Edit 共用 |
| 8 | 第二批 | 笔刷选择与减选 | 十字，另有范围预览 | 小十字加选择或减选标记；范围继续在画布绘制 |
| 9 | 第二批 | 移动网格点、Warp 控制点和 Bezier 控制柄 | 普通组件多为箭头，部分点使用手形 | 统一移动光标，与平移视图的手形区分 |
| 10 | 后续评估 | 任意角度缩放 | 朝向取最近的四种双箭头 | 有实际辨识需求时增加有限数量的方向变体 |
| 11 | 后续评估 | 时间线曲线切线调整 | 未见针对切线命中的专用光标 | 小切线或控制柄图形，可先复用移动光标 |

手势依据见[网格编辑](../../crates/zipzi-editor-core/src/tools/manual_mesh.rs)、
[变形器手柄](../../crates/zipzi-editor-core/src/deformer.rs)、
[覆盖层状态](../../crates/zipzi-editor-core/src/tools/overlay.rs)和
[时间线操作分类](../../crates/zipzi-editor/src/panels/timeline/hints.rs)。

### 2.1 保留标准光标的操作

普通选择、文本输入、按钮点击、禁止操作、面板分隔条和数值横向拖动继续使用标准光标。
时间线播放头和事件的水平移动可以沿用水平双箭头，关键帧移动先复用移动光标。
平移视图继续采用张手与握手语义；macOS 使用系统样式，Windows 补齐对应资源。

`DragCopy` 和 `DragLink` 的平台差异保留在后续修复清单中，
不因底层存在这些枚举而扩大首批产品功能。

### 2.2 保留画布预览的内容

笔刷范围与硬度、框选矩形、套索路径、吸附点、连接预览线、旋转角度及距离读数
继续由画布覆盖层绘制。光标表示动作，预览表示动作的范围或结果。
当前 `OverlaySelectionBrush` 已携带位置、半径、形状、角度和减选状态，
应复用这套数据，避免再建立一份随鼠标移动的范围状态。

Glue 工具有入口和提示，但当前检查到的输入路径不足以确认独立的拖拽创建绑定手势。
胶水或链条图标暂不计入交付清单，待操作语义确认后再加入。

## 3 光标状态与交互规则

### 3.1 从实际操作解析光标

工具、命中目标、编辑权限、修饰键和活动手势共同决定光标。
空闲时表达下一次按下的操作；拖动期间表达当前手势，不只读取工具栏选中的工具。
禁止操作只覆盖当前确实不可执行的动作，不能因对象不可编辑而禁止可用的视图平移。

解析顺序建议为：

1. 弹窗、菜单及窗口边界按各自的命中区域处理，不让画布光标覆盖其他界面。
2. 已捕获的视图平移使用握手；其他已捕获手势使用该手势的操作和有效性。
3. 空闲状态下，按实际输入路由解析临时平移、快捷操作、命中手柄及当前工具。
4. 无专用操作时使用区域默认光标。

这套顺序应集中在可测试的解析逻辑中，避免工具逻辑、连接反馈和视口样式分别覆盖彼此。
解析应读取现有命中和编辑能力结果，不为光标另做一套拓扑检查或命中测试。

### 3.2 修饰键与手势锁定

平台主修饰键在 macOS 为 Command，在 Windows 为 Ctrl。
Mesh Edit 当前用主修饰键启动连接，用主修饰键加 Shift 启动删除；
骨骼端点按下时的 Alt／Option 决定缩放还是调整显示长度。
这类按下时确定的操作在拖动过程中保持光标语义，松开修饰键不改变手势类型。

已有手势允许实时变化的约束，如轴向锁定、旋转步进和缩放中心，继续遵循手势实现。
首批不为每个约束创建一个图标；约束线和数值提示仍由画布表达。

选择工具的加减角标应来自实际选择操作，不能只根据键盘状态生成。
当前普通区域选择的 Shift 为添加、Alt 为移除，部分点击选择还有切换选中的行为；
笔刷的快捷操作也应从其自身状态解析。
鼠标静止时按下或松开修饰键，应重新解析并提交光标，不等待下一次移动。

### 3.3 图形与热点

热点是点击实际落点，应与十字中心、箭头尖端或操作定位点一致。
增加角标或切换状态不得改变热点，避免图形切换产生落点跳动的感觉。
资源以统一逻辑尺寸设计，使用能在浅色画布、深色画布和复杂贴图上辨识的轮廓。
加点、连边等精确操作的装饰图形避开热点附近，不遮挡顶点。

资源保存矢量母版，按目标尺寸生成原生光标需要的位图。
具体逻辑尺寸、线宽和角标位置在首批原型中确定，并在两端真实缩放倍率下比较。
光标尺寸不跟随模型缩放；笔刷范围按其既有交互单位更新。
方向变体采用有界缓存，不为每次鼠标移动或每个浮点角度重新分配原生资源。

## 4 macOS 与 Windows 实现

| 事项 | macOS | Windows |
| --- | --- | --- |
| 原生资源 | `NSImage` 创建 `NSCursor(image:hotSpot:)` | `.cur` 资源，或位图与 `ICONINFO` 创建 `HCURSOR` |
| 热点 | 左上角为原点，以逻辑点计算 | 按实际位图坐标设置整数热点，随输出尺寸换算 |
| 高分辨率 | 同一逻辑尺寸提供标准及高分辨率图像表示 | 按有效 DPI 选择或生成资源，覆盖分数缩放倍率 |
| 显示接入 | 现有 cursor rect 注册和失效刷新 | `WM_SETCURSOR`、当前句柄及光标变更消息 |
| 生命周期 | 缓存并持有原生对象 | 区分共享系统句柄与自有句柄；自有资源不再使用后释放 |
| 首批平台补齐 | 保持现有系统张手与握手 | 新增张手与握手资源，并验证静止指针换形 |

macOS 的创建和热点规则依据 Apple 的
[NSCursor 初始化接口](https://developer.apple.com/documentation/appkit/nscursor/init%28image%3Ahotspot%3A%29)
及[热点定义](https://developer.apple.com/documentation/appkit/nscursor/hotspot)。
多分辨率资源参见[高分辨率适配指南](https://developer.apple.com/library/archive/documentation/GraphicsAnimation/Conceptual/HighResolutionOSX/Optimizing/Optimizing.html)。

Windows 的透明位图方案使用带 alpha 的颜色位图及掩码，
设置 `ICONINFO.fIcon = FALSE` 和热点，再调用 `CreateIconIndirect`。
临时位图和生成的光标句柄分别管理生命周期，不能销毁共享系统光标。
依据 Microsoft 的[光标创建指南](https://learn.microsoft.com/en-us/windows/win32/menurc/using-cursors)、
[ICONINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-iconinfo)和
[DestroyCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-destroycursor)。

### 4.1 更新与恢复

macOS 在 AppKit 主线程创建和使用原生光标对象，接入当前视图的 cursor rect 流程。
窗口焦点、悬停窗口和捕获归属需共同验证，避免多窗口下将光标提交到错误窗口。

Windows 在光标语义变更时更新缓存句柄，并在本窗口确实拥有指针显示责任时立即应用。
`WM_SETCURSOR` 路径仍负责普通移动时的设置；捕获期间和静止指针换形不能仅依赖该消息。
窗口边框缩放、原生菜单、禁用窗口与隐藏光标状态继续保留各自处理。
消息行为依据 [WM_SETCURSOR 文档](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-setcursor)。

两端都应覆盖拖出画布再返回、Escape 取消、失去焦点、切换文档及关闭窗口。
没有捕获时离开画布即交还区域光标；捕获期间遵循活动手势，结束后重新解析当前位置。

### 4.2 DPI 与系统偏好

Windows 按有效 DPI 和资源变体缓存光标，DPI 变化时重新选择资源并同步热点。
跨屏及 125%、150% 等分数倍率单独验收；窗口 DPI 变化依据
[WM_DPICHANGED](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged)。
macOS 检查普通屏与 Retina 屏上的逻辑尺寸、清晰度和热点一致性。

两端均验证系统指针放大和高对比度设置下的可用性。
自定义光标对这些偏好的实际继承行为需要实机确认；实现应保留标准光标回退路径，
资源创建失败时也使用语义最接近的标准样式。

## 5 代码职责与资源边界

| 层级 | 职责 |
| --- | --- |
| `zipzi-editor-core` | 提供操作语义、活动手势、命中结果和可编辑性；保持无 GPUI 依赖 |
| `zipzi-editor` | 集中解析工具光标；维护图形、角标、热点及标准样式回退映射 |
| `vendor/gpui-fast` | 提供通用自定义光标注册与请求能力，贯通命中区域和拖拽光标路径 |
| `vendor/gpui-fast-macos` | 创建、缓存和应用 `NSCursor`，处理平台恢复与资源生命周期 |
| `vendor/gpui-fast-windows` | 创建、缓存和应用 `HCURSOR`，处理 DPI、消息、捕获与释放 |

建议采用“标准样式或自定义资源 ID”的请求模型。
图像数据在资源注册时提交，命中区域与每帧请求只携带轻量引用；
具体 Rust 类型在基础接口阶段确定，并检查现有 `Copy`、序列化、缓存和拖拽调用方。
通用层不加入 `MeshAddPoint` 等 Zipzi 业务枚举，也不向 EditorCore 传递原生句柄。

原生光标注册成功后直接复用。更换主题、DPI 或资源版本时更新对应缓存，
正在显示或被排队消息引用的资源不得提前释放。
平台创建失败应降级为标准光标，不能让指针消失或中断编辑手势。

## 6 实施顺序

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 基础接口 | 增加通用自定义资源入口；贯通两端；补齐 Windows 张手和握手；检查立即换形 | 一个自定义光标在两端可显示、切换、跨 DPI 使用和正常恢复 |
| 2 首批工具 | 接入六类首批操作；统一手势优先级与热点；保留标准样式回退 | 加点、删除、连边、固定边、旋转、骨骼显示长度可明确区分 |
| 3 选择与移动 | 接入套索、笔刷选择及控制点移动；角标与实际操作一致 | 普通画布、Mesh Edit 和笔刷中的反馈不冲突 |
| 4 后续优化 | 评估方向缩放和时间线切线；处理 macOS 私有对角接口及其余 Windows 映射差异 | 按实际需求分别验收，不扩大首批完成条件 |

首批基础图形为六类工具语义加 Windows 张手与握手。
连边新增终点、按下状态及方向可产生额外变体，因此不把八类基础图形当作最终文件数。

## 7 验收与测试

### 7.1 状态逻辑

以表驱动用例验证集中解析器，覆盖工具、命中目标、修饰键、权限和活动手势组合。
重点检查创建与删除快捷操作、连接现有点与创建终点、固定自动边、
骨骼缩放与显示长度、临时平移、禁止操作及模态界面。

按下时锁定的操作在修饰键释放后保持不变；实时约束按既有手势变化。
无鼠标移动的修饰键切换也应更新光标。
测试覆盖语义和状态转换，不为单个 SVG 路径或纯视觉尺寸编写实现镜像测试。

### 7.2 双平台原生验收

| 场景 | 通过标准 |
| --- | --- |
| 指针静止切换工具或修饰键 | 正确换形，无需额外移动鼠标 |
| 精确点击顶点及切换角标 | 热点位置不漂移，点击与图形定位点一致 |
| 拖出画布、返回和释放 | 捕获中的操作正确，结束后恢复所在区域光标 |
| Escape、失焦、菜单和弹窗 | 无光标残留、消失或覆盖原生界面 |
| 多视口和多窗口 | 光标归属于当前命中或捕获的窗口与视口 |
| macOS 普通屏与 Retina | 逻辑尺寸与热点一致，图形清晰 |
| Windows 100%、125%、150%、200% 及跨屏 | 图形尺寸合理，热点同步缩放，无旧 DPI 资源残留 |
| 浅色、深色和复杂贴图 | 热点与动作符号均可辨识 |
| 系统放大指针和高对比度 | 可操作，必要时使用标准样式回退 |
| 高频移动与长期切换 | 同一资源不反复创建，缓存有界，原生句柄无持续增长 |
| 资源创建失败 | 有可用的标准光标，编辑流程继续运行 |

原生光标可能不出现在普通画布截图中。
资源预览只能验证图形；热点、换形时机与恢复必须通过原生交互验证，
录屏或截图取证时先确认是否包含系统指针。

### 7.3 聚焦测试入口

从受影响的最小模块开始：EditorCore 语义变化使用
`./tools/test-editor.sh fast <filter>`，应用解析及交互路由使用
`./tools/test-editor.sh ui <filter>`。
底层平台补丁按对应 vendor 包的实际测试入口验证，并完成上述原生验收。
只有涉及更广的输入或捕获改动时才扩大回归范围。

验收记录应写明操作系统、屏幕倍率、实际覆盖场景和未完成项。
macOS 测试通过不能替代 Windows 验收；当前 Windows 静止指针换形疑点需单独记录结论。

## 8 首批原型需要确定的细节

- 基础逻辑尺寸、轮廓粗细和角标位置，以真实画布上的辨识度和遮挡情况决定。
- 旋转及骨骼长度是否需要随轴向变化的图形，以及采用多少个方向变体。
- 固定边标记的具体造型，避免与对象锁定或不可编辑状态混淆。
- 自定义资源对系统指针放大偏好的实际响应，以及相应的标准光标回退策略。

这些细节通过首批原型确定，不影响“原生光标负责指针、画布覆盖层负责操作预览”的实现边界。
