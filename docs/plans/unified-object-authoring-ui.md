# Editor UI 对象交互统一方案

日期：2026 年 10 月 21 日。状态：2026 年 10 月 23 日开始实施；当前 U1 共享适配功能已收口，U2 创建、树与 Parameter 导航、共享移动及保持形态改父级交互已接入；跨阶段原生截图和完整验收仍待 U6 收口，见[实施记录](unified-object-authoring-ui-implementation.md)。

在 [对象创作核心架构改造方案](unified-object-authoring-core.md)完成并交付后，统一 Editor 的对象创建、Properties 编辑、文件夹、预览、排序和引用管理交互。核心负责身份、数据、规则与事务；本方案负责操作入口、控件事件、焦点、反馈和视图协调。

对象能力和数据模型以核心方案第 4、5 节为准，本方案不另行复制一份 schema 或领域校验。已确认的行为保留：New 直接创建后在 Properties 编辑；Motion、Expression 单击自动改变预览；Sort 支持合法的跨组移动与改父级；Group 支持创建空组。

## 1 前置条件与覆盖范围

开始统一交互前，核心方案第 9 节交付接口和第 10 节核心验收必须完成。UI 可以先做设计，但不能用 UI 中的临时 ID、资产 JSON 拼装或单独历史栈替代未完成的核心能力。

UI 阶段覆盖所有清单项的入口或明确的不支持状态，不要求每个类型都有独立面板。保留画布、Timeline 和专用表格的内容编辑方式。

| UI 表面 | 覆盖对象与内容 |
| --- | --- |
| 组织树与变形树 | Part、Mesh、Warp/Rotation Deformer、Offscreen，以及所属关系和锁定反馈 |
| Parameters | Parameter、ParameterGroup、嵌套空组和参数编辑定位 |
| Motion 列表与 Timeline | MotionGroup、注册条目、Clip、Track、Key、Event、插值和控制柄 |
| Expression | 资源列表、参数条目、blend、fade 和预览反馈 |
| Physics | 根配置、组、输入输出、节点链和测试状态 |
| Pose | 根配置、组、成员及 links |
| Properties 中的绑定编辑 | MeshBinding、SceneBinding、GlueBinding、轴、关键值、Keyform、BlendBinding、BlendKeyTable、BlendConstraint 和 DeltaKeyform |
| 画布与专用内容编辑 | Mesh 顶点/UV/三角形、Warp 网格/Bezier、Glue 与配对、Offscreen 形态和映射 |
| 绘制和文档集合 | DrawOrderGroup、ModelHitArea、ModelParameterGroup、CdiCombinedSet |
| 资源管理 | Texture/ImageAsset、Attachment、导入替换和引用修复 |
| 文档 Properties | Document、Layout、ExportSettings、SourceCanvas、UserData 引用 |
| 诊断与状态 | Unresolved、MissingReference、待配置项、编辑器状态和受保护的扩展信息 |

完整领域支持矩阵见[核心方案](unified-object-authoring-core.md)第 4 节；某类型不支持文件夹、普通重排或跨容器移动时，不展示误导性的通用按钮。

## 2 UI 适配架构

### 2.1 操作入口

工具栏、右键、主菜单和快捷键使用同一命令适配层。适配层捕获文档、面板集合、选中实体、创建上下文和目标位置，调用核心能力查询与类型化命令。

能力区分“不支持”和“暂不可用”：不支持的动作省略；暂不可用的动作禁用并显示核心原因。UI 只做命中和状态呈现，不重复实现循环、引用、锁定或变形转换校验。

### 2.2 结果协调

操作成功后读取 OperationResult，统一更新检查目标、展开祖先、滚动定位、显示 Properties 和聚焦字段。只有明确的 Motion/Expression 激活或创建后选择策略才调用预览动作；重排和移组不伪造成点击。

### 2.3 Properties 与内容编辑器

保留 PropertyProvider、PropertyForm、PropertySpec、PropertyPatch 和现有预览适配基础。内联改名与 Properties 名称字段共用字段定义、校验和提交。重复字段使用核心稳定子条目地址，不能自行保存长寿命数组下标。

集合描述驱动子条目列表、创建按钮和动作菜单；专用表格可以有不同布局。名称、引用、数值等进入 Properties，空间与时间编辑继续由画布和 Timeline 承担。所有控件事件通过同一编辑协调器执行 Begin/Update/Finish/Cancel。

### 2.4 文件夹显示

默认同一容器内文件夹在前、普通对象在后，分别手动排序。第一版不支持文件夹与普通对象任意交错，以避免无需求地改写 ParameterGroup 等现有顺序模型。Part 组织树沿用现有允许的混合成员投影，不强制改成文件夹分区。

## 3 创建与文件夹交互

### 3.1 入口与默认位置

面板工具栏提供 `+` 菜单，列出当前集合支持的创建类型；有文件夹能力时提供“新建文件夹”。Physics 和 Pose 的动作明确写成“新建物理组”“新建 Pose 组”，避免暗示可嵌套整理。

右键菜单、主菜单和快捷键调用同一操作。右键创建捕获点击行的上下文，不依赖菜单打开后可能改变的全局选择。

| 创建上下文 | 插入位置 |
| --- | --- |
| 选中普通对象 | 同一容器中该对象之后 |
| 选中可容纳该类型的文件夹 | 文件夹内末尾 |
| 选中不支持嵌套的同类组 | 该组之后创建同级组 |
| 多选同一容器 | 最后一个被选成员之后，按文档顺序确定 |
| 多选跨容器 | 面板根集合末尾；若必须有唯一拥有者则动作不可用并说明原因 |
| 无选择 | 面板根集合末尾 |
| 从父对象 Properties 的集合创建 | 明确使用该父对象，不读取其他面板的选择 |

过滤状态下仍根据完整文档位置插入。新对象即使不符合过滤条件，也通过临时“新建项”显露并提供清除过滤入口，不悄悄更改用户筛选条件。

### 3.2 创建后的行为

稳定 ID、默认名称和适用的 runtime ID 由核心创建操作分配；UI 呈现结果，不向用户索取内部 ID，也不自行计算另一套避重规则。

创建、设置关系与初始顺序一次提交。随后选中、展开祖先、滚动到对象、显示 Properties。默认聚焦 Properties 名称字段并选中文字；文件夹也遵循这一规则，内联改名只是后续快捷入口。

Motion 创建后使用同一选择路径切换当前 Motion，沿用现有重置时间与 Timeline 行为；不额外启动播放。新 Expression 使用空参数表，可以进入现有表达式选择与预览路径。

创建和后续改名是两个编辑事务。Esc 只取消当前字段或手势；撤销创建使用模型 Undo。文本控件具有焦点时先遵循文本撤销语义。

### 3.3 默认内容与无名称条目

默认内容由[核心方案](unified-object-authoring-core.md)第 6 节统一定义，面板不自行拼装默认资产。无名称子条目创建后聚焦 Properties 首个待配置字段，例如参数、Part 或顶点引用，不虚构 name 字段。

Texture/Attachment 的 New 先创建无内容条目，再在 Properties 选择文件；取消文件选择保留已创建对象。直接 Import 保留为独立快捷动作。Physics/Pose 已有根资源时只新增组或定位根配置，不提供创建第二个单例的入口。

空组根据组集合直接渲染，不能从成员反推标题。绑定、轨道、节点等必须有拥有者的创建动作从对应对象发起；缺少合法上下文时显示禁用原因。

## 4 选择与预览

### 4.1 列表选择

单击普通对象更新当前面板选择与 Properties。Shift 范围选择、Cmd 多选仅在声明支持多选的集合启用；多选不等于批量写属性，批量属性编辑只对共同可写字段显式提供。

上下键移动焦点行，Enter 激活行，保留当前 Motion/Expression 列表的键盘行为；Physics 等已有立即选择行为由面板激活策略声明。左右键折叠展开层级。未来若要统一方向键即预览，需要作为单独交互变更讨论。

右键打开菜单不触发 Motion/Expression 预览；菜单作用于点击项或包含点击项的现有多选集合。文件夹单击选择文件夹，折叠箭头只切换展开；折叠不会清除隐藏成员的已有身份。

### 4.2 Motion 与 Expression

Motion 单击继续切换动作、定位检查对象并按现有逻辑重置时间；点击已经选中的同一条目保留现有特殊处理。双击可播放动作继续启动播放。Expression 单击继续按播放或暂停状态选择 fade 或立即生效，保留当前触发队列语义。

同一 Clip 的两个注册条目是不同预览选择。Properties 分“动作内容”和“当前注册”两部分：名称、轨道等修改 Clip；注册 fade、sound 修改当前条目，并显示是否存在覆盖及继承值。清除覆盖恢复继承，不向 Clip 写入等价值。

结构或内容编辑涉及正在运行的时间／物理状态时，操作描述明确其播放策略：时间轴结构与形态编辑先暂停并定位当前编辑时间；物理结构修改先暂停测试并从当前参数重建；名称、文件夹位置等纯展示修改不暂停。既有 Motion/Expression 的单击预览不经过这一内容编辑暂停策略。

拖动排序、组改名、移组不应被当成再次点击：保持当前稳定注册引用和播放位置。仅改变展示位置不重启播放。改变影响执行的配置按现有预览失效机制重建，保留能保留的播放上下文。

无效资源仍可选中和修复。激活预览失败时显示原因，保持最后有效预览或明确的空状态；不能只因无法播放就禁用整行检查。删除当前预览目标时清理对应触发或选择，不能自动预览任意邻居。

### 4.3 编辑上下文

Modeling 与 Animation 的选择和内容编辑目标继续独立。每次编辑捕获 DocumentId、上下文 token、实体身份和必要的字段基线。切换文档、工作区、关键形态或 Timeline 目标后，迟到事件不得写到新目标。

打开 Properties 是检查动作，不隐式改变参数值、关键形态或播放状态；Motion/Expression 行激活明确组合检查与预览两个动作。

## 5 字段编辑与操作边界

### 5.1 控件行为

| 交互 | 行为 | 模型历史 |
| --- | --- | --- |
| 文本输入 | 草稿；Enter 或失焦提交合法值 | 一次提交一条 |
| 无效文本提交 | 显示字段原因并恢复最新已提交值 | 无 |
| Esc | 恢复字段基线；连续预览恢复手势前值 | 无 |
| 下拉、开关 | 一次选择立即提交 | 一条 |
| 数值拖动 | begin/update 实时预览，松手 finish | 整个手势一条 |
| 颜色或专用弹出编辑 | 实时预览，接受提交，取消回滚 | 接受时一条 |
| 跨字段约束 | 明确的组合编辑一次提交相关字段 | 一条 |
| 无变化或非法操作 | 不修改模型，不清空 redo | 无 |

沿用当前 Properties 的无效提交恢复策略。对于范围、引用和形态转换等必须一起变化的字段，提供类型化组合操作，不能依次提交到非法中间状态。

### 5.2 操作边界

开始 New、Move、Delete 等操作前，由同一协调器结束旧输入：合法文本先提交；非法文本恢复并显示原因；仍活动的拖动或候选手势取消。已经完成的手势不会被重复提交。

切换选择、文档、工作区采用同一规则。窗口失活取消未完成拖动；已产生的文本 blur 按普通提交规则处理。Save 结算文本输入并取消仍活动的手势，随后保存已提交文档，允许保存待配置对象。不能由某个面板擅自调用 FinishEdit，而另一个面板无条件 CancelEdit。

Undo/Redo 到达文档命令层时，先取消未提交候选，再操作 SDK 历史。原生文本控件聚焦时，其文本撤销优先。结构变更后统一校正选择和检查引用；Undo 恢复对象数据与原 ID，不重放一次动画点击事件。

### 5.3 失效与异步反馈

核心拒绝过期字段地址、上下文或集合版本时，UI 恢复最新提交值并显示原因，不能换用当前选中对象重试写入。异步导入捕获资源引用，取消、删除或切换文档后不转移导入目标。

输入法组合期间 Enter 优先完成组合，不提交字段或触发对象命令。文档保存占用时按核心能力禁用对应编辑，其他文档仍按各自状态工作。

## 6 排序移动与改父级

### 6.1 共用交互

拖拽、右键“上移/下移”“移到…”和键盘动作调用同一 Move。列表聚焦且没有文本输入时，建议使用 Alt+Up/Down 上下移动；映射最终通过现有命令与快捷键系统配置。

可容纳源类型的容器行，上下各 25% 表示 Before/After，中间 50% 表示 Inside；普通行上下各一半。类型不允许进入时不显示 Inside 提示。进入容器会高亮容器，排序显示插入线，二者明确区分。

建议悬停 600ms 展开容器，靠近边缘自动滚动。拖动期间展开属于视图状态，取消拖动不写模型。Esc、窗口失活、文档切换取消拖动。

搜索或过滤下仍以完整集合中的稳定目标定位，不按可见下标写入。仅在手动排序视图提供拖拽；临时按名称排序时提示切回手动顺序。隐藏成员保持相对顺序，跨组后定位新位置。

多选移动保留源集合内顺序，移除已包含在被选祖先中的后代。跨源集合使用明确的投影顺序，并整体预校验；任意成员不合法则整体失败，不移动一半。第一版不支持拖到另一文档。

多选上下移按完整集合中的连续选区逐段移动一格，每段跨过一个未选邻居，保留选区之间的间隔；到达边界的选区保持原位。组织树与 Parameters 的不同拥有者集合分别处理后一次提交。变形树当前只提供同一实际变形父级内的上下移，跨父级选择显示不可用原因。

结构写入检查源对象、受影响子树和目标容器的锁定规则；不因从另一个投影发起移动而绕过锁定。批量操作中存在不可编辑成员时整体拒绝，并定位具体成员。

### 6.2 领域效果的呈现

移动是否合法、是否需要转换、哪些对象受影响，由[核心方案](unified-object-authoring-core.md)第 8 节规划结果提供。UI 不重复实现这些规则。

| 操作 | 界面必须表达的含义 |
| --- | --- |
| 组织树排序和 Part 归属 | 插入线与移入高亮不同；不暗示修改实际绘制顺序 |
| 变形父级 | 拖放和“移到…”打开保持形态审阅；默认仅当前编辑态，可显式选择整个参数范围与修改容差；不能证明时展示原因，不自动降级 |
| Motion 注册移动 | 移动当前注册条目，保留 Clip 引用与覆盖，不重置播放 |
| Timeline 轨道行整理 | 改展示顺序，不修改时间或重复目标轨道的执行顺序 |
| PhysicsGroup | 使用“调整执行顺序”措辞，提交后按核心要求重建测试预览 |
| Physics 节点、Binding 轴、关键值、Mesh 拓扑 | 使用专用结构编辑，不套用普通列表任意上下移 |
| Pose / Expression 子条目 | 允许的跨拥有者移动通过统一命令，错误指向具体成员 |
| DrawOrderGroup | 明确改变绘制组织，与文件夹排序分开 |

保持形态审阅只为当前选择的落点建立计划，搜索、绘制和拖动悬停不执行几何转换。打开时结算旧输入，冻结 Modeling 参数值、编辑时间和文档版本，在后台构造可取消计划；更换目标、保证范围或容差时作废旧计划。界面展示影响对象、修改地址数量、保证范围、模型单位误差上界、绝对/相对容差、参考尺度、转换容量和不覆盖的继承外观、可见性、Glue、有状态动画等效果。确认直接执行已审阅的同一份计划，版本或冻结参数变化则拒绝；改父级和目标位置一次发布、一条 Undo/Redo。初始容差保持 core 默认值，不能证明时由用户明确修改后重新请求，不自动放宽。当前原生支持范围见核心第 8.1.2 节；无证明的 Warp 逆变换和变形器子树保持明确不可用。

### 6.3 无效落点

不可放置时显示原因：锁定、类型不兼容、循环、目标失效、无法保持形态等。核心返回结构化原因供本地化使用。UI 与提交使用同一领域判断，释放时重新验证。原地移动保持历史和 redo 不变。

## 7 复制删除与修复入口

数据复制、依赖删除、解散和修复的权威规则在[核心方案](unified-object-authoring-core.md)第 8 节。UI 先获取操作计划，展示具体影响和可执行选项，不自行决定级联删除。

| 入口 | 交互规则 |
| --- | --- |
| 普通复制 | 选中和定位结果；外部资源默认共享，内部身份由核心重建 |
| Motion 复制 | 明确区分“复制动作内容”和“添加已有动作引用”；复制组保留其引用集合语义 |
| 空文件夹删除 | 无依赖时直接执行，使用 Undo 恢复 |
| 普通文件夹 | 提供“解散文件夹”和适用的“删除文件夹及内容” |
| MotionGroup | 使用“删除组及注册”；计划说明哪些最后注册将迁移到根列表，不能暗示共享 Clip 被删除 |
| 删除动作资源 | 显示所有注册和依赖的影响，与删除一次注册分开 |
| Part / PhysicsGroup / PoseGroup | 根据业务能力提供动作；Pose 提供迁移成员到指定组或删除组及成员，不提供无意义的通用解散 |
| 外部引用仍存在 | 展示使用者和替换引用、处理依赖动作，不静默级联 |
| 删除后的定位 | 定位邻居或父对象只更新检查，不自动预览另一个 Motion/Expression |
| 未配置或未解析引用 | 显示不同状态，允许选择目标、修复或显式移除 |

无依赖且可撤销的普通删除直接执行；删除非空拥有者或影响其他对象时展示具体计划。修复使用稳定目标引用，不用整段 JSON 绕过校验。不透明扩展和受保护内容保留核心诊断，不自动生成无约束编辑器。

## 8 模块改动与实施顺序

| 步骤 | 工作 | 完成条件 |
| --- | --- | --- |
| U1 共享适配与编辑协调 | 接入核心能力与结果；统一命令入口和字段边界 | 无面板业务校验副本；同一动作经不同入口结果一致 |
| U2 Parameter 与层级树 | 新建、文件夹、Properties 定位、拖拽、多选及锁定反馈 | 覆盖既有层级和参数行为，空组与过滤状态可用 |
| U3 Motion 与 Expression | 注册与 Clip 分区、空组、成员、列表排序与现有预览 | 单击/双击保持现有逻辑；移动和改名不伪造激活 |
| U4 Physics 与 Pose | 根资源、业务组和内部条目入口；专用结构编辑 | 名称、结构、执行顺序与测试预览反馈一致 |
| U5 其余完整覆盖 | 场景对象、绑定、BlendShape、绘制组织、文档行为集合、资源附件 | 第 1 节每项有合适的入口或明确不支持状态，没有遗漏的独立旧逻辑 |
| U6 清理与验收 | 移除被替代的面板资产拼装、重复 can_target 和旧控件路径 | 完成第 9 节 UI 验收及性能回归 |

主要修改 editor 的 panels、properties、commands 与视图协调。只有缺少通用交互能力时才调整 GPUI Kit，不向 Kit 引入 Kasane 类型。若 UI 接入暴露核心契约缺口，回到核心方案更新和测试，不在面板里临时补领域规则。

## 9 UI 验收与性能

| 场景 | 验收结果 |
| --- | --- |
| 工具栏、右键、主菜单、快捷键 | 同一上下文产生相同核心意图和结果 |
| New 对象与空文件夹 | 立即可见、定位、展开并显示 Properties；默认焦点正确；Esc 不删除对象 |
| 过滤与折叠状态下创建 | 新项可发现，完整集合位置正确，不悄悄修改筛选条件 |
| Motion/Expression 激活 | 既有单击预览、重复点击、双击播放、暂停/播放触发行为保持 |
| Motion 改名、移组和排序 | 注册身份、覆盖配置和播放位置保持，不触发新点击 |
| 注册属性与 Clip 属性 | 清楚显示继承和覆盖，修改目标正确，共享内容影响可理解 |
| 文本、数值、颜色、组合字段 | 提交/取消一致，连续手势一条历史，非法值恢复并说明原因 |
| 输入法、Save、Undo、文档与工作区切换 | 不误提交、不重复提交、不把旧控件事件写入新对象 |
| 拖拽、上下移、多选、锁定 | 命中标记清楚，自动滚动和悬停展开正确，整体失败可定位原因 |
| Physics/Pose/Binding 等专用内容 | 结构变化后选中和字段仍指向正确条目，执行与拓扑操作提示准确 |
| 删除与引用修复 | 展示实际影响、无静默级联，删除后不自动激活邻近预览 |
| Texture/Attachment 异步加载 | 取消选择保留新对象；过期结果不误用当前文档或资源 |
| 全部对象覆盖 | 对照第 1 节和核心能力清单检查入口及禁用原因 |

覆盖工具栏、右键、菜单和快捷键四类入口的一致结果；覆盖中英文、长名称、空列表、隐藏 Properties、过滤结果和折叠容器。验证输入法组合中 Enter 不被误当创建或提交命令。

验证文本合法和非法失焦、Esc、数值取消、Save、Undo、工作区切换的统一边界。验证拖动自动滚动、悬停展开、无效落点说明及多选顺序。必要的截图和原生交互验收复用现有项目工具。

控件渲染、hover 和拖动查询复用核心投影与集合版本，不每帧克隆整个资源或构建索引。维持现有列表虚拟化与定向刷新；标签变化不触发全模型重建。沿用属性编辑链和 Timeline 基准验证共享适配没有引入回退，新增结构交互按实际负载补针对性检查。

## 10 交互建议与跨阶段决策

以下仍是原方案建议，并非本次拆分新增的已确认需求。

| 选择 | UI 默认建议 | 归属 |
| --- | --- | --- |
| 无效文本结束编辑 | 恢复最新已提交值并显示原因 | 本方案维护；若改为保留草稿，需要同时重定义 Save/离开目标规则 |
| 文件夹与普通对象交错 | 通用列表文件夹在前；Part 保留现有混合投影 | 存储影响由核心方案第 12 节维护，UI 不独立扩展 |
| Motion 嵌套与新增纯整理文件夹 | 只呈现核心交付的能力 | 先在核心方案确定模型范围 |
| 变形父级移动 | 普通拖放采用保持形态策略，不可转换显示原因 | 领域转换由核心定义，UI 维护解释与显式替代入口 |
| 上下移动快捷键 | 建议 Alt+Up/Down，可由现有快捷键系统配置 | UI 交互建议 |
| 拖动悬停展开 | 建议 600ms | UI 交互建议 |

模型与共享引用决策详见[核心方案](unified-object-authoring-core.md)第 12 节；本方案只引用其结果，不维护另一份删除或导出规则。
