# 动画曲线配置与帧步进方案

状态：设计方案，尚未实施。日期：2026-11-09。

本方案补齐时间线中的曲线配置入口、Auto Smooth、Bezier 缓动预设和区间级 Frame Step。用户应能直接选择两个动画关键帧之间如何过渡，以及每隔多少帧更新一次姿态；同一套配置必须贯穿 Editor、SDK、原生工程保存与 motion3 导出。

## 需求与范围

已明确的需求：

1. 时间线面板需要可发现、可操作的曲线配置入口，不能以底层已有枚举或条件性的属性字段代替功能交付。
2. 支持 Linear、Auto Smooth、Bezier、Step、Inverse Step 五种类型。
3. Bezier 提供 Cubic In、Cubic Out 等快捷预设，应用后仍能编辑控制柄。
4. 两个关键帧之间可以指定每 N 帧更新一次，形成二维动画的一拍二、一拍三等节奏。

以下章节给出本次实施建议。算法、默认值和编辑传播规则是 Zipzi 的设计选择，不等同于 Cubism 的内部实现。本文中的区间指时间线相邻动画关键帧之间的区间；用户所说的 keyform 在此按动画姿态理解，不修改建模参数域的 Keyform 插值。

首批覆盖已有 MotionTrack 数值通道，不新增 FA 轨道、全局帧步进轨道或参数组继承体系。曲线直接拖动、Bounce／Elastic 多段缓动、整幅画面的后处理式定格留待后续。

## Cubism 参照

Cubism Graph Editor 列出 Auto Smooth、Linear、Step、Inverse Step、Bezier 五种曲线；类型应用于所选关键帧到下一关键帧的区间，支持多选。Bezier 支持控制柄、连续手柄和曲线预设。[官方 Graph Editor 手册](https://docs.live2d.com/en/cubism-editor-manual/grapheditor/)

Cubism 另有 Frame Step，提供单帧、双帧、三帧及数值输入，可通过关键帧改变设置，也可为参数组设置；导出时可转换成 Step。Zipzi 首批采用区间级设置，不照搬独立的 Frame Step 属性轨道。[官方 Frame Step 手册](https://docs.live2d.com/en/cubism-editor-manual/limited-animation/)

## 面板与选择行为

### 时间线工具栏

在 Dope Sheet 和曲线视图共同提供：

```text
插值 [Bezier ▾]   缓动 [Cubic Out ▾]   帧步进 [关闭 ▾] [N 帧]
```

插值入口常驻。Bezier 时显示缓动入口，其他模式隐藏其专属设置；帧步进始终可见。面板过窄时折叠到有文字标签的“曲线设置”菜单，不能只留下无提示的图标。曲线与阶梯的小图形用于辅助辨认，选项同时保留名称与提示。

属性面板同步显示“区间曲线”分组，包含插值、缓动预设、帧步进，以及适用时的 Bezier 控制柄数值。工具栏、属性面板和右键菜单使用同一命令和状态计算，不各自维护一份配置。

### 操作对象

- 选中关键帧，修改它的 outgoing 区间；可点击曲线段定位同一个对象。
- 支持跨通道多选。各区间独立应用相同设置，预设按各自时间和值范围映射。
- 多选不同设置显示“混合”，只有用户主动选择的字段被覆盖。
- 最后一个关键帧没有 outgoing 区间；单选时禁用区间设置，并显示“没有后续关键帧”。多选中末尾关键帧不计入作用区间，界面显示实际区间数。
- 未选择、混入事件或包含不可编辑区间时显示明确原因；涉及锁定区间的批量修改整体禁用，避免静默部分成功。
- 单次选择预设或完成一次数值拖动产生一个撤销步骤。拖动走现有 Draft 预览流程，取消恢复原值，外部发布失效时遵循现有冲突处理。

## 插值与自动平滑

| 界面名称 | 含义 |
| --- | --- |
| Linear 线性 | 区间内按时间线性变化 |
| Auto Smooth 自动平滑 | 根据关键帧自动生成平滑控制柄 |
| Bezier 贝塞尔 | 使用可编辑的三次 Bezier 控制柄 |
| Step 阶梯 | 区间内保持起点值 |
| Inverse Step 反向阶梯 | 区间内使用终点值 |

新建轨道的首个区间默认 Auto Smooth、帧步进关闭。已有区间插入关键帧时按结构编辑规则继承，不覆盖为全局默认。导入的四类段保持原类型，Bezier 默认显示 Custom，不推测它原先是否来自 Auto Smooth。

Auto Smooth 必须是持久化的编辑模式，不能只是一次性生成 Bezier 手柄后丢失模式。建议采用确定性的分段三次 Hermite 方案，再编译成三次 Bezier：

- 连续 Auto Smooth 段组成自动平滑区间组；内部斜率采用按时间间隔加权的单调三次插值斜率，同向采用加权调和平均，异向或平坦处取零。
- 自动区间组首尾斜率取零，使独立两键区间表现为缓入缓出；不会修改相邻手动 Bezier 段。
- 从斜率转换为时间方向位于三分之一、三分之二处的控制柄。相邻自动段内部一阶连续，单调数据不额外过冲。
- 修改关键帧时间、值或拓扑后重算受影响的自动段；编译不依赖播放历史。
- 手动拖动自动控制柄时，将受编辑段转成 Bezier，先保留当时编译出的曲线，再施加拖动。连续手柄操作涉及的另一自动段也显式转为 Bezier。

上述算法为建议基线。实施首阶段应固化不等时距、峰谷、平坦和混合插值的样例；官方手册未定义 Auto Smooth 的数学公式，验收不宣称与 Cubism 自动曲线逐点相同。

## Bezier 预设与手柄

### 预设集合

| 分组 | 选项 |
| --- | --- |
| 基础 | Ease、Ease In、Ease Out、Ease In Out |
| Cubic | Cubic In、Cubic Out、Cubic In Out |
| 常用扩展 | Sine、Quad、Quart、Quint、Expo、Circ，各提供 In、Out、In Out |
| 自定义 | Custom，表示当前手柄由用户编辑或导入 |

菜单按分组展示缩略曲线，Cubic 首批必须可用。完整列表在本方案交付前补齐。所有预设使用固定、可版本管理的归一化控制点表，不在 UI 中临时计算另一套曲线。In 表示缓入，Out 表示缓出，In Out 表示两端缓、中间快，下降区间沿同一规则映射。

预设是 Bezier 形状的快捷配置；其中部分形状只是对应解析缓动函数的近似。不能把单段 Bezier 预设宣称为精确的全部解析缓动函数。控制点表与近似误差基准在实现首阶段确定，纳入源代码和测试；界面详情标注近似属性。Bounce／Elastic 需要多段表达，不进入首批单段预设。

设起终点为 `(t0, v0)`、`(t1, v1)`，归一化控制点为 `(x1, y1)`、`(x2, y2)`，按以下方式应用：

```text
c1 = (t0 + x1 * (t1 - t0), v0 + y1 * (v1 - v0))
c2 = (t0 + x2 * (t1 - t0), v0 + y2 * (v1 - v0))
```

要求时间方向单调、端点不变。等值区间得到平直曲线，不因除以零产生无效数值。预设只改变形状，保留帧步进设置。

### 编辑与标签

- 选择预设会进入 Bezier，并设置控制点及预设标识。
- 手动编辑手柄、拆分曲线或其他使形状不再匹配预设的操作后显示 Custom，清除预设标识；不靠宽松误差猜回名称。
- 整体平移或缩放时间和值时，只要归一化形状保持，保留标识。普通关键帧移动沿用手柄调整规则，发生形状变化则转 Custom。
- 支持独立手柄、共线的连续手柄与“整理手柄”。共线不强制等长；联动不得修改锁定区间。
- 控制柄的时间和值可通过属性面板精确输入，拖动和数值输入共用单调时间校验。
- 预设表名称和控制点统一供 Editor、SDK、Python 使用。既保存实际控制点，也保存经校验的预设来源，表的扩展不得悄悄改变已有工程曲线。

## 帧步进

### 配置语义

Frame Step 独立于插值类型，表示沿原曲线每 N 帧采样一次并保持。N 是保持帧数，不是将两个关键帧之间等分成 N 段，也不改变动画播放速度。

快捷项为“关闭”“一拍二”“一拍三”“自定义”。N 为正整数；N=1 规范化为关闭，保留连续采样，不额外量化子帧时间。自定义 N 不限制为 2 或 3，允许大于区间长度；数值上限由契约整数范围约束，导出体量另行预检。非整数、零和负数无效。

可以组合 Linear + 每 2 帧、Auto Smooth + 每 3 帧、Cubic Out + 每 3 帧。Step 和 Inverse Step 本身在区间内为常量，叠加后没有额外变化；保留配置，并提示原因，以便切回连续类型时继续使用。

### 采样与边界

在非循环的 clip-local 时间下先按现有规则选择区间，再对该区间的采样时间量化。对 `[t0, t1)`、动画帧率 F、N≥2：

```text
q  = floor(((t - t0) * F) / N)
tq = t0 + q * N / F
value = evaluate_base_segment(tq)
```

计算使用足够精度并统一浮点边界处理，不能通过随意增加 epsilon 将边界前的时间提前到下一格。区间起点作为计步原点，允许其处于子帧；首批不做全局拍点对齐。

到达 `t1` 后立即转入后续区间，尾段不足 N 帧不延迟切换。最后关键帧之后保持尾值。现有采样器在精确关键帧时刻选择 outgoing 段，因此该段是 Inverse Step 时会直接使用它的终点值；帧步进保留此边界语义，不强制插入一个起点姿态。连续插值或 Step 的普通边界会取该关键帧值。

示例：第 0 到第 12 帧，原曲线为 Cubic Out，每 3 帧更新，终点后无 Inverse Step 覆盖：

| 播放帧 | 使用的原曲线样本 |
| --- | --- |
| 0–2 | 第 0 帧 |
| 3–5 | 第 3 帧 |
| 6–8 | 第 6 帧 |
| 9–11 | 第 9 帧 |
| 12 | 终点关键帧 |

动画 FPS 改变后 N 保持不变，保持时长变为 N/F 秒；时间缩放也不隐式缩放 N。多个通道选择相同起点和 N 时同步计步，起点不同则各自计步。循环时间先由既有播放逻辑解析，再进入相同采样器；不在每个渲染帧积累计数，因此暂停、跳转、倒序查询和随机访问结果一致。

### 曲线值与最终画面

帧步进作用于 MotionTrack 原始曲线采样，先于现有淡入淡出、动作混合和物理求值。事件与音频继续使用真实动画时间，不量化、不重复触发。Editor 原始编辑预览和 SDK 原始采样应完全一致。

如果结果预览叠加了物理、淡变或其他连续动画，最终画面仍可能变化。首批交付的是所选动画通道的按帧保持；需要整幅画面定格时，应另行设计最终姿态采样或烘焙流程，不能用暂停全局时间的方式实现。

曲线视图显示实际阶梯结果，可用淡色叠加原连续曲线；量化产生的台阶不是持久关键帧，不参与普通关键帧选择。关闭帧步进即恢复原曲线。绘图仅生成可见范围所需的阶梯，避免按整个长动画逐帧展开。

## 数据与职责

建议将原生段重构为“终点关键帧 + 曲线描述 + 帧步进”结构，曲线描述区分五种类型。这是方案结构，字段名称在契约实现阶段定稿：

```text
MotionSegment
  end: MotionKey
  curve: Linear | AutoSmooth | Bezier { control1, control2, preset? }
         | Stepped | InverseStepped
  frame_step: Off | EveryFrames(N)
```

不向用户关键帧列表插入大量虚拟键，不用不透明 extensions 存放正式语义，也不将播放必需配置只存于 EditorState。Auto Smooth 控制柄作为编译结果，避免持久化两套可互相矛盾的权威数据。稳定身份仍属于关键帧，区间通过相邻键关系定位。

| 层 | 职责 |
| --- | --- |
| Contract | 数据、预设标识、命令和投影契约；同步生成 Python 类型与编解码 |
| Core | 时间顺序、帧步进数值、预设与控制柄一致性等校验 |
| SDK | 自动段重算、预设应用、切换、复制粘贴和结构编辑；经现有 Draft 原子提交 |
| Animation | 共用曲线编译和采样；编译输入携带 FPS、restricted 标志等必要上下文 |
| Runtime | 沿用发布、历史、事件与快照所有权，失效相关编译缓存 |
| EditorCore | 选择与作用区间、状态投影、预览及命令适配 |
| Editor | 工具栏、属性、菜单、手柄和图形显示 |
| Project／格式适配 | 原生持久化、motion3 烘焙、重新导入验证 |

原生工程尚未正式发布，允许必要的破坏性重构，不设计旧原生版本迁移。外部 motion3 的既有导入语义继续保留。

`restricted_beziers` 是现有 clip 级语义：时间限制模式不能直接套用任意时间控制点预设。首次应用不兼容预设时，应在同一事务中将 clip 转为 unrestricted，并将既有受限段转换为等价的三等分时间控制点，保证无关段采样不变；不可只切换布尔值。此转换需有数值对照测试。

## 结构编辑与持久化规则

| 操作 | 建议规则 |
| --- | --- |
| 移动关键帧 | 配置随 outgoing 区间保留；自动段重算，手动段按既有规则调整手柄；计步原点随起点移动 |
| 在区间插入关键帧 | 新的两个区间继承类型和 N，各自重新计步；自动段重算，手动 Bezier 使用既有拆分能力并清除失效预设标识 |
| 删除内部关键帧 | 合并后的区间继承左侧区间的类型与 N；自动段重算，手动合并后不匹配预设则清除标识 |
| 删除首尾关键帧 | 清理不存在区间的配置，不残留孤立引用 |
| 复制粘贴 | 携带复制范围内完整区间的类型、手柄、有效预设标识和 N；目标连接边界按既有粘贴规则处理 |
| 切换插值 | 保留 N；离开 Bezier 时清除预设来源，回到 Bezier 不恢复隐藏旧配置 |
| 保存和重开 | 保留编辑模式、控制柄、预设和 N，不能只保存烘焙结果 |
| 撤销重做 | 单次操作整体恢复数据和相关投影，不以 UI 本地缓存代替持久状态 |

插入关键帧会建立新的计步原点，因此即使连续基础曲线保形，实际阶梯节奏也可能变化。首批不承诺 Frame Step 下的保形插键；提示这一行为，并用测试固定结果。若后续需要无损插键，应另行加入采样相位表达。

## 导出与重新导入

原生 `.zipzi` 保存完整编辑配置。motion3 输出使用目标格式支持的四种基础段：Auto Smooth 编译为 Bezier，Bezier 预设输出实际控制点，Frame Step 展开成 Step 段。导出使用和预览相同的区间边界与采样器，不另写近似的 FPS 计数逻辑。

默认导出包含帧步进效果，并在导出摘要说明烘焙段数量；不静默丢弃效果。不支持的目标必须显式报告。导出不修改原工程，也不把烘焙键加入作者时间线。展开前预估输出规模并应用现有资源预算，不能为超长动画无界分配。

重新导入普通 motion3 后，烘焙结果作为常规 Step／Bezier 段；不承诺恢复原 Auto Smooth、预设名称或 N。精确编辑往返依赖 `.zipzi`。

导出采样对照覆盖步进边界前、边界时刻、边界后、非整帧端点、混合 Inverse Step、循环尾部及 restricted 转换。原始通道在相同时间的值应一致；运行时淡变、混合和物理配置差异不属于曲线导出的一致性保证。

## 实施顺序

1. 固化语义：为自动平滑、Bezier 控制点表、精确边界和 Frame Step 形成确定样例，确认数据与命令契约，记录近似预设误差。
2. 完成 Contract、Core、SDK 和 Animation：持久数据、校验、编译采样、编辑传播、restricted 等价转换，以及 Python 生成同步。

4. 完成 EditorCore 与面板入口：工具栏、属性、右键、多选、预览、控制柄和阶梯绘制；覆盖真实选择及窄面板状态。
5. 完成验收：Editor 和 SDK 同一工程的采样一致，撤销重做和导出一致；更新使用说明。各阶段可独立验证，全部完成后才标记本需求交付。

## 验收与测试

必须覆盖以下行为，而不只检查枚举或按钮存在：

- 无选择、单选、末尾键、多选混合值、锁定、事件混选和窄面板的入口状态。
- 五种插值在正向、反向、等值与不等时距数据下的结果。
- Auto Smooth 的连续性、极值与过冲约束，以及转手动时保持初始形状。
- Cubic In／Out／In Out 的可见差异、所有预设的固定控制点、Custom 转换、时间单调性。
- N=1、2、3、自定义、超过区间长度、非法值、子帧起点、非整除区间和 FPS 变化。
- Step／Inverse Step 与 Frame Step 的组合和既有精确端点语义。
- 随机跳转与连续播放采样一致；事件不受帧步进重定时。
- 插入、删除、复制粘贴、移动、时间缩放、取消拖动和一次撤销的整体行为。
- 原生保存重开、SDK／Python 访问、motion3 导出重新导入后的采样对照。
- 可见范围绘图、长区间采样与烘焙预算，不因开启帧步进而持续增加持久关键帧。

从仓库根目录按实际改动选择 focused gate；新增用例必须确认被过滤器选中：

```sh
cargo test --locked -p zipzi-animation --test motion_sampling
./tools/test-sdk.sh fast motion_curve
./tools/test-editor.sh fast timeline::
./tools/test-editor.sh ui timeline
cargo test --locked -p zipzi-project --test motion_tests
cargo test --locked -p zipzi-contract
uv run --locked python tools/test_tools.py -p test_python_codegen.py
```

契约生成变更完成后再运行 `./tools/test-sdk.sh python`。新增 Runtime 生命周期行为才补相应 focused runtime gate。原生面板操作验收需实际启动 Editor，不能以 UI 逻辑测试代替可发现性检查。
