# Warp Deformer 交互与 Deformer 属性面板完善方案

日期：2026-10-31。实施更新：2026-11-01。状态：A–F 阶段已实现并完成下述自动验证。
E 的任意非线性保形编辑仍明确拒绝；原生人工操作和 Windows 桌面验收留待后续。

本方案以 Cubism Editor 5 Manual 的交互能力为参考，结合当前 Zipzi 的画布、属性和
Runtime 编辑链路制定。实施前基线来自代码检查；已执行的验证见当前进度。
下文的交互规则和分期是 Zipzi 的设计提案，不代表 Cubism 内部算法。

## 2026-11-02 当前交互约定

Deformer 基础字段与 Mesh 共用表单配置和通用行布局，按名称、Runtime ID、Part、
父变形器、透明度、正片叠底色、滤色、启用的顺序平铺；不再使用独立的基础／外观折叠组。
颜色重置默认值属于共用字段配置，Warp 和 Rotation 同样提供白色／黑色恢复按钮。
基础字段之后显示编辑形状提示及类型专属设置。父级重挂接、编辑 scope 和数值范围仍由
各自的类型化绑定负责。此项重组通过 67 项属性测试，2 项可选资产跳过，继续排除已记录的
检查锁定基线用例；中英日原生截图覆盖基础字段与直接细分输入。

以下约定取代后文历史方案中冲突的 UI 设计：

- 移除 Fix children 工具栏按钮、属性复选框及持续开启状态，只保留 macOS Command／
  Windows Ctrl 在按下鼠标时启用本次 Warp 拖动的保形行为。后续普通拖动恢复正常变形；
  交互帮助保留热键说明，拖动期间仍显示保形状态。
  此项通过画布核心 106 项、画布／属性 UI 51 项（1 项可选资产跳过）及中英日原生截图验证；
  覆盖热键平移／旋转／缩放、撤销重做和后续普通拖动，编辑器编译通过。

- Fix children 保形校验按实际 float32 映射、子对象及关键形状的测量偏差执行 0.01 画布
  单位限制，拒绝非有限结果；不再把绝对坐标大小及远处采样位置乘以机器精度叠加成误差。
  修复正常画布尺寸下整体移动／旋转／缩放被误判超限的问题。静态、可逆仿射的适用范围
  保持不变，独立采样不宣称证明全参数域的浮点误差上界。
  SDK 保形 7 项、Editor 核心保形 3 项通过；覆盖 5 × 5 网格／2 × 2 贝塞尔、两种底层
  插值、较大坐标偏移和真实精度损失的原子拒绝。1097 × 1434 实际项目中的 14 个子 Mesh
  复测整体平移／旋转／缩放，子图像最大位移不超过 0.0002 个画布单位。
- 贝塞尔与网格点始终融合展示，移除模式切换按钮与编辑状态。网格使用较细的灰线和小灰点，
  贝塞尔曲线减淡为绿色背景线，锚点使用绿色描边，切线与实心绿色手柄强化。
  两类点同时可编辑，重合处优先命中贝塞尔控制器；框选／套索可混合选点，变换时选中的
  网格点只移动一次，未选网格点继续接受控制器影响。
  融合显示验证：画布核心 105 项、画布／属性／绘制 UI 56 项通过（1 项可选资产跳过），
  原生 Metal 标记测试通过。中英日截图覆盖默认 5 × 5／2 × 2 的静态及手柄变形后显示；
  混合选区的取消与拖回原位均保留原形状、缺省控制器状态和重做历史。
- 新建 Warp 默认网格细分 5 × 5（36 个网格点）、贝塞尔细分 2 × 2（9 个锚点）；
  嵌套分组为保持现有变形而需要继承父网格时，保留该网格结构。
  默认值验证覆盖 SDK 创建／分组／生命周期 40 项、Editor 创建／生命周期 18 项及
  Warp 属性 UI 5 项；包含保存重开、撤销重做及贝塞尔／网格点融合显示的实际点数。
- 网格插值不再提供用户选择；底层存储与导入／SDK 支持保留。
- 网格细分与贝塞尔细分直接提供横 × 纵输入，复用面板提交／预览／取消流程，取消独立弹窗。
- 移除 Numeric transform 数值变换入口和弹窗。
- 外框覆盖 Mesh、Warp 及 Part／Offscreen 的可变换内容；多选父子时归一化根，
  点选区只操作选点。参数、纹理等无画布几何的资源不提供无意义的外框。
  单个网格点、贝塞尔锚点／切线手柄或 Mesh 顶点只显示选中状态并直接拖动，不生成外框
  及其缩放／旋转命中区域；多点选区及对象整体保留外框。
  此项通过画布核心 106 项、单点／外框 UI 5 项及中英日原生截图验证，覆盖单点拖动、
  撤销、移除命中区域以及多选后恢复外框。

  Alt／Option 中心缩放。方向键为 1 个画布单位，Shift 为 10，Alt／Option 为 0.1。
  文本、树、时间线和弹窗保留自己的方向键行为。Rotation 使用原有中心、旋转轴、圆环及缩放控制，
  不提供外框；混合选择中的直接选中 Rotation 也不加入通用外框。

## 2026-11-01 交互修订

此前 A–F 的功能入口已齐全，但面板按实现顺序堆叠，常用细分与变换需要滚动查找，
“整体”按钮的名称随当前作用域改变，“仅调整边框”缺少清晰的结束入口。本次调整如下：

- Properties 首屏放名称、当前网格／贝塞尔细分数、数值变换和边框入口、保持子对象复选框。
  Rotation 首屏放姿态；贝塞尔控制、对象与层级、外观、原始形状分别折叠，按需展开。
- 工具栏先选贝塞尔／分割点，再选整体变换和固定子对象；整体按钮名称固定，提示说明
  作用于边框／数值变换，拖点仍编辑点选区。工具栏在窄视口内换行。
- 调整边框期间显示“不改变形状”和“完成”，暂停数值形状变换；退出后恢复编辑方式和
  保形开关。边框状态变化单独刷新属性面板，不依赖模型版本变化。
- 自动外框与控制点保持 12 个逻辑像素的间距。修正独立边框与控制点重合时，禁用控制点
  仍抢走手柄命中的问题；调整边框状态在未拖动时也持续显示。
- 跨多个 Warp 的点选区统一使用同一份边框状态；从任一对象的面板控制显隐、调整框和
  数值旋转，都使用画布上同一个框及枢轴。原先按菜单入口对象分别保存会使显隐和枢轴脱节，
  已用先失败再修复的回归用例验证，并覆盖未选点不变及一步撤销。

不扩大保形或原始形状恢复的算法适用范围。下文 A–F 记录的是先前实现与验证历史；
当前 UI 的布局和入口以上述修订及 Editor README 为准。

## 目标与范围

让用户可以在画布中完成 Warp 的整体和局部变换，在 Properties panel 中查看、编辑
已有的 Deformer 属性，并明确 Bezier、细分点和关键形状之间的关系。

包含以下工作：

- Warp 鼠标旋转、局部选区变换、移动约束与中心缩放。
- 变换边框显隐、独立调整和角度对齐。
- Warp 与 Rotation 的通用及专属属性面板。
- 转换细分数、Bezier 细分数、Bezier 编辑方式。
- 自动整形、沿手柄整形和重置 Bezier 控制器。
- 调整 Warp 时保持子对象不动。
- 记录、更新及恢复变形器原始形状。

按本次范围约定，软选择与笔刷、编辑等级、子对象越界检查及自动扩框不纳入方案。
保留当前 Bezier／细分点切换，不新增 Level 1/2/3 编辑体系。
属性面板覆盖 Warp 和 Rotation；Rotation 的画布手势重设计不在本次范围内。

## Deformer Properties panel

属性面板是本次首批交付的一部分。已有模型字段应提供可用的控件和写回路径；仅展示原始
JSON 或只读字段清单不能作为完成标准。只读仅用于当前目标确实不可编辑、派生值或诊断。

### 通用属性

| 显示项 | 模型来源 | 控件与编辑规则 |
| --- | --- | --- |
| 类型 | `TransformData` | 只读 Warp／Rotation 标签，不提供直接切换类型 |
| 名称 | `name` | 文本输入 |
| 运行时 ID | `runtime_id` | 文本输入；沿用 ID 校验，不改变内部稳定 ID |
| 启用 | `enabled` | 开关；与 Editor 的隐藏／锁定状态区分 |
| 所属 Part | `part_id` | 可搜索对象选择器，支持根节点；复用组织关系编辑 |
| 父变形器 | `parent_id` | 可搜索选择器，显示层级；排除自身、后代及无效候选 |
| 不透明度 | `appearance.opacity` | 百分比输入与拖动预览；保留合法导入值，不因读取或聚焦而截断 |
| 正片叠底色 | `appearance.multiply` | 颜色控件与通道输入 |
| 滤色色彩 | `appearance.screen` | 颜色控件与通道输入 |

外观字段显示当前编辑形状的局部值，预览展示层级合成后的结果。不能把父级合成值直接
写回本地字段。普通滑杆可以采用常用范围，但不能静默截断模型契约允许的扩展值。

父变形器选择必须走与 Deformer tree 相同的重挂接计划和可行性检查，不能只替换 ID。
现有子树重挂接保形限制必须在面板中一致体现；尚不支持的目标显示具体原因。
本方案后续的“保持子对象不动”能力也不自动等于任意重挂接保形。

### Warp 专属属性

| 显示项 | 数据性质 | 控件与编辑规则 |
| --- | --- | --- |
| 转换细分：横／纵 | 已有 `columns`／`rows` | 整数输入，初始沿用 Core 的 1–64 限制；操作作用于整个 Warp 的形状集合 |
| Bezier 细分：横／纵 | 已有控制器 `columns`／`rows` | 整数输入，沿用控制器 1–32 限制；创建／重建控制器后可独立调整 |
| 网格插值方式 | 已有 `quad` | 高级设置中的枚举；说明可能改变中间插值结果，不使用未经验证的 Cubism 版本标签 |
| Bezier 编辑方式 | 新增编辑设置 | 下拉选择，按后文算法验收后逐项开放 |
| 自动整形 | 新增编辑设置 | 开关，决定后续 Bezier 编辑如何处理细分点细节 |
| 沿手柄整形 | 新增动作 | 对当前形状执行一次整形 |
| 重置 Bezier 控制器 | 新增动作 | 按当前网格重建控制器，保持当前网格不变 |
| 选中点坐标 | 已有点数据的画布投影 | 单点显示 X/Y；多点提供相对位移，写回经过父空间逆变换 |
| 整体／选区数值变换 | 派生操作，不是 Warp 固有 TRS 字段 | 提供位移、旋转角和缩放输入，复用画布变换链路 |

任意变形后的 Warp 没有唯一的整体旋转角或缩放值。数值变换按当前边框和枢轴施加增量，
提交后增量归零；不把包围盒测量值伪装成模型里的位置／旋转／缩放属性。
横向对应 columns，纵向对应 rows，标签采用“细分数”而非“点数”。

### Rotation 专属属性

| 显示项 | 模型来源 | 控件与编辑规则 |
| --- | --- | --- |
| 原点 X/Y | `pose.origin` | 数值输入，明确标注父空间；保留 f64 精度，画布同步预览 |
| 角度 | `pose.angle` | 角度输入与拖动预览，单位为度；不限制为单圈 |
| 缩放 | `pose.scale` | 百分比输入，100% 对应 1；按契约和可逆性要求校验 |
| 水平／垂直反射 | `pose.reflect_x`／`pose.reflect_y` | 开关，分别提交可撤销编辑 |
| 基准角度 | `base_angle` | 独立数值项；与当前形状角度区分，说明其控制器参考方向语义 |

Rotation 的姿态字段写入当前 Base 或可编辑的关键形状，不能在用户编辑关键形状时
意外覆盖 `Transform` 的基础 pose。基准角度属于变形器定义，应单独路由。

### 属性读取、写回与布局

面板按“基础信息、外观、Warp／Rotation、形状操作”组织。随对象类型和编辑上下文更新，
显示当前写入的是基础形状、普通关键形状还是 BlendShape；不自动创建或选择关键形状。
已有中间参数值不可编辑策略应继续生效，并说明原因。

通用表单不能仅凭 `ObjectKind::Deformer` 生成固定字段集合，应由 Deformer provider
结合具体类型与编辑 scope 提供字段、值、可用性和动作。读取使用轻量投影；普通面板刷新
不序列化整套网格和所有关键形状。画布拖动后字段刷新不得抢焦点或覆盖正在输入的文本。

数值拖动和颜色选择复用 Properties 的候选预览、提交、取消流程，一次连续操作只产生
一步撤销。Enter 或明确完成操作时提交，Escape 取消；对象、文档或编辑目标变化时按
现有生命周期结束候选，过期控件不得写入新目标。

首版保证单选完整。多选只开放已实现原子批量写回的共同字段，并显示混合值；其余字段
给出单选提示。混选 Warp／Rotation 不显示错误的专属字段。锁定对象及锁定依赖沿用共同校验。

## 画布变换与边框

### 操作目标

没有点选区时，边框操作整个 Warp；存在点选区时，显示选区边框，只操作选中的点。
提供“整体变换”入口以保留点选区并临时操作整个 Warp。画布与数值面板共享这一目标。

选中 Bezier 锚点时，其自身手柄随变换移动；仅选中手柄时只编辑手柄。启用平滑影响模式
后允许影响邻域，但要与直接选择范围区分。细分点选区变换只改变选中网格点。
跨多个独立 Warp 的点可沿用批量编辑，祖先与后代同选的编辑继续拒绝，避免重复变换。

当前 `ControlChange::Transform` 被解释为全 Warp 变换。实现时必须拆出明确的作用域，
不能直接复用这个分支实现局部选区旋转／缩放，否则会误改未选中点。

### 手势规则

| 手势 | 提议行为 |
| --- | --- |
| 拖点 | 平移当前点选区 |
| Shift 拖点 | 沿画布水平／垂直方向移动；跨过拖动阈值后锁定主轴 |
| 拖边框边线 | 平移当前变换目标 |
| 拖角点／边中点 | 在边框局部轴上双轴／单轴缩放 |
| Shift 拖角点 | 等比缩放 |
| Alt／Option 拖缩放柄 | 围绕边框中心缩放 |
| Shift + Alt／Option 拖角点 | 围绕中心等比缩放 |
| 拖旋转柄 | 围绕边框中心旋转，连续跨越 ±180° |
| Ctrl／Command + 上述编辑手势 | 进入保持子对象不动的操作，见后文适用范围 |

新增独立旋转柄，避免与角点缩放共用命中区域。初期枢轴为边框中心；不扩展任意枢轴编辑。
坐标变换在画布空间定义，再通过已有父空间转换写回；不能直接在父局部坐标应用屏幕 delta。

修饰键在按下时冻结，沿用当前手势契约；拖动中按键不改变本次操作。Shift 点按保持
加选／切换选择；Shift 拖动已选点应保留该点并开始轴约束，因此点按取消选择需延迟到
松开后判断。Alt／Option 点按及区域拖动保留减选，命中缩放柄时优先解释为中心缩放。
Ctrl／Command 优先选择保形编辑，无法执行时给出原因，不回退成普通变形。

### 边框状态

支持边框独立显隐；隐藏边框时仍显示并允许编辑控制点。画布绘制和命中必须使用相同
可见性，隐藏的边框不能继续截获拖动。缩放柄、旋转柄和控制点优先级通过共用几何确定。

提供显式“调整边框”模式，只修改操作框的位置、尺寸与方向，不写入模型；再提供
“对齐变形器方向”和“重置边框”。对齐方向从 Warp 网格整体横向趋势估计，退化情况
说明不可确定，不能随机跳转方向。手动框与自动框均明确自身中心和局部轴。

边框状态属于视口操作状态，不写入模型历史。按视口、对象和选区关联；切换目标后重建，
外部几何修改使旧边框失效。一次手势始终冻结起始框，不因预览产生的新包围盒而漂移。

## Bezier、细分和整形

### 数据关系

转换网格是实际变形求值的数据，Bezier 是作者编辑控制器。仅切换显示模式不得修改
二者，不产生撤销项；控制器缺失时可以显示派生控制器，但实际写入必须进入正式编辑。

提议将“控制器 + 网格残差”作为编辑语义：关闭自动整形时，Bezier 的变化增量叠加到
当前网格，保留手工细分点细节；直接编辑细分点不再丢弃已有控制器。
残差可以由网格与控制器求值差按需计算，无需先引入第二套持久化顶点数组。

| 操作 | 对网格的作用 | 对控制器的作用 |
| --- | --- | --- |
| 细分点编辑 | 修改选中网格点 | 保留已有控制器 |
| Bezier 编辑，自动整形关闭 | 应用控制器前后求值差，保留网格细节 | 更新控制器 |
| Bezier 编辑，自动整形开启 | 按新控制器重新采样当前形状 | 更新控制器 |
| 沿手柄整形 | 按当前控制器重新采样，明确会覆盖细分点细节 | 不变 |
| 重置控制器 | 保持当前网格逐点不变 | 按网格拟合／重建控制器 |

自动整形默认关闭，保持已有 delta 编辑的基本行为。切换开关本身不立即改变几何；
用户需要立即整形时使用显式动作。重置后再拖动应以新控制器和当前网格为基线，不能跳形。

### 细分设置

转换细分变化调用共同 Core/SDK 重采样计划，覆盖基础形状、普通关键形状及 BlendShape
位移，并保持点数量契约一致。Bezier 细分变化按目标控制网格重新拟合控制器，默认保留
当前转换网格，不能把改变控制器密度隐式当作整形。

转换细分输入是整个 Warp 的定义级操作。Bezier 细分也作为整个 Warp 的一致编辑配置：
统一处理其已存储控制器，缺失控制器保持可派生。不能只修改当前形状导致其他形状在切换
时出现不一致的控制点编号和选择。

已有 `ResizeWarp` 会提示重采样可能改变节点之间的插值。增密是否精确保形取决于原网格
分区与插值方式；减密尤其不能承诺无损。提供预览、实际误差信息和明确提交，取消恢复
原网格、控制器、全部关联形状及选择。手柄拖动期间不再静默改变已显式设置的转换细分。

### 编辑方式

参考 Cubism 的局部平滑、全局平滑和保持控制结构能力，提供可解释的邻域影响策略。
首批保留当前局部编辑作为基准，再实现由弱到强的平滑影响及保持控制结构策略。
不能仅增加选项标签，各策略必须具有可观察且稳定的区别。

手册只描述效果，没有公开完整权重公式。具体核函数、边界处理、手柄耦合与对称性需
通过小型规则网格夹具和参考操作验证后定稿；未经比对不宣称等价于 Cubism 的某个版本。
本项目未发布，无需为此新增 Cubism 2.1／5.2 兼容模式。

## 保持子对象不动

用户通过 Ctrl（macOS Command）拖动调整 Warp 的位置、大小、角度或控制点，画布上
已有子对象保持原样。面板提供同一模式入口，并在操作时清晰显示当前处于“只调整变形器”。

这是一项坐标重参数化操作，不能通过临时解绑、只修正当前显示顶点或屏蔽渲染来实现。
对旧变形映射 F 和新映射 G，子对象补偿满足 `G(x_new) = F(x_old)`；整体计划同时包含
Warp 修改、子对象转换和所有关联形状修改，提交为一步撤销。

先交付可验证的仿射场景，再扩展非线性编辑。支持范围由共同转换计划判定，面板和画布
使用相同结果。仿射能力交付不能标记为任意控制点调整已完成。

必须处理基础形状、普通关键形状、BlendShape 和嵌套变形器的表达能力。有限网格的
非线性重参数化、Rotation 子对象及参数插值未必能精确保形：先验证可表示性和逆解唯一性，
对近似转换同时验证独立采样点与参数中间值误差；只检查网格节点或关键点不足以证明保形。

无法满足容差、存在奇异／折叠映射、受影响对象锁定，或相关依赖尚不支持时，原子拒绝并
指出原因。不得只保住当前参数姿态却改变其他已存形状，也不得把采样通过表述成全域精确保证。
误差阈值在实现数值实验阶段确定，采用画布模型单位，不依赖当前缩放或屏幕像素密度。

## 原始形状与恢复

在原生项目中为 Deformer 记录独立的原始形状。记录含画布空间形状、类型、必要的网格／
控制器信息以及创建／更新来源；它不是 Undo 的某个历史节点，也不是当前参数默认值。

创建时记录原始形状；首次从无普通关键形状进入有关键形状时，可按对象的“自动更新”
开关更新。面板显示记录状态，提供“更新原始形状”“恢复原始形状”和自动更新开关。
手动更新后关闭自动更新，避免下一次加键覆盖用户保存的基准。

恢复作用于当前可编辑形状，经当前父空间逆变换后恢复记录的画布形状；不回滚其他参数
或整个文档。记录不存在、逆解不唯一或类型／拓扑转换无法完成时明确拒绝。恢复需要改变
共享转换细分时，必须对其他形状执行共同重采样计划，并在提交前说明其影响。

原始形状及本方案新增作者设置须参与原生项目保存、重开、复制和撤销。CMO3 等交换格式
是否能保存这些信息应单独验证；现有 CMO3 导出已说明不会保存 Bezier 手柄，不能承诺
新增属性在所有交换格式中无损往返。

## 架构与状态归属

| 层 | 职责 |
| --- | --- |
| Contract | 新增持久化作者设置／原始形状的类型与校验；明确形状目标 |
| Core | Bezier 策略、整形、重采样、坐标转换、子对象补偿与原始形状恢复计划 |
| SDK / Runtime | 类型化编辑入口、版本校验、候选事务、原子提交及历史 |
| Editor Core | 变换目标与边框状态、修饰键策略、命中、属性 scope 与可用性 |
| Editor UI | 类型化 Properties 布局、数值／颜色／引用控件、工具栏及菜单入口 |
| Project / 格式层 | 新增元数据的保存、复制、重开与交换损失报告 |

Bezier 编辑方式、自动整形开关和原始形状记录属于对象作者设置；基础／普通关键形状
仍各自保有相应控制器。BlendShape 目前没有独立 Bezier 控制器，必须沿用显式编辑准入，
不能借新增面板偷偷写入基础控制器。完整 BlendShape 控制器体系不作为本次隐含新增能力。

视口边框、当前模式和点选区留在 Editor 操作状态。Properties 仅发起编辑，不能维护
第二套正式形状或直接替换 Runtime 所有的文档。几何预览变化必须驱动画布与属性同步刷新。

沿用[视口交互契约](../references/viewport-interactions.md)：起始帧和目标冻结，预览基于
同一原始状态计算；提交一步历史，Escape、失焦、丢失鼠标按键及上下文失效取消未完成编辑。
失败操作不能留下部分修改；回到原点的无变化操作不新增历史。

  偏差和 293 点转换格偏差，不把采样最大值视作全域上界。粗转换格可能不能表现手柄曲率。
- Properties 提供重置控制器、沿手柄整形、自动整形和影响方式。重置保持转换格，显式
  整形覆盖当前可编辑形状的细节；自动开关本身不改几何，相同控制值提交不触发整形。
- 策略为 Zipzi 自有算法：局部仅改选中项；邻近平滑使用半径两控制格的余弦核；全局平滑
  使用 UV 空间高斯核；结构模式保持反向切线长度比。显式选择优先于邻域传播，锚点带自身
  手柄，手柄编辑不移锚点。状态栏提示扩大影响范围；不宣称与 Cubism 算法等价。
- 新增作者设置通过共同类型化计划写回，参与原生保存重开、复制和撤销；锁定绑定、无效
  密度及不支持的 BlendShape 控制器动作原子拒绝。CMO3 导出明确报告设置及控制器元数据损失。

E 阶段交付：

- Properties 提供“只调整 Warp，保持子对象”模式，数值变换共用；macOS Command／
  Windows Ctrl 从按下时启用同一手势策略。当前范围要求被编辑 Warp 的新旧转换格为静态、
  可逆仿射映射，允许 float32 构造误差，不对近似非线性映射作精确保证。
- 共同 `WarpKeepChildren` 计划按 `G⁻¹F` 统一转换直接子 Mesh／Warp 的基础、普通关键形状
  和控制器，BlendShape 位移只用线性部分。Rotation 子对象复用父空间重参数化，补偿基准
  方向和原点／缩放通道；更深子树保留原输入，包含非线性嵌套 Warp。
- 静态矩形 Warp 及 Rotation 父链可用；被编辑 Warp 或祖先已驱动、非线性祖先／新旧映射、
  奇异映射、转换细分变化、锁定依赖及超出数值预算时原子拒绝。任意控制点调整没有标为可用。
- 每次预览从按下时的完整通道重算，回到原点精确恢复缺失元数据及子对象；取消不留候选，
  成功一步撤销。模式切换保留视口手动框，并使旧数值目标失效。
- 数值预算固定为 0.01 画布单位，包括测量偏差和 float32 构造包络，与缩放和设备像素无关。
  新旧原生映射用 121 个独立内外采样点验证，并核对含隐藏对象的默认／逐驱动端点、关键值
  和关键中点姿态。报告给出测量最大值和样本数；结构上的仿射通道转换与采样验证分别说明，
  不宣称采样证明全参数域误差上界。
- 非线性实验使用原生双线性映射 `G(u,v)=(u(1+v),v)`：两个普通关键位置分别精确求逆后，
  线性插值中点仍偏移约 0.047847 单位。因此拒绝“只改当前顶点／关键点”的替代实现；
  非线性、折叠及更广父空间仍属于后续能力范围。

F 阶段交付：

- Warp／Rotation 原始形状以独立画布空间快照持久化，记录创建／首次加键／手动来源，
  不引用 Undo 或关键形状。SDK 创建与首次加键使用冻结的预览父姿态；Core 直接调用未指定
  上下文时使用参数默认值。分组创建在最终保形归一化后记录实际形状。
- 首次创建普通关键形状可自动更新一次，删除再建绑定不会重复覆盖；关闭自动更新仍记录
  已经历首次加键。手动更新关闭自动更新。旧项目及导入对象缺失记录时明确显示未记录，
  不把载入时的形状猜作原始形状；可显式手动更新。
- Properties 提供来源、自动更新、更新和恢复入口，覆盖中英日文。形状动作只作用于当前
  可编辑 Base／普通关键形状，拒绝 BlendShape 及中间参数目标；自动策略独立路由。
  目标冻结会话、完整版本、预览参数、scope 和对象选择，撤销后旧按钮目标不会复活。
- 恢复经当前父空间逆变换写回当前形状，保留当前父级、Rotation 基准角度及其他参数形状。
  转换细分／插值或已有控制器的共享密度需要变化时，先显示影响审阅，再共同重采样
  Base／普通／Blend 网格或重拟合全部已存控制器；取消无编辑，应用一步撤销。
- 恢复保留控制器的缺失状态；缺失控制器仍按当前作者配置派生，不回滚整套编辑策略。
  当前父空间须可逆仿射；非线性、奇异、类型不匹配、锁定依赖及误差超限原子拒绝。
  旧非线性父空间下保存的原生烘焙网格可恢复到可用父空间，但已有控制器不能宣称精确
  转换为画布空间三次曲线，明确拒绝该控制器恢复。已存控制器另以 289 个独立样本检查
  0.01 画布单位容差，采样不构成全域误差证明。
- 原生 JSON／CBOR、保存重开、复制和撤销保留记录及首次加键标记，历史预算计入快照
  网格、控制器与诊断。CMO3 明确报告原始形状元数据损失，导入不伪造记录。
