# SDK Runtime 分阶段实施计划

合仓导航：SDK 与 Editor 现位于同一仓库的根 `crates/`，Editor 资产位于 `crates/kasane-editor/assets/`；下文两仓名称表示原模块职责，旧 R0 记录保留原路径与 SHA。新采集使用同一仓库 SHA、dirty 状态和根锁文件。
日期：2026 年 10 月 23 日。状态：**R0 实施准备进行中，R1–R7 尚未开始**。

架构与行为契约以[详细设计](sdk-runtime-design.md)为准。本文定义两个仓库的交付顺序、接口覆盖与验收。当前不存在 `kasane-runtime` 或连接后端；后续新增模块、测试名称和命令模板仍为待实现目标，不能作为已经通过的证据。R0 已落地产物与未完成项见 [实施记录](sdk-runtime/r0-preparation.md)。

## 1. 执行规则与阶段总览

- 先读两个仓库 README 和各自 AGENTS；保留工作区已有改动。当前 editor 仍在进行 UI 统一，R0 需要重新确认切入基线，不能依赖聊天中的旧文件布局。
- 每阶段先交付 kasane-2d 的公共能力，再接 editor 适配；记录可配对的两仓 revision、必要的 lockfile/依赖变更。路径依赖不由 Cargo.lock 固定，不能只写“使用最新 SDK”。
- 日常迭代运行受影响模块/过滤测试；全套门禁用于最终交付或确有跨域风险的阶段。检查通过后不无原因重复扩展测试。
- Runtime 保持薄层。发现新领域规则归 core/SDK；连接适配只能转换类型和调用。
- 每阶段有行为测试和可复核证据，不能以“编译成功”“接口已添加”替代验收。未知/跳过的 GPU 或模型用例不计为通过。
- 允许两仓破坏式重构，不做旧实验协议/包布局迁移；已有制作行为、资源正确性和性能约束需要保留。

| 阶段 | 交付目标 | 前置依赖 | 状态 |
| --- | --- | --- | --- |
| R0 | 接口清单、配对基线、预算与性能门槛 | 无 | 进行中，见实施记录 |
| R1 | 无 UI 的 Runtime 核心与 SDK 补强 | R0 | 未开始 |
| R2 | Editor 使用托管会话，窗口生命周期解耦 | R1 | 未开始 |
| R3 | 本机协议和 Python 最小完整闭环 | R2 | 未开始 |
| R4 | Modeling、资源、Plan 与工程 IO 完整连接 | R3 | 未开始 |
| R5 | Animation、独立 Preview、Observer 和长任务 | R4 | 未开始 |
| R6 | 候选 Review 与人工精修后接续 | R5 | 未开始 |
| R7 | 完整创作、发行包、性能与生命周期总验收 | R6 | 未开始 |

阶段可以在前置契约稳定后提前准备测试 fixture，但不能跳过退出门槛。R3 是连接可用的最小交付；整个项目完成要求 R7，而非在 R3 后将未覆盖领域留作静默限制。

## 2. R0：基线、清单与实施准备

### kasane-2d 改动/产物

- 从 SDK 公共 API、Python facade、现有 `python-coverage.json` 和 `tools/check_coverage.py` 建立新的连接覆盖清单，不以旧绑定统计推定完整。
- 为每项列出：领域、SDK 入口、Python 入口、SourceRef、输入/结果、修改/历史效果、Plan/句柄生命周期、批量形式、长操作属性、对应验收。
- 核对 NativeBackend 独有类型依赖、候选观察与内存资源缺口、默认 preview 和事件读取的迁移策略；盘点 Python Edit 的 `_call`、`commit`、`__exit__` 和取消路径，明确领域失败、Busy 与结果未知的不同处理。
- 记录 AuthoringSession/候选/快照的内存与 clone 成本、代表性 commit/plan/save 耗时，确定哪些调用不能直接放 UI 线程。
- 盘点 `prepare_rgba_asset`、`retain_prepared_image` 与工程 `memory_assets` 的持有和清理路径。当前资源表会长期持有像素，历史预算只计图片描述信息；取消候选或淘汰历史不等于释放底层资源，须将统计与回收原语列入 R4 的 SDK 补强。

### editor 改动/产物

- 列出所有 session 可变访问、`drain_events`、commit/undo/redo、保存与资源替换入口，建立迁移检查表；同时盘点在途加载/保存的路径预留和依赖窗口的任务完成回调，分别归入 Runtime 注册表与应用级宿主。
- 记录 Modeling 手势、Properties、Timeline、动画播放、多视口、文档切换和关闭行为基线。
- 记录两仓 revisions、工作区差异、Rust/Python/构建模式、机器/GPU、模型身份与参数，不把未提交 UI 工作遗漏在测量之外。
- 冻结设计第 13 节的默认预算及支持 Python 版本，写明依据。性能门槛按第 6 节执行。
- 记录 endpoint 发现规则、宿主可执行文件定位方式和启动等待上限；开发入口、桌面入口与 Python 启动请求必须使用同一套 endpoint 身份及仲裁规则。

### 接口与退出门槛

- 覆盖表每项均分类为需要连接、纯本地 helper 或明确不属于创作接口；未知状态不得当作“不需要”。
- 所有当前正式写入路径均有迁移归属，能区分持久模型变化与 Editor 临时状态。
- 完成 A01 基线清单，输出可重复使用的合成模型/动画/内存纹理 fixture 和性能命令。
- R0 是后续实施的第一步；原设计文档阶段未运行 benchmark 或改测试工具，实施阶段的实际运行证据另行记录。

## 3. 分阶段交付

### R1：Runtime 核心及 SDK 契约

**kasane-2d**

- 新增 `kasane-runtime` 并接入 workspace，基础构建无 GPUI/PyO3/GPU 要求。
- 实现会话注册、RuntimeInstanceId、SessionId、操作表、所有权转移与 Ready/Busy/Faulted/Closing/Closed 状态；提供进程内类型化接口。持有正式会话的 worker panic 且一致性无法确认时进入 Faulted，保留可用的版本化冻结读视图，拒绝继续写入或保存，不自动恢复 Ready。
- 注册表统一管理已打开工程身份和在途 Open/Save As 的路径预留；按工程规范化身份识别目录、manifest 等等价入口，在派发 IO 前原子检查并预留，不能仅靠每会话 Busy 防止跨会话覆盖。保存期间保留旧路径身份，成功后更新身份，失败保留原身份；临时预留在任务完成或确认停止后释放，不能收到取消请求就提前释放。
- 实现 SDK 回执的唯一消费点、原子订阅快照/游标、管理事件、有限事件缓冲与 resync。
- 用 SDK owned candidate 实现事务托管、客户端归属、统一提交和临时对象预算。补候选读取/快照公共契约；保持 SDK 规则唯一。
- 建立 executor/作业适配接口，先以 CPU 测试宿主证明后台结果、取消、所有权归还及 panic 的终态投递；完成结果以宿主中的操作为目标，不依赖发起视图存活。不把具体桌面执行器放进 crate。

**editor**

- 仅准备新的路径依赖和最小类型对接；主文档所有权迁移在 R2 完成。
- 用 editor-core 测试 fixture 验证可直接读 Runtime 中的文档数据，不复制一套正式会话。

**退出门槛**

- A02、A03、A04、A05、A08、A10 的进程内/CPU 部分通过。
- 两个调用方共享同一历史：交替提交、Undo/Redo、删除/恢复后旧句柄失效，且取消/no-op 保留 redo。
- 失败操作不发布部分修改；Runtime 不能用预检查代替 SDK commit 校验。
- A02 覆盖跨会话并发 Save As、Open 与 Save As 冲突及失败后重试：在途目标只被一个操作占有，被拒绝的操作不改写目标文件或其他会话，预留按终态释放。
- A08 单独注入持有正式会话的 worker panic：Job 和 Session 均进入明确终态，不永久停在 Busy、不伪装 Ready；可检查冻结来源，其他会话仍可用，重复或晚到完成消息不能复活故障会话。普通 SDK 错误归还同一会话与此路径分别验收。
- 事件断档明确要求 resync；无订阅者时写入语义相同。
- crate 依赖检查证明 SDK 不反向依赖 Runtime，Runtime 基础目标不包含 GUI/Python/GPU。

### R2：Editor 所有权、发布和窗口生命周期

**kasane-2d**

- 为 Editor 迁移补齐必要的短调用、SDK 回执和共享读取接口。
- 落实交互占用与会话 Busy 契约，确保它们不成为新的持久模型字段。

**editor**

- 将 AuthoringSession 从 Document/EditorView 所有权链移入应用级 Runtime；DocumentView 保留选区、投影与工具适配。
- 迁移模型、属性、排序、对象操作、Timeline、Undo/Redo、资源、保存等全部正式写入入口。
- 删除 Editor 对托管 SDK 的独立 event drain，以统一事件驱动投影、纹理和动画更新；防止 UI 本地提交重复通知。
- 将后台保存的 SDK 所有权移交、任务持有者和完成投递一并迁入应用级宿主/Runtime；Open/Import 等会话任务沿用同一生命周期。先在宿主中归还会话并记录结果，再通知仍存活的视图；不得把 `finish_save` 等正式完成处理放在窗口 `update_in` 成功的条件内。保留视图冻结数据和原有失败反馈，无窗口时结果仍可查询。
- 将当前 Workspace 的已打开路径、在途加载和 Save As 目标保护迁入 Runtime 注册表，所有 UI 写入使用同一预留流程。
- 实现无窗口启动、窗口 attach/detach、驻留会话列表与显式应用退出；变更 dev-session 和开发脚本时保持单宿主发现和进程清理正确。
- 保持属性输入、焦点/IME、Esc、窗口失焦、Timeline 手势的既有行为。

**退出门槛**

- A02–A05 的 UI 部分以及 A08、A09、A10、A13、A16 的 R2 部分通过。
- 无 Python/IPC 时也能完成原有制作，关闭并重开窗口后同一未保存会话、对象和历史仍存在。
- 保存进行中关闭最后一个窗口，分别在无窗口期间完成成功与失败任务，再重开窗口：同一会话和历史仍在，状态不残留 Busy，成功保存更新路径/modified，失败保留脏状态及可查询错误；加载/导入完成也不能因发起视图消失而丢失或重新弹出窗口。
- 保存失败、后台任务失败和切换文档不会将结果送到错误文档。
- 静态迁移表和测试共同证明没有残留可绕过 Runtime 发布的托管写入口。
- 运行第 6 节交互基线比较，达到门槛后才进入 IPC；不把 UI 回归留到总验收处理。

### R3：IPC 与 Python 最小闭环

**kasane-2d**

- 实现本机 framing/DTO、严格握手、请求去重、远端 token、事件、预算和有限重连。
- 分离 Python facade 与 `_native` 的 import 依赖，提供连接模式所需纯 Python 类型/异常和安装产物；保留 NativeBackend。
- 重构公共 Edit 的生命周期：已确认的普通编辑失败使候选失败；明确未执行的 Busy 保留 Edit；传输超时/断线导致结果未知时保留 RequestId 和待确认操作，阻止后续写入并允许查询/同 ID 恢复。不得在任意异常后直接 abort，或在 commit 的 `finally` 中无条件标记关闭；上下文退出也必须遵循这些状态，不能掩盖原异常或把未确认提交当作已取消。
- 提供 endpoint 发现及按需启动客户端流程；协议不匹配仍直接失败。启动超时不视为宿主已死亡，不因超时自动拉起第二个实例。
- 最小覆盖：连接、列出/创建/绑定会话、对象/参数批量查询、事务内读取、Mesh/Parameter 修改、提交/取消、历史和保存。
- 增加真实子进程客户端测试，不只测试内存中的 mock transport。

**editor**

- 装配 socket listener 与应用线程调度；支持从无窗口宿主打开已有会话窗口。
- 实现按用户/endpoint 的启动仲裁与宿主驻留期间的唯一所有权，统一 Python 冷启动和桌面启动/重开入口；以成功握手判定就绪。残留 socket/发现记录只有在取得唯一所有权、确认无活跃宿主后才能清理；启动失败须结束本次尝试并允许后续重试。
- 用真实 Python 子进程修改 Editor 中未保存的合成工程，检查 UI 增量更新与历史。

**退出门槛**

- A06、A07、A12、A17 的最小切片及 A18 生命周期闭环通过；独立 Preview 在 R5 验收。
- 测试覆盖 apply 成功后丢响应、commit 成功后丢响应、重复 ID 不同参数、重连查询、去重结果过期和宿主重启。
- A07/A12 的故障注入必须经过安装后的公共 Python Edit 与 `with session.edit(...)`：Busy 后保持候选且可用新 RequestId 重试；apply/commit 响应丢失后不自动 abort、关闭或重复提交；未确认结果阻止后续写入；普通编辑错误即使捕获也仍不能提交，清理失败不替换原异常。
- A06 使用两个真实 Python 子进程同时冷启动，确认只有一个宿主、双方得到同一 RuntimeInstanceId，并能绑定同一未保存会话；覆盖慢启动超时、残留 socket、监听前启动失败、后续重试及桌面重开复用，不能用两个进程连接预先启动的宿主代替。
- 用 UI 与真实 Python 客户端竞争同一 Save As 目标，重跑 A02 的路径预留切片，证明连接入口不会绕过 Runtime 的跨会话保护。
- 未安装原生扩展的隔离环境能 import 连接客户端并完成上述闭环；不得通过开发机 PYTHONPATH 意外加载源码扩展。
- Python 正常退出/被终止不带走正式会话；未提交候选按约定回收，已提交结果不重做或回滚。
- 小切片能力在握手中如实公布，缺失操作显式报不支持。此阶段不声明 modeling/animation 全覆盖。

### R4：完整 Modeling、资源与工程操作

**kasane-2d**

- 覆盖场景对象、参数/分组、层级/排序、网格与拓扑、变形器、绑定/关键形/BlendShape、Glue、Offscreen、引用和文档元数据。
- 接入只读规划、成本/损失报告、能力查询、稳定字段地址和 SDK 句柄；删除、移动、Undo 后失效语义与 NativeBackend 一致。
- 交付正式与候选 `SourceRef` 上的无状态 CPU 求值、显式参数批量采样和建模几何诊断，沿用 SDK 的求值规则与容差；结果携带来源、Version、候选序号及参数，不修改任何 Preview 或历史。该能力用于本阶段绑定、关键形和 BlendShape 验收，不依赖 R5 的独立播放实例或 GPU Observer。
- 接入图片/附件、内存内容、大数组/blob、资源诊断、工程打开/导入/保存/导出，以及项目替换的 generation 语义。
- 实现对应长任务、资源快照和取消；总预算覆盖多个候选/Plan/临时数据。
- 补齐 SDK/project 的内存资源计费、持有与回收公共接口，由 Runtime 接入总预算。统计实际存活的 RGBA、已编码 PNG 和准备中负载，记录共享负载的计费规则，不能只统计远端 token 或沿用历史元数据估算；资源准备、注册和编码缓存增长前检查或预留预算，失败释放临时占用且不破坏已有状态。
- 资源持有关系覆盖正式内容、Undo/Redo、活动候选/Plan、快照、Preview 和 Job，R6 的 Proposal 复用同一机制。取消、失败、显式释放、断连清理及历史淘汰后回收已无使用者的负载；仍被任一来源引用的内容保持可解析，不能靠清空整个资源表或关闭 Session 实现回收。

**editor**

- 验证外部变化对全部对象投影、选择、关系面板、纹理和属性表单的更新。
- 提供带版本的可选 EditorContextProvider；无窗口时查询模型仍正常。
- 对计划和失败提供必要反馈，不为外部写入调用隐藏的 UI 菜单流程。

**退出门槛**

- 第 4 节覆盖表的 modeling/资源行全部完成，A04、A05、A09、A10、A12、A14、A15、A17 对应案例通过。
- 同一 recipe 在 NativeBackend 和 ConnectedBackend 上生成等价原生内容、几何结果、诊断和历史效果。
- A15 使用连接 API 对正式与候选模型做参数 sweep，比较绑定/关键形/BlendShape 的采样结果并验证正式状态、人工预览及历史未被求值改变；不能通过保存后另开 NativeBackend 代替连接求值验收。
- 在 SDK 规定限额内测试大网格、已有绑定的拓扑编辑与资源替换，限额之外保持原状态。
- 无窗口完成素材导入、模型构建、保存重开和导出；实际运行涉及内存资源的流程，不能只用已保存模型绕过。
- A17 在同一驻留会话中至少 100 轮准备不同内容的图片再取消候选，并覆盖图片替换提交后的历史淘汰；不通过关闭/重开会话清理。直接核对底层资源条目及存活字节有界、无使用者的负载被回收，并验证预算拒绝不残留资源、不改变正式内容或历史；仍被历史、候选或快照引用的图片继续可读，最后释放后占用返回应有基线或声明的有界缓存。

### R5：Animation、Preview、Observer 与调度

**kasane-2d**

- 完成 Motion/Track/Key/Event、注册组、Expression、Physics、Pose 及相关 Plan/地址的连接覆盖。
- 在 R4 无状态 CPU 求值与来源契约上，实现每客户端/每视图独立 Preview、动画批量采样、seek、播放结果和空间诊断。
- 接入 sdk-observe，候选新增和替换资源可正确解析；结果携带版本、候选序号、参数/时间和资源来源。
- 完善长任务取消、并发预算和批量观察调度，使交互工作不会被持续批任务饿死。

**editor**

- 将当前隐式共享的 preview 状态迁为视图/客户端作用域；保持双视口和动画 worker 的版本拒绝机制。
- 接入外部动画内容变化后的 Timeline、资源列表、检查面板和播放来源更新。
- 保留原生 Metal 展示链，依据测量做必要资源复用，不为接入而重写渲染器。

**退出门槛**

- 第 4 节动画/观察行全部完成；A08、A11、A14–A17 对应案例通过。

### R6：候选 Review 和人工接续

**kasane-2d**

- seal 在 Runtime 协调下检查正式 Version 等于 edit 基准，捕获该基准的只读快照并固定基准/候选资源，完成预算检查后才消费 Edit 并登记 Proposal。若准备工作移到后台，登记前再次检查版本；提前发生外部提交则返回 `STALE_VERSION`，不生成 Proposal，也不把当前正式内容冒充旧基准。Busy 或资源/预算准备失败不吞掉 Edit，版本过期后的候选仅按设计保留只读诊断来源。

- 提供接受/拒绝及接受后进入正式文档精修的流程。保持文档级独占保存与未决候选限制明确可见。
- Agent 能查询人在正式文档上的新版本并开始下一轮制作，不读取另一个临时副本。

**退出门槛**

- A19 全部通过：seal 不产生历史、拒绝不改变 redo、接受恰好一个步骤、过期不能覆盖、脚本退出后仍可 review。
- A19 分别覆盖 seal 前及准备过程中发生外部提交、seal 后正式版本变化：前两者不生成错误基准的 Proposal，后者保留固定基准/候选供只读对比但拒绝接受；预算/资源准备失败不丢 Edit，成功 seal 后客户端清理不影响两侧资源。
- A17 覆盖 Proposal 固定资源后客户端清理、历史淘汰和 Proposal 最终释放：引用存续期间两侧内容可读，最后一个使用者释放后底层负载被回收。
- 人接受并手动微调，随后 agent 读取到精修结果并继续修改；原对象身份和 SDK 历史连续。
- 无 GPU 环境可完成 CPU 候选与报告检查，图像能力不足明确报告；有 Metal 的验收环境必须完成实际图像/播放对比。

## 6. 性能、内存与工作量门槛

### 6.1 测量方法

复用[属性链基准](../../tools/benchmarks/README.md#property-editing-chain-benchmark)、[UI 性能参考](../references/ui-performance.md)和 README 中的 Timeline/窗口基准。采用相同机器、Release 配置、模型、窗口尺寸和交互脚本；预热后至少 5 对交替的 baseline/candidate 进程测量。记录每进程 P50/P95、各进程统计的中位数和范围，不将不同操作或不同模型混为一个平均值。

最低场景：属性数值/颜色拖动、顶点或变形器拖动、Timeline 键拖动/seek、持续动画播放、双视口切换，以及另一文档存在后台 agent 批次时的人工操作。

### 6.2 默认判定

- 对没有刻意改变算法的已有 UI 路径，CPU/输入到显示延迟的 P50 增量不超过 baseline 的 10%，P95 不超过 15%；允许绝对噪声裕量分别为 CPU 阶段 0.2 ms、输入到显示 1 ms，按两者中较大的允许增量判断。
- 如果 R0 实测噪声已超过此窗口，先登记新的测量方法/阈值及依据，再开始相关改动；不得在看到失败后临时移动门槛。
- 现有工作量回归继续有效：单次输入不引入重复 SDK 提交、重复历史、无必要全索引重建或每事件完整模型快照；标签等 metadata 修改不增加不必要的几何/动画求值。
- 批量 agent 工作有公平调度；上述无独占冲突场景适用同一 UI 门槛。会话被明确 Busy 的操作单列耗时与反馈，不把冻结画面算作低延迟通过。
- 连接、读取少量上下文不在 Python 侧建立完整模型或历史。记录正式会话数量、候选/快照估计字节、图片缓存及进程 RSS，不能只以 RSS 不翻倍证明正确。
- 反复创建/释放 Edit/Plan/Preview/blob、取消 Job、断连至少 100 轮后，存活计数返回应有基线，字节占用在已声明缓存/预算内；RSS 分配器驻留与实际存活对象分别报告。
- 内存资源报告包含 SDK/project 资源表中的 RGBA、已编码 PNG 和准备中负载；按持有来源说明仍存活字节，不能以 Edit/blob 数量回到基线代替底层资源回收证据。图片循环使用不同内容，避免内容去重掩盖累积；R4 验证取消与历史淘汰，R6 补 Proposal 持有与最终释放。
- 大数组传输按批量进行，给出代表性 Mesh/动画负载的往返次数、字节、P50/P95；不承诺无基准依据的“零开销”或通用固定 RPC 延迟。
