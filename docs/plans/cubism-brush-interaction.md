# Cubism 笔刷交互与需求方案

状态：需求讨论稿，尚未实施。日期：2026-11-05。

为 Zipzi Editor 增加变形、扩展与收缩、Warp 整形、笔刷选择四种功能，
支持 Mesh 和 Warp。快捷键和操作手感尽量对齐 Cubism，工具面板沿用 Zipzi 风格。
当前阶段先确定交互与需求，不进入代码实现。

## 1 已确认范围

| 项目 | 已确认内容 |
| --- | --- |
| 功能 | 变形笔刷、扩展与收缩笔刷、Warp 整形笔刷、笔刷选择全部纳入 |
| 对象 | 先支持 Mesh 和 Warp；Warp 整形仅作用于 Warp |
| 暂不支持 | 图形路径与胶水笔刷 |
| 操作体验 | 快捷键与手感尽量对齐 Cubism |
| 界面 | 沿用 Zipzi 的面板风格 |
| 当前交付 | 需求和交互方案；继续讨论后再实施 |

除本节外，Zipzi 的具体操作规则均为建议，待讨论确认。
手册明确的 Cubism 行为与需要实机核对的细节分别列出，不能把建议当作已确认决策。

## 2 Cubism 行为基线

### 2.1 四种功能

| 功能 | 手册描述的行为 | 本次适用对象 |
| --- | --- | --- |
| 变形笔刷 | 以涂刷方式直接改变对象形状 | Mesh、Warp |
| 扩展笔刷 | 按住鼠标左键使对象扩展；Shift 加按住使其收缩 | Mesh、Warp |
| Warp 整形笔刷 | 根据贝塞尔手柄位置整理分割点，使形状顺畅并修正局部塌陷 | Warp |
| 笔刷选择 | 涂出具有不同权重的选择区域，再对顶点进行移动、旋转或缩放 | Mesh 顶点、Warp 分割点 |

前三种功能依据 [Cubism 变形笔刷手册](https://docs.live2d.com/zh-CHS/cubism-editor-manual/deform-brush/)。
笔刷选择依据 [如何选择](https://docs.live2d.com/zh-CHS/cubism-editor-manual/how-to-choose/)
与 [如何编辑](https://docs.live2d.com/zh-CHS/cubism-editor-manual/how-to-edit/)。

Warp 整形的参考是贝塞尔手柄定义的形状。简单地对相邻顶点求平均，
不能作为已经对齐 Cubism 整形行为的依据。

### 2.2 参数与快捷操作

| 参数 | 含义 | Cubism 快捷操作 |
| --- | --- | --- |
| 权重 | 控制变形影响强度或选择权重 | 本方案不指定快捷键 |
| 大小 | 控制影响范围 | B 加拖动 |
| 硬度 | 控制中心至边缘的权重衰减 | V 加拖动 |
| 形状 | 圆形、正方形、线形 | 本方案不指定快捷键 |
| 角度 | 调整正方形和线形的方向 | C 加拖动 |
| 权重颜色 | 显示影响强弱或选择状态 | 面板设置 |

参数与快捷操作依据 [工具详细面板](https://docs.live2d.com/en/cubism-editor-manual/detailed-toolpalatte/)。
各类变形笔刷分别记忆设置，见 [笔刷调整](https://docs.live2d.com/zh-CHS/cubism-editor-manual/deform-brush/#)。

建议首次交付包含三种笔刷形状与以上参数。数值范围、初始值、调节灵敏度、
跨应用重启的设置保存方式，以及笔刷选择与其他工具是否共享部分设置，仍需确定。

## 3 对象选择与作用范围建议

先选对象，再使用笔刷。笔刷只影响已选中且可编辑的 Mesh 或 Warp，允许多对象编辑；
经过未选中对象时不改变它，也不自动切换选择。没有有效对象时提示先选择 Mesh 或 Warp。

选中 Warp 时修改其分割点，子对象通过变形器自然跟随。笔刷不直接修改子对象数据，
除非最终确定的多选规则明确把子对象列为编辑目标。

父 Warp 与子 Mesh 或子 Warp 同时被选中时，直接同时写入可能造成双重变形。
建议只编辑选中层级中最上层的对象，并显示实际作用对象；这一规则尚待用户确认，
也需要核对 Cubism 的处理方式。

以下范围细节仍需确定：

- 已有顶点选择是否进一步限制直接变形笔刷的作用范围。
- 隐藏、锁定、隔离范围外以及部分不可编辑对象混选时，是跳过还是拒绝整笔。
- 对象重叠时，是否影响所有选中对象中落入笔刷范围的点。
- 笔刷选择形成的权重是否也约束后续直接变形笔刷。

## 4 四种工具的交互建议

### 4.1 变形笔刷

按下并拖动时，局部形状跟随笔刷运动；停住时不继续变形。权重控制移动程度，
硬度控制影响由中心向边缘的变化。

落笔时固定受影响顶点，还是随笔刷移动更新受影响顶点，会直接改变推拉手感。
在对照 Cubism 前不选定其中一种实现。重复经过同一区域的累积规则也一并核对。

### 4.2 扩展与收缩笔刷

按住左键持续扩展，Shift 加按住持续收缩，移动时作用区域跟随笔刷。
扩展速度应按实际经过的时间计算，避免相同按住时长因刷新率不同而产生明显不同的结果。

需要核对落笔后按下或松开 Shift 是否立即切换方向，以及圆形、正方形、线形的扩展方向。
收缩靠近中心、极高强度和长时间按住时的稳定性需要单独验收；防折叠或位移限制规则待定。

### 4.3 Warp 整形笔刷

在涂刷区域内，将 Warp 分割点逐步整理到贝塞尔手柄所定义的平滑形状，
权重控制每次整理的程度。仅选中 Mesh 时，工具不可用并显示原因。

整形是否在静止按住时持续生效、是否保持贝塞尔手柄不变，以及已有自动整形策略如何参与，
需要对照 Cubism 并检查 Zipzi 的 Warp 编辑语义后确定。

### 4.4 笔刷选择

笔刷选择先建立软选择权重，不立即改变几何。切换到选择工具后，
对选中区域进行按权重的移动、旋转和缩放。

建议提供增加权重、擦除权重和清空权重。具体擦除修饰键、重复涂刷的累积方式、
权重上限以及旋转和缩放中心的计算规则，应对照 Cubism 确定。

建议将权重作为临时编辑状态：切换到选择工具及完成一次变换后仍保留，
便于连续调整；明确清空或切换编辑对象时才移除。权重是否保存进工程、
是否参与撤销，以及切换关键形状时是否保留，尚待确定。

## 5 面板与画布反馈建议

### 5.1 Zipzi 面板

提供笔刷设置区域，上方切换功能，下方显示对应参数。参数采用 Zipzi 现有控件和布局，
避免额外建立一套与属性面板不一致的交互方式。

圆形不需要角度设置；方形和线形显示角度。没有可用 Warp 时，整形入口显示不可用原因。
工具入口是在工具栏分为笔刷选择与变形笔刷两项，还是使用一个入口切换四种功能，待确定。

### 5.2 画布反馈

直接变形类工具显示笔刷轮廓，并预览当前位置的影响范围与强弱。
笔刷选择持续显示已涂好的权重，即使鼠标移开或切换到选择工具，也能判断后续变换的作用范围。

权重显示需要区分当前笔刷预览与已保存的临时选择，避免用户把两者混淆。
颜色设置、几何遮挡与选择标记之间的显示优先级需在界面验收中检查。

笔刷大小采用屏幕单位还是模型单位、缩放画布时笔刷是否同步缩放、
线形笔刷的长度与宽度含义，先作为 Cubism 对照项，不预设行为。

### 5.3 输入设备

鼠标是基础输入。数位板压感是否纳入首次交付尚未确认；如需要，
应明确压感控制权重、大小或可配置的组合，并确认无压感设备的等效默认行为。

## 6 编辑生命周期建议

- 从按下到松开作为一笔，几何变化合并成一次撤销；没有变化时不产生空历史。
- Esc 取消当前笔触，并恢复落笔前的状态。
- 快速拖动保持连续作用，扩展速度不依赖帧率；具体采样策略以手感验证结果为准。
- 沿用现有形状写入规则，编辑基础形状或当前可编辑关键形状，不由笔刷静默创建关键点。
- 不可编辑时在落笔前说明原因，避免完成动作后才发现没有写入。
- 失去窗口焦点、指针捕获中断、切换工具或文档时，按统一手势生命周期结束或取消，
  具体策略在实现前与现有交互契约对齐。

笔刷选择涂权重的撤销不应未经讨论就与几何撤销混为一体。
需要明确临时选择历史和模型历史之间的关系，尤其是撤销变换后应恢复哪些权重状态。

## 7 项目接入方向

当前 [ToolController](../../crates/zipzi-editor-core/src/tools.rs) 的工具类型包含
Select、Lasso、Glue 和 Hand，尚未包含笔刷工具。
Editor 已有 Mesh 与 Warp 编辑基础，可以在现有编辑和预览流程上扩展。

建议遵循现有职责边界：

| 层次 | 接入方向 |
| --- | --- |
| Editor UI | 工具入口、参数控件、快捷键、输入设备数据与画布反馈 |
| Editor Core | 工具状态、作用对象解析、手势生命周期、临时权重与预览协调 |
| SDK 与 Core | 可复用的形状操作、坐标转换及模型有效性检查 |
| Runtime | 沿用现有正式写入与历史所有权，不另建笔刷历史后端 |

此处仅确定职责方向，不指定新 API 或文件拆分。
实施前应核对 [Editor Core 说明](../../crates/zipzi-editor-core/README.md)、
[Editor 开发说明](../../crates/zipzi-editor/README.md) 与实际形状编辑接口。
本次范围不自动扩展为新增 Python SDK 笔刷接口。

## 9 Cubism 对照与验收草案

### 9.1 实机对照

固定并记录 Cubism 版本，在同一简单 Mesh 与 Warp 上观察以下行为：

1. 推拉笔触是固定抓取还是随移动更新范围，重复涂刷如何累积。
2. 扩展与整形在静止按住时的行为，Shift 在笔触中途切换的效果。
3. 大小与画布缩放关系，三种形状的范围、方向和角度调整。
4. 软选择增减、清空、变换中心以及切换工具后的权重保留。
5. 多选、父子同选、已有顶点选择、隐藏与锁定对象的处理。
6. 参数默认值、调整灵敏度和压感行为。

手册说明功能语义，但没有提供精确衰减曲线、采样规则或膨胀速度。
这些参数应通过操作对照确定，不能声称已逐点复现 Cubism 算法。

### 9.2 功能验收

| 场景 | 建议检查内容 |
| --- | --- |
| Mesh 与 Warp | 变形、扩展与收缩、软选择及其三种变换均可用 |
| Warp 整形 | 整理结果符合手柄定义的参考形状，Mesh 不误进入整形 |
| 父级变形 | 在旋转、缩放及嵌套 Warp 下，光标范围与实际受影响区域一致 |
| 参数编辑 | 写入正确的基础或关键形状，不改变无关形状 |
| 历史与取消 | 一笔一次撤销，重做恢复结果，Esc 不留下部分几何修改 |
| 采样与耗时 | 快慢拖动和不同刷新率不产生断笔或明显速度差异 |
| UI 与快捷键 | 参数、轮廓与反馈一致，快捷调节不误触发几何编辑 |
| 权重生命周期 | 按最终确认的保留、清空及撤销规则执行 |
| 大型选区 | 交互过程中保持可用；选定代表模型与硬件后再制定性能门槛 |

实现后从受影响模块的 Editor Core 测试和 UI 逻辑测试开始，
再用原生 Editor 检查连续输入、画布反馈与实际手感。
本阶段只交付讨论稿，不把以上验收项记为已实现或已通过。
