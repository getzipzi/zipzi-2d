# Panel 工具栏组件设计

状态：首期已实现。Parameters、Mesh Tree 和 Deformer Tree 已接入公共组件。

本方案统一 Parameters 与层级树面板顶部的工具栏。基于 GPUI Kit 已有的 `Toolbar` 和 `ToolbarGroup`，提供可组合的 `PanelToolbar`、搜索控件和弹出控件，统一尺寸、排列、状态反馈与键盘操作。各面板继续负责业务状态、命令可用性和回调。

## 接入范围

| 面板 | 接入前的顶部控件 | 公共工具栏的接入方式 |
| --- | --- | --- |
| Mesh Tree | 搜索、对象类型筛选、清除条件 | 筛选在前，搜索在末尾；保留现有筛选规则 |
| Deformer Tree | 搜索、对象类型筛选、清除条件 | 与 Mesh Tree 共用工具栏，类型选项由面板提供 |
| Parameters | 新增参数按钮、独立的分组展开入口 | 新增与分组开关进入同一工具栏 |

Parameters 的分组列表、关键形标记说明和绑定详情继续显示在工具栏下方。它目前没有参数搜索与筛选，本次接入不新增这些业务能力。画布浮动工具栏继续使用现有实现；其注册表依赖 `CanvasView`，不作为 Panel 工具栏的基础。

## 布局与视觉

工具栏位于面板标题下方，列表或面板内容上方，固定一行。默认顺序为操作、筛选或视图开关、搜索；没有搜索时，末尾留出弹性空白。未配置的区域不生成空组、分隔线或占位控件。

接入面板应将 `Panel::inner_padding` 设为 `false`，由公共工具栏管理标题下的间距。Dock 默认会给多标签组内容增加 8 px 顶部内边距；关闭这层内边距后，单标签和多标签面板的工具栏位置一致。

```text
Mesh Tree
┌─────────────────────────────────────────┐
│ [类型 ▾] [⌕ 搜索名称或 ID             ×] │
├─────────────────────────────────────────┤
│ 树列表                                  │
└─────────────────────────────────────────┘

Parameters
┌─────────────────────────────────────────┐
│ [＋] [分组图标]                         │
├─────────────────────────────────────────┤
│ 分组列表（展开时）                       │
│ 关键形标记说明与绑定详情                 │
│ 参数列表                                │
└─────────────────────────────────────────┘
```

| 项目 | 首期规范 |
| --- | --- |
| 容器高度 | 工具栏主体 32 px，另加底部分隔线 1 px；沿用 Kit Toolbar 的 Small 尺寸 |
| 控件高度 | 24 px，沿用 Kit Small 控件；将树面板现有 26 px 高度统一到此规格 |
| 内边距与间距 | 各 4 px；控件垂直居中，容器不参与列表滚动 |
| 按钮 | 默认 ghost；参数面板的新增与分组按钮始终为单图标，视图开关使用 selected 状态 |
| 搜索 | Search 前缀图标，`flex_1` 与 `min_w_0`，提示文字随可用宽度裁切 |
| 筛选反馈 | 有类型限制时触发器高亮；徽标含义由面板明确提供 |
| 背景与边界 | 沿用面板背景，底部一条主题 border 分隔线 |
| 颜色与文案 | 使用现有主题及国际化，不硬编码业务文案或颜色 |

控件保持单行，操作按钮不被挤压。现有 Dock 的最小面板宽度为 100 px；小于 260 px 时，操作按钮工厂收到紧凑布局标记，可省略可选文案并保留 tooltip 与可访问名称。参数面板在所有宽度下都只显示 Plus 与 FolderTree 图标，新增文案和分组数量通过 tooltip 与可访问名称提供。搜索继续伸缩，类型筛选徽标继续可见。首期没有自动溢出菜单。

## 组件职责与 API

代码位于 [公共工具栏组件](../crates/editor/src/panels/toolbar.rs)，由 `panels/mod.rs` 内部导出，供各面板使用。组件采用 `RenderOnce`，不持有 `EditorView`、文档或面板实体。

| 组件 | 负责的内容 | 调用方提供的内容 |
| --- | --- | --- |
| `PanelToolbar` | 基于 Kit Toolbar 的排列、尺寸、分隔线、语义分组和窄版布局 | 稳定 ID、操作按钮、控件、可选搜索 |
| `PanelToolbarSearch` | 搜索图标、输入框布局、可选清除按钮及其可访问名称 | 已存在的 `Entity<InputState>`、输入 ID、提示文字、清除 ID 与回调 |
| `PanelToolbarPopover` | 一致的触发按钮、选中态、可选徽标、Popover 外壳 | ID、图标、名称、禁用态、受控 open 状态、开关回调与弹出内容 |

普通操作和视图开关复用 Kit `Button`，通过 `.action(build)` 接入，`build` 是接收 `compact: bool` 并返回 Button 的闭包；按钮的图标、文案、selected、disabled 和点击回调由调用方定义。`.control(...)` 接收弹出控件或其他自定义控件；`.search(...)` 最多接受一个搜索控件，始终排在最后。组件内部用有名称的 `ToolbarGroup` 表达操作组与视图组。

以下示意组件组合；具体按钮工厂和事件回调由面板构造：

```rust
// Parameters
PanelToolbar::new("parameters-panel-toolbar")
    .action(build_new_parameter_button) // FnOnce(bool) -> Button，保留 ID new-parameter
    .action(build_groups_toggle_button) // 保留 ID parameter-groups-toggle

// Mesh Tree / Deformer Tree
PanelToolbar::new(toolbar_id)
    .control(type_filter_popover)
    .search(
        PanelToolbarSearch::new(&self.search)
            .id(search_id)
            .label(search_label)
            .reset_action(clear_id, clear_label, conditions_active, on_reset),
    )
```

`.reset_action(...)` 显式定义清除按钮的可见条件、语义和回调。它不推断“清除”是否包含筛选，也不直接调用 `InputState::set_value`。因此纯搜索面板可提供“清除搜索”，树面板可继续提供“清除搜索和筛选”。

搜索提示文字由调用方在 InputState 中设置，`.label(...)` 设置可访问名称。`.disabled(...)` 同时控制搜索输入与清除按钮。`PanelToolbarPopover::new(id, trigger)` 接受调用方构造的 Button，统一为 Small compact ghost 样式；`.open(...)`、`.on_open_change(...)` 和 `.content(...)` 转发给 Kit Popover。

Kit 的 `.child(...)` 会向 `Sizable` 控件传递尺寸，并使 Button 采用工具栏样式；`.content(...)` 用于弹性空间及自定义布局，不会传递尺寸。封装需分别处理这两种路径，搜索输入和 Popover 触发器明确使用一致尺寸，避免所有内容转成 `AnyElement` 后丢失尺寸规则。

## 状态与交互规则

搜索输入实体、筛选条件、弹窗开关以及分组展开状态均由面板持有。公共组件只读取状态并转发事件，不新增镜像状态；每次 render 也不重建输入实体。

公共组件仅保存按稳定 ID 关联的紧凑布局标记。测量到宽度跨过 260 px 时，延迟通知所属视图重绘；普通宽度变化不额外通知。初次渲染采用紧凑布局，宽面板测量后展开文案。

树面板继续按文档、按面板分别保存搜索与类型条件。切换文档关闭筛选弹窗，恢复对应输入和条件；弹窗内回调继续校验捕获的 `DocumentId`，避免旧弹窗修改新文档。搜索与筛选不改变对象选择、折叠状态和参数焦点。

树面板保留以下已存在的行为：

- 搜索框尾部的清除按钮在任一条件生效时出现，点击后同时清除搜索与类型限制。
- 类型筛选徽标表示当前纳入的类型数，不能改成已排除类型数或结果对象数。工具栏已补充 tooltip 与可访问名称，明确写出“显示 N 种对象类型”。
- 弹窗内的“全部类型”只重置类型，保留搜索。
- 类型选项支持连续多选，选择后弹窗保持打开。

Parameters 的分组按钮使用 selected 表示列表展开，tooltip 与可访问名称说明展开或收起操作及文档中现有分组数；点击仍切换原有列表，组内点击仍执行导航。新增参数继续打开现有创建弹窗，并保留创建成功后的定位与聚焦。

禁用态逐控件设置。新增操作继续服从文档、忙碌、模态和命令可用性规则；本地搜索、筛选或分组展示按其自身规则判断。Kit `Toolbar::disabled` 仅关闭方向键导航，不会禁用子控件，不能用它替代按钮和输入的禁用逻辑。

## 键盘与可访问性

使用 Kit Toolbar 已有的 Toolbar 角色与左右键焦点移动，不另写面板级方向键处理。搜索框放末尾，输入时左右键仍用于移动光标；Tab 按已渲染控件顺序进入和离开工具栏。Popover 的焦点与 Esc 关闭沿用 Kit 行为：关闭后恢复打开前的焦点，键盘从触发器打开则返回触发器，鼠标从搜索框打开则返回搜索框。

图标按钮必须提供 tooltip 与可访问名称。分组开关应表达展开或收起；筛选触发器应表达筛选名称与活动条件。所有控件使用稳定 ID；保留 `new-parameter`、`parameter-groups-toggle`、`mesh-tree-*` 和 `deformer-tree-*` 的现有测试入口，工具栏根节点另设互不冲突的 ID。

## 实施顺序与验收

先落地公共容器、搜索与 Popover 外壳，再接入两种树面板，最后接入 Parameters 的新增与分组按钮。树的类型选项内容、过滤计算、每文档状态以及参数的创建命令、列表缓存继续留在原有模块。

实施时应验证以下场景：

1. 三个面板采用同一高度、间距和按钮样式；100、220、260、310 和 360 px 宽度下现有两种控件组合可操作，无横向溢出。
2. 无搜索或操作时不留下空占位；空参数列表仍显示创建入口，文档不可编辑时正确禁用。
3. 树搜索、类型限制、清除全部条件、仅重置类型及弹窗多选保留现有语义。
4. 两个树面板的条件相互独立，切换文档后恢复；旧弹窗回调不修改新文档。
5. 分组开关只有一个入口，展开内容不进入工具栏；新增弹窗与创建定位保持原有行为。
6. Tab、左右键、输入光标、Esc 和弹窗返回焦点工作正常，禁用控件不被激活。
7. 既有 hierarchy 与 parameter 创建 headless 回归通过；新增验证聚焦组件组合、事件转发和尺寸，不重复测试底层 Kit 实现。

新增 [工具栏 headless 回归](../crates/editor/headless_tests/panel_toolbar.rs) 覆盖宽度变化、输入与焦点保持、清除回调、弹窗焦点恢复、工具栏键盘导航、禁用按钮以及参数分组入口。布局已经过 headless 测量，单图标按钮和标题间距已通过真实 Metal 无头截图确认；原生窗口视觉尚未检查。
