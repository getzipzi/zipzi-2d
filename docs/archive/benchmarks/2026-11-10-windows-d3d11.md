# Windows 原生 D3D11 验证记录

Windows 默认模型预览和 SDK GPU observation 切到原生 D3D11。Editor 后台在 GPUI 的设备上记录命令列表，UI 提交后通过现有共享 surface 合成。SDK 捕获使用独立 D3D11 设备。`wgpu-backend` 保留为构建时的对照选项。

## 同二进制窗口对照

Windows、RTX 5060，同一 Release 二进制，交替选择 wgpu/DX12 和原生 D3D11。Mao 原模型每侧四次，每次 360 个测量输入。嵌套离屏变体每侧两次，每次 240 个输入。两组使用相同的 Angle_X 拖动、选择和 1061 × 1478 物理像素视口。每次核对参数变化、受影响网格和历史状态，编译与测量分开。

| 指标，wgpu/DX12 → D3D11 | Mao | 嵌套离屏 |
|---|---:|---:|
| 进程专用显存采样峰值中位数，MiB | 621.69 → 267.38 | 621.71 → 276.18 |
| 后台 CPU 记录或提交 P95，ms | 5.17 → 2.38 | 5.56 → 2.52 |
| 输入到平台绘制返回 P95，ms | 30.50 → 27.92 | 30.80 → 28.04 |
| UI 绘制 P95，ms | 9.14 → 9.42 | 9.22 → 9.72 |
| 新预览更新间隔 P95，ms | 34.29 → 34.82 | 34.01 → 35.05 |
| 关联到新预览的输入 / 总输入 | 1319/1440 → 1333/1440 | 438/480 → 444/480 |

P95 取各进程 P95 的中位数。显存来自每秒采样的进程专用显存计数。延迟的起点是应用注入输入，终点是 CPU 平台绘制返回，排除 OS 输入投递、DWM 和屏幕扫描。后台计时覆盖各后端的记录或提交工作，D3D11 的 UI 提交另行计时。二进制 SHA-256 为 `3d70ca303fb9f54c6f00aec65e2cfa4ad477d1416591e7594255cf1c7476025b`。

同一次迁移还优化了命令记录。单独的 Release 记录探针预先求值 120 个姿态，预热 30 帧，测量 240 帧。Mao 的 CPU 记录 P95 从 1.12 ms 降到 0.72 ms。原生方案的主要收益是显存和后台 CPU 开销，窗口刷新节奏的优化另行对照。

## 正确性与复核

- 合成夹具覆盖所有 raw blend 模式、嵌套离屏和遮罩。GPU 测试还覆盖命令列表丢弃、换序、拓扑修改和 renderer 释放后的执行。
- Mao 原模型和嵌套离屏变体分别对照默认姿态、Angle_X 两端。像素比较报告的平均通道差均为零。保留帧不被后续预览覆盖的共享纹理测试通过。
- 本机复跑 2 项 D3D11 parity、11 项 SDK GPU capture，以及 6 项运行时依赖矩阵检查。Windows Editor、Runtime 和 Python 的默认依赖检查确认选用 D3D11。Python Local 和 Connected observation 验证通过。
- 共享 render 和 wgpu 回归串行复跑 55 项通过。一次默认并行 wgpu GPU smoke 运行在本机停滞，成因未定位。硬件测量覆盖 RTX 5060。

当前命令见 [D3D11 renderer](../../../crates/zipzi-render-d3d11/README.md) 和 [Editor render](../../../crates/zipzi-editor-render/README.md)。本机原始 trace、采样和每轮汇总位于 `target/d3d11-native-acceptance/` 与 `target/d3d11-performance/`。
