# 全选后的重复画布工作与菜单开销 — 2026-10-26

> **呈现指标更正：** 后续复核发现，旧版报告按 Metal 纹理地址关联模型帧，会把复用该地址的辅助层纹理误认成旧模型帧。因此下文涉及模型帧率及其关联延迟的结论已撤回，保留原始数据供审计；独立 CPU 分段、工作次数和全部窗口绘制时间仍有效。修正与复测见[更正报告](2026-10-26-selected-ui-release-recheck.md)。

已定位并优化两处 CPU 开销。原生开发构建全选显示顶点时，三轮新预览呈现频率中位数从 **41.94 Hz 提升至 51.60 Hz（+23.0%）**，全部窗口绘制的 UI draw P95 从 **10.109 ms 降至 7.477 ms（−26.0%）**，输入到呈现 P95 从 58.312 ms 降至 51.208 ms。

详细进程验证了工作量减少：360 次输入期间，画布构建和 paint 从 680 次降至 350 次；原生菜单刷新 P95 从 2.40 ms 降至 0.26 ms。GPU 辅助层提交次数约保持不变，因为原有纹理缓存已经避免了旧画布的重复 GPU 提交。

Release 默认组的新预览频率中位数为 107.54 → 102.34 Hz（−4.8%），UI draw 和端到端延迟略降，**不能据此宣称 Release 整体性能提升**。开发组的改善三轮一致；Release 仍有明显的呈现节奏波动。补充复核与完整数据见下文和 JSON。

## 具体函数和改动

### 1. 菜单在每次根视图渲染时重新遍历全选对象

系统调用栈和独立 UI 分段计时定位到：

```text
EditorView::render
  → EditorView::refresh_menus
  → Editor::authoring_command_capability
  → Document::validate_scene_object_creation_in
  → scene_creation_container / deformation_creation_container
  → SDK 对象身份、归属和集合能力检查
```

全选 150 个 Mesh 后，创建菜单反复计算相同的结构条件。优化前独立详细进程中，菜单刷新累计约 791 ms，而参数列表、参数行和属性面板自身的构建很轻。

新增 `SceneCreationMenuCache`，按活动文档、`properties_revision`、候选编辑状态和完整选区复用场景创建能力查询结果。参数姿态变化不改变这些结构条件。选区、锁定、历史、候选编辑和文档变化均使缓存失效；最终创建操作仍执行原有校验。预览、播放、焦点、文本输入、模态状态和命令目标继续读取当前状态；缓存保留带类型的错误，在显示时本地化原因。

### 2. 参数输入先刷新旧画布，预览返回后再刷新新画布

原链路是：

```text
ParametersPanel::apply_values
  → EditorView::complete_preview_edit
  → redraw_canvas_for_input
  → notify_canvas（旧纹理、旧画布）

预览线程返回
  → EditorView::receive_viewport_frame
  → notify_viewport（新纹理、新画布）
```

`complete_preview_edit` 现在检查 `request_preview_for_input` 的入队结果。成功提交新模型预览后，保留当前画布，等 `receive_viewport_frame` 接收有效结果后再通知对应视口。参数行、状态栏和相关文档面板仍更新；焦点变化、无新请求、求值错误和工作线程不可用时立即刷新。

导航、缩放、框选和直接画布操作仍使用立即刷新的路径。没有加入延迟、降低输入频率或改变 Metal 绘制方式。

## 同一模型的原生配对测试

沿用上一轮 CPU 优化后的二进制作本轮 before，保存本轮 after 的开发版和 Release。两侧均启用 `test-support,bench-instrumentation`，正式采样关闭详细计时；构建完成后才开始采样。before SHA-256 与上一轮 after 一致，记录在机器可读报告中。

模型仍为相同的 `mao_pro.zipzi` 磁盘副本：260 个 Mesh，150 个可见且未锁定的 Mesh 被选中，5,159 个顶点、12,202 条边、2,825 条边界线。拖动 Angle_X，每进程 30 次预热和 360 次正式输入，目标 120 Hz，实际输入间隔保存在 JSON；确认每个进程实际改变 93 个 Mesh，预览为 941×1312 物理像素。

环境为 Apple M4、16 GiB、macOS 27.0.1、CB27U1 3840×2160／逻辑 1920×1080／120 Hz。每进程独立配置和私有 Runtime endpoint；偶数轮反转构建、场景和版本顺序。

下表为三个进程各自指标的中位数，不合并原始样本。UI draw 包含测量区间内所有窗口绘制；Hz 使用新模型纹理的实际呈现时间戳。时间单位 ms。

| 构建与状态 | 新预览 Hz：前 → 后 | 全部 UI draw P95：前 → 后 | 输入到呈现 P95：前 → 后 |
| --- | ---: | ---: | ---: |
| 开发，未选中 | 62.14 → 68.57 | 4.510 → 4.541 | 48.174 → 47.240 |
| 开发，全选显示 | **41.94 → 51.60** | **10.109 → 7.477** | **58.312 → 51.208** |
| 开发，全选但跳过绘制 | 48.39 → 54.55 | 8.295 → 7.155 | 49.720 → 48.688 |
| Release，未选中 | 118.33 → 117.67 | 4.819 → 4.743 | 34.087 → 40.734 |
| Release，全选显示 | 107.54 → 102.34 | 6.138 → 6.050 | 46.885 → 46.792 |
| Release，全选但跳过绘制 | 100.16 → 106.56 | 5.385 → 5.103 | 48.417 → 46.292 |

开发全选逐轮 Hz 为 42.32 → 51.60、41.94 → 51.86、41.57 → 49.64。Release 全选为 96.00 → 101.26、111.15 → 103.83、107.54 → 102.34；后两轮下降保留，不能用某个改善进程替代整组结果。

报告工具中按新预览请求关联的 `ui_draw_ms` 与“全部窗口绘制”口径不同：开发全选该 P95 为 10.742 → 9.846 ms，Release 为 6.171 → 6.052 ms；两种口径均保存。窗口合成频率也不等于新预览频率：开发全选窗口约 80.80 → 101.99 Hz，新预览约 41.94 → 51.60 Hz。窗口仍会为参数控件和预览分别更新，但旧画布的构建和 paint 已被消除。

本轮开发未选中基线低于前一报告，不能跨批次拼接结果或宣称累计收益；结论只使用本轮相邻配对。所有请求终态，包括拒绝、未合成和未发出新请求，均保留在 JSON。

默认组出现下降后，补充相对上一呈现时间戳的 0／2,500／5,000 μs 输入起始相位，各两轮，第二轮反转相位和版本顺序。这里只对齐起始时刻，后续调度没有持续锁相。这 12 个有效进程不替代主组三轮结果。

| 起始相位 / μs | 优化前新预览 Hz（两轮） | 优化后新预览 Hz（两轮） |
| --- | --- | --- |
| 0 | 89.92／116.32 | 112.17／102.86 |

## 独立详细进程：CPU 工作次数与函数耗时

下表来自一对开发版详细进程，360 次输入，未检测到编译器干扰。详细计时与正式三轮结果分开，不相加嵌套阶段的 P95。

| 工作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| `refresh_menus` P95 / ms | 2.40 | 0.26 |
| `EditorView::render` P95 / ms | 2.63 | 0.51 |
| 菜单刷新累计 / ms | 791.2 | 80.7 |
| `ViewportSurface::render` 次数 | 680 | 350 |
| 完整 overlay 构建次数 | 680 | 350 |
| overlay 构建累计 / ms | 824.7 | 425.7 |
| overlay paint 次数 | 680 | 350 |
| overlay paint 累计 / ms | 1,059.3 | 599.7 |
| GPU 辅助线 pass 提交次数 | 355 | 350 |
| GPU 顶点 pass 提交次数 | 355 | 350 |

每次保留下来的画布构建仍约 1.4 ms；减少的是重复执行次数。每张新预览仍需生成顶点/边快照，`canvas_overlay::paint_lines` 的 GPUI 边界线和控制线 P95 约 1.07 ms，`MetalOverlayRenderer::draw_pass` 仍需整理绘制键和必要的 GPU 提交。GPU 尾部也仍有波动，本轮没有优化这些单次工作。

## 正确性和完整性

69 项定向测试通过：UI 工作量回归 10 项、原生创建命令 12 项、变形创建 7 项、画布交互 40 项。一个原有的手动画布 CPU benchmark 保持忽略，没有运行完整 SDK/Editor 套件。

新增回归同时断言减少工作和实际状态正确：

- 三次参数变化不通知旧画布，各自的新帧到达后只通知一次，并验证参数值、请求版本和已呈现版本；工作线程不可用时仍通知并显示错误。
- 姿态预览不重算场景创建能力；选区、锁定、撤销、候选编辑、取消和切换文档均使缓存失效，禁用原因保持正确。
- 现有测试继续覆盖模态状态、快捷键和文本输入、菜单过期目标、锁定/撤销，以及滑条、框选、悬停、缩放和导航。

后台另一个 worktree 的短暂 Cargo/Xcode 编译多次出现。受影响的进程保留在 `excluded-*` 目录；正式配对中任一侧受影响时重测整对。有效主组 36 个进程共 12,960 次正式输入，未检测到编译器干扰，结束标记完整且丢失事件为 0。Release 报告 issues 为空；开发版只保留预期的 debug 构建提示。

原始目录为 `target/selected-ui-optimization-20261026/`，包含冻结二进制、源码哈希、修改前后 diff、构建/测试日志、系统调用栈采样、独立 UI 分段 trace、每进程配置/审计/后台快照，以及可恢复的 `run_pairs.py`。帧率结论使用独立正式进程，系统 `sample` 采样只用于定位函数。

另有 4 个详细进程和上述 12 个相位进程，共 52 个有效进程、18,720 次正式输入；全部通过结束标记、呈现、模型变形和丢失事件检查。早期 `ui-before-detail_unselected` 探索捕获标记有编译干扰，只用于初步定位，不参与表格或帧率结论。开发版详细 before 另存了只增加 UI 分段观察的二进制，其哈希与正式 before 分别记录；Release before 沿用原有 overlay 分段，不包含新增的 `ui.*` 分段。
