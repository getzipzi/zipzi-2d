# Mao 实际窗口采样（2026-09-28）

连续两轮 Release 采样，每轮各负载预热 30 次、正式输入 300 次，目标输入频率 120 Hz。两轮追踪丢失数均为 0，报告完整性检查通过。

环境：Apple M4（10 核 GPU）、16 GB、macOS 27.0；主屏配置 120 Hz，另接 60 Hz 副屏。默认 1100×740 逻辑窗口，实测模型输出纹理 1284×1364 像素。Metal HUD 关闭。窗口显示间隔中位数为约 8.33 ms。

下表按两轮原始样本合并后重新计算 nearest-rank 分位数，没有平均各轮的分位数；只对有系统显示时间的请求计算延迟，分母与未显示结果另列。

| 操作 | 正式输入 | 显示成功 | 输入到显示 P50 | P95 | P99 | 最大值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 平移 | 600 | 600 | 48.07 ms | 56.52 ms | 56.73 ms | 62.36 ms |
| 缩放 | 600 | 600 | 48.15 ms | 56.30 ms | 56.67 ms | 56.80 ms |
| 透明度 | 600 | 575 | 48.10 ms | 56.36 ms | 56.69 ms | 63.35 ms |

透明度：第一轮 18 个过期请求被拒绝；第二轮 5 个被拒绝、2 个已经提交但系统报告未显示（原始事件包含 `present_dropped`）。平移与缩放的正式请求全部关联到显示。

## 各轮与阶段观测

| 轮次 / 操作 | 实际输入 Hz | 输入到提交 P95 | 输入到显示 P95 | 输入到显示 P99 |
| --- | ---: | ---: | ---: | ---: |
| 1 / 平移 | 101.66 | 24.81 ms | 56.56 ms | 61.74 ms |
| 1 / 缩放 | 102.80 | 24.33 ms | 56.35 ms | 56.67 ms |
| 1 / 透明度 | 102.51 | 20.56 ms | 56.34 ms | 56.69 ms |
| 2 / 平移 | 95.93 | 24.65 ms | 56.50 ms | 56.62 ms |
| 2 / 缩放 | 106.16 | 19.85 ms | 56.29 ms | 56.57 ms |
| 2 / 透明度 | 106.79 | 24.57 ms | 56.38 ms | 56.70 ms |

- 场景准备 P95：平移/缩放约 0.002 ms，透明度约 0.60–0.62 ms。
- 预览 GPU 区间 P95：约 0.77–1.81 ms；GPUI CPU 布局/绘制 P95：约 1.80–2.13 ms。
- 结果交付到 UI 的等待 P95：约 7.85–15.85 ms；获取 drawable 的阶段 P95：约 10.96–13.81 ms。
- GPUI 合成命令的 GPU 时间区间 P95：约 7.91–8.76 ms。这个区间不等同于硬件活跃计算时间，仍需进一步区分 GPU 工作与资源/显示依赖等待。
- 新预览显示间隔 P95 约 16.67 ms，透明度最大间隔两轮分别为 41.67 / 33.33 ms。目标 120 Hz 输入实际只达到约 96–107 Hz；不能据此宣称持续 120 Hz 负载下稳定 120 fps。

以上是不同阶段分别统计的分位数，不能相加成端到端分位数。当前证据更支持优先排查 GPUI 合成、drawable 获取、共享队列和 UI 交付调度；尚不足以把约 48 ms 延迟归因于某个单一组件，也不支持先通过增加 CPU 渲染线程解决。
