# Windows 视口预览交付实验

选用在构建视口图像与 overlay 前，非阻塞取用后台已完成的预览。成功取用的帧仍经过同一套绑定和版本校验，后台结果晚到时由原异步回调接收。

## 回调交付与绘制前取用

Windows、RTX 5060、Mao 的同一 158 顶点 Mesh，1061 × 1478 物理像素。使用同一 Release 二进制、D3D11 和 `ZIPZI_PREVIEW_LATCH=0/1` 交替运行。普通大幅拖动每侧两次，密集拖动每侧四次。每次每种选择热身 30 个输入，测量 720 个输入。密集模式每次唤醒注入四个事件。每轮验证求值、提交、当前画布和 Undo，测量不与编译重叠。

| 拖动 | 选择 | 输入到预览提交 P95，ms | 更新间隔 P95，ms | 插值位置差 P95，逻辑 px | UI 绘制 P95，ms |
|---|---|---:|---:|---:|---:|
| 大幅 | 单点 | 25.34 → 16.92 | 17.98 → 18.33 | 55.38 → 42.23 | 6.68 → 7.14 |
| 大幅 | 八点 | 25.34 → 17.05 | 17.97 → 18.79 | 52.69 → 42.53 | 6.77 → 7.30 |
| 密集大幅 | 单点 | 19.46 → 12.06 | 36.88 → 31.73 | 56.53 → 26.65 | 7.38 → 7.31 |
| 密集大幅 | 八点 | 14.99 → 11.92 | 31.80 → 30.86 | 32.72 → 27.40 | 6.99 → 6.79 |

P95 为每轮 P95 的中位数。位置差在有帧关联的 CPU 提交时按轨迹插值估计。绘制时间包括当前帧采纳结果的开销。密集八点仍有约 31 ms 的间隔长尾。比较用二进制 SHA-256 为 `f8d690b5442a0406424df2356f8ba401f6bb6531711152eb370e4094aaca4487`。

## 淘汰的 UI 记录方案

- 每个移动事件在 UI 线程记录 D3D11 命令，普通大幅拖动的提交延迟约 24 → 17 ms，输入 CPU 约 3 → 4.5 ms。密集拖动的新预览频率约 59 → 44–47 Hz。
- 视口每帧只在 UI 线程记录最新请求。12 轮对照中，普通大幅拖动的提交延迟约 25.5 → 17.0 ms，UI 绘制约多 1.2 ms。密集八点的新预览频率 55.75 → 50.57 Hz，提交延迟 P95 12.34 → 14.48 ms。

这些方案的代码已淘汰。原始记录保留在本机 `target/mesh-follow-pointer/`，其中 `ready-frame/` 是已采用的后台结果取用对照，父目录的 `comparison.json` 是每帧 UI 记录方案。
