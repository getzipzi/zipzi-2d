# Mesh 拖动求值和提交开销

Windows、RTX 5060、原生 D3D11，Mao 的同一 158 顶点 Mesh，1061 × 1478 物理像素视口。两项优化分别对照，表中延迟止于 CPU 平台绘制返回或应用层当前画布检查。

## 复用已验证的 keyform 候选

位置和外观更新仍检查坐标及 payload。已有验证通过且采样键与绘制顺序保持一致时，复用候选的验证结果。依赖或绘制顺序变化后重新执行完整校验。

8 个交替 Release 进程。每次每种选择热身 30 个输入，测量 240 个输入。表格取每个进程 P95 的中位数。

| 选择 | 同步输入 CPU P95，ms | 输入到预览提交 P95，ms | UI 绘制 P95，ms | 关联输入 / 总输入 |
|---|---:|---:|---:|---:|
| 单点 | 5.27 → 3.22 | 26.58 → 24.30 | 5.62 → 5.87 | 905/960 → 903/960 |
| 八点 | 5.02 → 3.12 | 26.19 → 23.90 | 5.27 → 5.49 | 907/960 → 905/960 |

## 松手时复用候选的对象索引

诊断记录中，松手时重建索引用了 37–43 ms，发布本身约 0.05 ms。成功提交非拓扑控制点编辑后，可以把当前候选索引推进到新投影版本。提交失败、取消、拓扑变化或索引已经过期时，按现有规则失效。

12 个交替 Release 进程，每次每种选择热身 30 个输入，测量 720 个输入。普通大幅拖动每侧两次，密集大幅拖动每侧四次。密集模式每次唤醒注入四个事件。每轮都验证最终画布、提交和 Undo。

| 拖动 | 选择 | 松手 CPU 中位数，ms | 松手到当前画布中位数，ms | 持续更新间隔 P95，ms |
|---|---|---:|---:|---:|
| 大幅 | 单点 | 40.50 → 1.78 | 76.09 → 7.67 | 18.12 → 18.20 |
| 大幅 | 八点 | 42.71 → 2.24 | 73.15 → 23.86 | 17.97 → 18.09 |
| 密集大幅 | 单点 | 40.83 → 1.74 | 77.27 → 22.27 | 31.65 → 32.08 |
| 密集大幅 | 八点 | 40.37 → 1.73 | 70.18 → 22.26 | 30.58 → 30.03 |

当前画布以 5 ms 轮询观察求值帧身份。松手列每次进程只有一个样本。持续更新间隔取各进程 P95 的中位数。

验证覆盖 keyform 的完整验证对照、旧快照保留、Mesh 和 Warp 的索引一致性、取消、失败发布及 Undo/Redo。原始记录与每轮汇总位于本机 `target/mesh-drag-performance/` 和 `target/mesh-drag-followup/`。
