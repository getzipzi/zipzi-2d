# 旧 Kit 与最终 Fast 方案完整对照

日期：2026-10-13。对照旧 Kit 0.6.5 / GPUI 0.3.6 与新 Kit 0.7.3 / GPUI Fast 0.1.7（包含正式缓存边界修复），不以 retention 开关替代旧版本基线。

## 采用决定

2026-10-13：接受 GPUI Kit 0.7.3 / GPUI Fast 0.1.7 加正式缓存边界修复作为默认方案，并接受本报告记录的端到端延迟取舍。CPU 收益与已观察到的延迟回退均保留，不将采用决定等同于“所有交互更快”。

正式代码保留 pan/idle 基准、真实窗口测量工具和缓存边界回归；移除本次定位专用的 layout stats、场景转储和 notify_editor 负载。早期结果归档于 [升级测量](archive/gpui-fast-benchmarks.md) 与 [上游复现和原因分析](archive/gpui-fast-reproduction.md)，正式 patch 验证见 [缓存边界修复](gpui-fast-cache-boundary-fix.md)。

## 预定覆盖与验证

测量开始前固定 194 次运行；网格超时后预先记录恢复方案，新增 2 次整组重跑（见后文）：

- 三模型 CPU pan / idle：五轮、两个版本，共 60 次；每次 10 次 warmup +100 次测量。
- 参数设置/场景求值、dirty 查询、独立 Metal 五种交互：三轮、两个版本、三个模型，共 54 次。
- 工作区导入/双文档切换 CPU、GPU：三轮、两个版本，共 12 次。
- 网格覆盖层：两个版本，各 5 档网格 ×2 档分辨率 ×2 种场景 ×2 种控制点设置 ×3 种方法 ×100 样本；共 120 组/版本，并运行像素 QA。
- Headless 动画：两个版本，各 600 个 60 Hz 采样点；三模型功能验收，持续播放数据来自含 motion 的 Mao。
- 真实窗口 pan / zoom / opacity：三模型 ×五轮 ×两个版本，共 30 次进程运行，每负载 30 次 warmup +300 次正式输入，目标 120 Hz。
- 真实参数滑块：三模型 ×三轮 ×两个版本，共 18 次。
- 真实变形：Mao 三轮；白兔、黑椒各一轮，均测两个版本，共 10 次。缺少可编辑控制点的模式保留为不完整覆盖，不修改模型制造通过。
- 真实动画：Mao 三轮、两个版本，共 6 次，每次约 10 秒，显示节拍驱动。

旧版 release 工作区测试 **399 passed、0 failed、4 ignored**；新版 **400 passed、0 failed、4 ignored**。两版均通过三模型动画验收、真实 Metal headless 截图验收和 release workspace all-targets 构建。新版多出一项虚拟列表缓存边界回归测试。

## 结论与提交判断

真实旧 Kit 对照确认了 CPU 收益：headless 平移 P95 下降 59.9%–67.3%，五轮每一轮均更快；真实窗口的平移 UI 绘制 P95 下降 6.3%–19.4%，参数滑块下降 13.2%–26.6%，Mao 动画 UI 绘制下降约 28.0%。原生动画呈现中位帧率均约 120 FPS。

**这些数据支持把本次改造作为 UI CPU 成本优化提交评审，不能支持“所有输入到呈现更快”或“端到端无回退”的声明。** Mao 参数滑块 P95 从 39.886 ms 升至 44.865 ms，三轮均比旧版慢；Mao 多点编辑从 31.401 ms 升至 39.456 ms，且新预览呈现频率下降。若合入门槛要求真实交互延迟不退化，当前证据尚未满足该门槛，需要继续解决这些回退或明确接受此取舍。

旧版的高延迟并非不存在：多数画布模式的 submit→present P95 也约为 32.4 ms，GPU 完成→present 约 31 ms。CPU 优化没有消除显示等待。不过，旧版已有等待不能用于解释掉本次逐项测得的回退；各阶段分位数不可相加，也不能仅凭 trace 把所有差异归因于系统合成器。

Mao 滑块三轮输入→呈现 P95：旧版 39.886 /33.985 /40.385 ms，新版 44.865 /39.990 /45.195 ms。Mao 多点编辑：旧版 46.305 /31.401 /31.278 ms，新版 39.456 /46.040 /34.262 ms。后一项存在明显的呈现节拍档位波动，当前三轮观察到回退，但不足以断言确定的引擎回归机制。滑块三轮则方向一致，不能忽略。

## 窗口完整性与测量边界

64 次真实窗口运行全部执行，无失焦重跑；60 次完整通过，4 次为旧、新版各自的白兔/黑椒变形覆盖不完整。白兔完成单点、多点和 Warp 后因缺少可编辑 Rotation 控制点停止；黑椒完成单点后因缺少 8 个可达控制点停止。两版失败位置一致。下表保留这些已完成模式，但它们只有一轮，不能视为完整三轮变形验收。

窗口测试运行原生 macOS 窗口和真实 Metal 渲染。平移、缩放、滑块、变形通过 `Window::dispatch_event` 注入脚本事件；透明度使用编辑命令。延迟起点为 GPUI 输入追踪入口，终点为相关纹理首次呈现的 Metal `presentedTime`。不包含物理设备延迟、AppKit 投递或屏幕像素响应，也没有进行高帧率相机的 input-to-photon 测量。
