## 逐符号目标映射与完整签名

本轮对 3,682 条原路径逐项登记决定、目标、语义规则、
签名/字段类型：保留 2,430 条、移动 256 条、替换 197 条、删除 799 条。
删除项主要是泄漏的 codec、依赖导入、内部工厂/Backend 构造参数和重复操作入口，
不表示删除 799 项领域能力。目录按已审查的声明家族展开，每条路径保留规则与理由；
未使用笼统的 `needs_review → retain` 替换。

重要决定如下：

- 操作移动到 meshes/parameters/bindings/resources；字段修改值为 `ParameterPatch`。
  RenameIntent、ApplyPlan 和 apply_plan 由统一操作及 `apply(plan)` 取代。
- 单项、批量、分页及 CPU 采样使用通用容器。旧扁平快照的每个有效字段移动到
  Mesh/Parameter/MeshBinding/Image 等纯值；Source 只留在外层。
- 当前完整 R4 的 Modeling/IO/address DTO 保留在 `modeling` 公共域。
  `ModelingIntent*` 映射到对应 `ModelingCommand*`，`value` 字段改为 `intent`，
  保留原有语义。Records、CapabilitySnapshot、EditorSnapshot 统一为具体的 Snapshot。
  `LabelAddress.plan` 保留其 SDK incarnation/context/field epoch 检查。
- 构造器中的 `_variant`/ClassVar 是旧生成实现细节。目标目录移除它们，并把
  `<factory>` 解析为实际纯值默认值，保留 Rust 声明中的默认语义。
- 生命周期对象由公开工厂创建，Backend/token 构造不进入目标公共签名。

目录另外登记 197 条新增/改变的目标条目，包含完整参数、关键字/默认值、overload、返回及
字段注解；新增容器、payload、Summary、状态、错误动作、能力/限制和描述类型均有定义。
本轮结果已验收；具体目标接口继续以 [P3A 契约](p3a-api-agent-contract.md) 为准。

[生成/校验工具](../../../../tools/python/python2_targets.py) 拒绝缺失/重复/未决定的路径、
丢失的方法签名、Backend/Any 泄漏、缺失新方法、非法签名，以及删除现有 R4 操作。
独立负控制还验证容器字段投影、Intent 字段重命名、Buffer.read 和地址规划保留。

## agent 验收配置

验收配置固定模型 `gpt-6.1-sol`、high 推理、当前 Codex CLI
`0.164.0-alpha.11.1` 和可执行文件哈希，禁止 fallback。运行时必须记录实际模型/服务修订，
42 次运行间模型或 runner 修订变化不能合并；身份或服务不可验证时记未验证。

G01–G06 各有 Local/Connected 环境，G07–G08 只用 Connected；14 个环境各 3 次，共 42 次。
各任务有固定完整提示、公共工作流提示、3 个 seed、外部故障控制约定和独立验收器版本。
当时每次预算为 900 秒、160 次工具调用、160,000 输入/24,000 输出 token、单次模型输出
8,192 token、单次工具输出 16 KiB、日志 8 MiB。只允许隔离 packet 中的 shell、正常安装包、
随包文档、任务数据和宿主可访问路径；控制故障的私有接口仅由外部 fixture 使用。

成功门槛仍为至少 38/42、每环境至少 2/3；重复写入、误改对象、静默部分发布、未知结果
报告为成功直接阻断。D/C 门禁独立全过。配置的提示、预算、种子和门槛即使重新计算哈希也
不能被工具悄悄放宽。此处只冻结实验输入；packet/fixture/runner 的执行落实属于 P3A-5，
**本轮 agent 实际运行数为 0，G01–G08 未验收**。

后续规则变更（2026-10-26）：用户明确取消全部 token 上限，改为测试结束后报告实际输入/输出/总量；缺失值记 unavailable，token 不参与判败。以上数值保留为 P3A-0 历史配置，不继续约束后续运行。当前配置与结果见 [P3A-6](p3a-6.md#token-仅报告用量的规则变更)。

## 独立失败基线和 Release P0

原始 11 个严格测试方法/13 条结果全部失败的证据保持不变，覆盖创建/get/commit 恢复、
吞掉未知异常、注解自省、257 对象分页、40 次关闭和有界 repr。
P3A-1 修复后的结果另建记录，不回写原始失败。

P0 基线使用重构前的原始测量脚本、两后端六项工作负载、
各 5 个 timing/5 个 probe 进程，每项 4 次预热和 32 个样本。适配器/宿主均为 Release，
instrumented 与计时产物分开。复制、JSON、堆峰值、资源及调用计数保留原统计边界。

首轮出现 Local single_edit/batch_100 进程间噪声超限，不能冻结，本轮按噪声超限拒绝。
原脚本/阈值不变的确认轮通过噪声门禁，原始数据位于
`target/python2/p3a-p0-before-confirmation/`。
重构前客户端、测量脚本、普通及 probe 原生适配器/CPU 宿主和构建元数据另复制到
`target/python2/p3a-frozen/`；哈希与冻结报告一致，后续构建不覆盖这些产物。
