## 实现

- [_calls.py](../../../../crates/zipzi-python2/client/python/zipzi/_calls.py) 保存操作身份、
  已拥有输入、请求/恢复阶段、原始续接和完整解码/投影。恢复不调用原始执行函数。
  成功或确定失败后释放闭包/输入引用；旧异常不能消费后来请求。
- 原有完整查询适配与 RecoveryOwner 都使用 Call。生成的网格/图片创建、手写参数/绑定创建
  在同一调用里完成单 ID 投影；场景单项读取恢复仍得到 Snapshot；commit 恢复只返回 Job，
  不等待发布；Job.close 恢复为 None，并保留 wait 的实际缓存结果。
- `recover_call` 使用 ParamSpec 保留方法参数和返回类型，只接受有限目录中的 SDK bound method。
  方法执行一次、自动恢复至多一次；任意 lambda、业务方法和未登记包装在执行前拒绝。
  继续未知时原 owner 可继续恢复；Busy、普通失败、预算和 JobTimeout 不被自动重试。
- 删除公开 `Edit.recover`，源码和安装测试调用者改用所属异常或泛型辅助函数。
  OutcomeUnknown.recover 的返回注解为运行时可解析的 object；公开例子无 cast/Any/type-ignore。
- Edit 的 state/receipt 是纯缓存值。正常退出只接受 committed 或 cancelled。
  捕获普通写入失败后仍不可提交；捕获写入、Job、只读查询或独立资源准备的未知结果时，
  退出重新抛出其原始异常和完整返回契约。只读/独立准备未知不毒化候选。
  已有异常传播时保留原异常并附清理说明。
- 生成便利方法中的参数转换移到 Edit 的 `_construct_and_apply` 失败作用域内，随后仍经
  原 apply/apply_many。转换失败被捕获也不能提交；没有新增 Session 自动事务入口。
- Job.wait 支持有限非负秒数及默认 None。已确认任务未结束时抛 JobTimeout、保留 Job，
  不制造 request_id=0、不取消、不缓存为终态失败。默认等待不被连接轮询时长截断；
  每次真实传输仍受连接超时约束。cancel/status 的待恢复请求不能被 wait 消费。
- SdkFailure 提供 recovery_action、requested/allowed/limit_name。Native/IPC 返回实际
  Runtime Budget 限制名称；commit 的错误与实际候选状态在同一次 Runtime 调用里捕获。
  Job/结果槽不足指引 release_resources，确认未执行的 Busy 可 retry，连接待恢复时
  指引 recover_original，候选普通失败指引 restart_edit。宿主未提供的数字保持 None。
- Runtime 有待恢复请求时 close 默认 Busy；显式 abandon_pending 才断连并放弃恢复。

Native 配对更新为 `zipzi-python2-11`，IPC 更新为 `zipzi-runtime-p3a-1`；旧宿主明确拒绝，
不回退 Local。正常 pure/native wheel 仍为开发版 0.1.0，完整 P3A 发行版本另由后续任务统一。
