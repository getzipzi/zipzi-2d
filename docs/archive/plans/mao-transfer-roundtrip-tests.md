# Mao 多轮格式转换测试

## 目的与边界

验证同一个 Mao 文档在保存、导出、重新导入后是否丢失可编辑内容或运行时行为，并区分首次转换差异与多轮累积漂移。测试调用生产 SDK 的导入、保存与完整文件组发布入口，不使用接受损失模式，也不修改本地授权素材。

原生工程和官方运行时包分别作为基线：两者本来就可能包含不同数据，不能直接将它们的差异判为转换错误。基线在首次导入 Kasane 后建立；本测试不能证明原始 CMO3/CAN3 中尚未被解析的字段均已保留，也不能代替 Cubism Editor 的真实读取与渲染校验。

## 输入与路径

只读取 `models/local/mao/` 内已合并的工作副本。测试前后校验所有源文件 SHA-256。

- 工程基线：`mao_pro_t06.cmo3`，另外验证选择 `mao_pro_t06.can3` 得到相同内容。
- 运行时基线：`runtime/mao_pro.model3.json`，另外验证选择配套 `.moc3` 并解析 model3 入口得到相同内容。
- K：保存为 Kasane 工程，然后创建全新会话重新打开。
- C：完整发布 CMO3/CAN3 文件组，然后创建全新会话从 CAN3 导入。
- R：完整发布 model3/MOC3 运行时包，然后创建全新会话从 model3 导入。

每个基线执行以下路径，默认每个循环重复 5 次：

| 路径 | 每轮操作 | 检查目标 |
| --- | --- | --- |
| Kasane | K | 自有格式持久化是否完整 |
| Cubism | C | 工程反复编码后是否退化 |
| Runtime | R | 运行时包首次转换与后续漂移 |
| Mixed C/R/K | C → R → K | 工程经运行时后还剩下哪些编辑语义 |
| Mixed R/C/K | R → C → K | 从运行时返回工程时的缺失与严格错误 |

每一步对比上一轮和最初基线，保留阶段、轮次、字段路径、数值误差和最差顶点位置。遇到严格拒绝或重新导入错误时，记录具体错误并停止该条路径，继续其他路径。不能将中断路径标为无损。

## 比较内容

### 完整持久化文档

通过生产项目编码器取得完整文档，逐字段比较，包括参数类型/范围/默认值、部件和变形器、网格和绑定、融合变形、Glue、层级与显示顺序、动画、物理、姿势、附带资源、画布及 PPU。新增字段自动纳入比较。

归一化自动生成的 UUID、纹理位置和 PNG 编码：顶层对象按 runtime ID、动画资源按名称识别，其他内部标识按定义位置识别；纹理按解码后 RGBA SHA-256 识别。融合变形表、约束及绑定由导入器散列表生成，无序集合按驱动参数、表内容与目标对齐。其余名称、层级与显示顺序、参数值、来源场景元数据等仍然参与比较，不以“格式不支持”为由忽略。

结构数值允许绝对误差 `1e-6`，同时记录实际最大误差。容差只消除微小浮点误差，不将超限变化自动解释为合法转换。

### 运行行为

- 每条动作曲线在播放区间采样 129 个等距时间点，加首尾相邻帧，共 131 次；按动作名和目标 runtime ID 对齐，容差 `1e-5`。
- 每个表情在参数全最小值、默认值、全最大值三种输入下，通过实际 ExpressionPreview 求值至淡入完成，验证 Add/Multiply/Overwrite 的结果。
- 动作时长、FPS、循环、淡变、事件及完整曲线结构仍参加持久化比较；区间外关键帧被裁剪时，行为一致也不代表编辑数据无损。
- 物理设置参与完整文档比较；当前不单独回放物理动态、动作队列淡变和多表情交叉淡变。

### 模型与资源

- 默认姿态、全部 128 个参数各自最小/最大值、头部/嘴/眼组合姿态，共 258 个姿态。
- 比较包含隐藏网格的完整顶点，记录最大像素偏移、超过 `0.1px` 的顶点数、缺失网格和最差位置。
- 比较 UV、三角形索引、可见性、透明度、颜色、遮罩、混合模式和绘制顺序；不能仅凭网格数量相同判定完整。
- 纹理按解码像素比较，避免 PNG 压缩字节不同造成误报。RGBA 相同的纹理重编码允许，尺寸、名称和绑定仍参与比较。

## 自动断言与报告

诊断测试完成只表示矩阵已执行并生成报告。报告中的 `lossless` 才表示所有路径是否均未发现差异或中断。

始终断言源素材未改变、导入文档结构有效、纹理资源齐全、导出不修改源文档、失败发布不留下半成品，以及 K 保存/打开不产生内容差异。K 的文档、采样结果和顶点要求完全一致，不使用浮点容差。输入包中原有的未解析参数、部件等语义诊断单独记录，不修补或删除它们来使转换通过。另有删除表情、改变混合方式、数值漂移和顶点偏移的负向测试，验证比较器能发现损失。

输出目录必须是新目录。默认保留基线、各路径最终归一化文档、`report.json` 和可读的 `report.md`，中间授权素材位于临时目录并在测试后清理。需要人工检查输出文件时设置 `KASANE_ROUNDTRIP_KEEP_ARTIFACTS=1`；不要提交这些数据。

```sh
# 默认完整 5 轮；授权素材缺失会报错，不会以跳过伪装成通过。

  transfer_roundtrip::mao_repeated -- --ignored --nocapture

# 固定新报告目录，并保留实际导出物。
env -u KASANE_DEV_SESSION_DIR \
  KASANE_ROUNDTRIP_OUTPUT="$PWD/target/mao-roundtrip-review" \
  KASANE_ROUNDTRIP_ROUNDS=5 KASANE_ROUNDTRIP_KEEP_ARTIFACTS=1 \
  cargo test --locked -p editor-core --test integration \
  transfer_roundtrip::mao_repeated -- --ignored --nocapture

# 要求所有路径无损；发现差异或中断时在写完报告后失败。
env -u KASANE_DEV_SESSION_DIR KASANE_ROUNDTRIP_ASSERT_LOSSLESS=1 \
  cargo test --locked -p editor-core --test integration \
  transfer_roundtrip::mao_repeated -- --ignored --nocapture
```

轮数可设置为 1–20。报告中应区分表现等价但编辑表示变化、实际行为变化、资源变化、累积误差和严格拒绝；需要根据具体差异判断原因，不能把所有变化归为预期损失。

## 2026-10-18 实测

两种起点、10 条路径、每条路径最多 5 轮，实际完成 30 次转换，5 条路径因严格错误停止；源素材 SHA-256 未变化，双入口归一化文档一致。完整结果位于 `target/mao-transfer-audit/report.json`，可读报告位于同目录的 `report.md`，实际文件组保存在 `artifacts/`。

| 路径 | 结果 |
| --- | --- |
| 两种起点分别保存/打开 Kasane 5 轮 | 10 次均完全一致，包括文档、采样和顶点 |
| 原生工程反复 CMO3/CAN3 5 轮 | 首轮两个纹理名称变化；后 4 轮无新增差异 |
| 原生工程反复运行时包 5 轮 | 首轮丢失对象显示名称、表情来源场景及区间外动作关键帧，并改变部分内部表示；后 4 轮稳定 |
| 官方运行时包反复运行时包 5 轮 | 首轮 60 处数值/标志差异，涉及画布 flag、旋转原点和关键形；后 4 轮稳定 |
| 含运行时包到 Cubism 工程的路径 | 5 条路径严格拒绝，涉及注册元数据、pose、Multiply 表情、未解析目标和非整数帧等，未生成半个输出包 |

成功步骤的 258 个姿态均为 `0px` 顶点差异，动作和表情采样差异均为 0；UV、拓扑及外观比较无超限变化。这说明已测表现稳定，不说明编辑文档无损。运行时转换中顶点整数标识、Glue 顶点引用和坐标基准等变化需结合行为比较判断，不将全部结构差异直接当作视觉损坏。

已确认的名称损失包括 261 个网格、175 个变形器、32 个部件的显示名称回退为 runtime ID，及 7 组 Glue 的派生名称变化。`mtn_01` 的负时间初始键从 `-5.6s` 裁剪为播放区间内的 `0s`；播放区间采样一致，但无法从运行时包恢复原有编辑区间。官方运行时输入原有 16 项未解析引用诊断，单独记录而未修补。

第 5 轮工程文件组已通过本机 Cubism 5.4 alpha 的模型实例和全部 15 个场景读取校验。比较器的两个负向测试通过。整体 `lossless=false`，当前未发现多轮累积漂移，已发现首次转换的信息变化和被阻止的逆向路径。

### 差异判定

- **已确认 bug：部件名称未导出。** CDI3 标准支持 `Parts[].Name`，但本次生成的 CDI3 只有 Version、Parameters、ParameterGroups，没有 Parts。原生导入设置 DisplayInfo 为 Imported 却未填入部件条目，使生成部件名称的回退分支失效。32 个部件名称丢失不能归因于格式限制。
- **预期的存储变化：** `imageFileBuf_360.png` 等是容器内部资源名，重新编号且像素/引用一致不等于纹理内容丢失；顶点标识重编号、PNG 重编码、坐标方向 flag 规范化也需要按语义而非原始值判断。
- **标准运行时格式的编辑信息边界：** 网格、变形器和 Glue 的编辑显示名，以及表情场景的时长/FPS、初始部件设置等，不像部件名称那样有现成的 CDI3/exp3 标准承载字段。
- **当前明确的运行时转换约定：** 只输出动作播放区间，保留区间内曲线行为；区间外键的裁剪有意为之，但会丢失编辑信息，并非声称 motion3 规范强制删除所有区间外值。
- **工程逆向导出的实现缺口：** 自产运行时包返回 Cubism 工程只因 `CAN3_MOTION_REGISTRATIONS` 被拒绝，属于需要补齐的映射能力；拒绝本身遵守严格错误策略，不能将该链路计为已经无损支持。
- **待进一步确认：** 原运行时包首轮 60 项数值/标志变化不能全部当作 bug，也不能仅凭 258 个姿态一致就证明精度变化均无害。需要随机组合参数及原生 Core 对照进一步确认大数值旋转原点的精度风险。
- **输入问题：** 16 项诊断中的 Param5、ParamRabbitEliminationEffect、PartSketch 在原始 MOC3 中没有相应标识，不是新一轮导出产生的引用丢失。

报告摘要曾遗漏带数字的 CAN3/MODEL3 错误码，现已修复并补回摘要；原始 report.json 保留了完整错误，未受到影响。自产包中断的原因是动作注册元数据；官方包的中断还涉及 Multiply 表情、未解析目标及帧量化。比如官方 motion3 的 `0.333s × 30FPS = 9.99`，直接回写整数帧需要取整，严格拒绝本身不是静默数据损坏。

## 2026-10-19 修复与回归

上节记录的是修复前结果。本次修复了两项已确认的问题：

- 原生工程导入时将全部部件写入 DisplayInfo 的 Parts 条目，运行时包通过标准 CDI3 `Parts[].Name` 保存显示名称。Mao 的 32 个部件名称在“工程 → 运行时 → 工程 → 运行时”中均保留，测试同时直接检查实际 CDI3 文件。
- 将简单 model3 动作注册组映射为 CAN3 原生播放列表，保留分组名、注册顺序、重复引用及空组。播放列表使用约定的 UUID 命名空间标识注册用途；原生 Editor 的普通播放列表不被当作 model3 分组。已注册场景保留动作身份，其余场景继续采用初始值分类表情的规则。

注册条目单独覆盖的淡入、淡出、声音和不透明扩展仍严格报错；没有静默删除这些数据。单独导出 CMO3 也不能丢弃动作注册组。

新增回归覆盖中文部件名、空组名、与默认播放列表同名的组、重复注册、静态动作身份及不支持的注册字段。Mao 的针对性回归验证 7 个动作、8 个表情及完整分组在返回工程后保留。带注册播放列表的实际输出已通过本机 Cubism 5.4 alpha 的模型实例和全部 15 个场景读取校验。
