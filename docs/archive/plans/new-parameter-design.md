# 新增参数需求设计

状态：首期已实现。2026-10-04 确认范围为新增参数的创建流程，同日按下述方案接入编辑器。普通与 BlendShape 两种类型均可创建，切换类型保留数值，循环、精度和分组位于高级选项中。

用户通过 Parameters 面板创建一个可保存、可撤销的独立参数，随后能在面板中找到并预览它。创建流程覆盖参数身份、取值范围、类型和现有分组归属；绑定对象和生成关键形另行设计。

## 现有能力

Parameters 面板已支持参数预览、数值输入、参数聚焦、分组浏览和绑定查看，尚无新增参数入口。SDK 已提供 `create_parameter` 与 `set_parameter_group`，持久模型和历史由 SDK 管理。

参数有两种身份：内部 `id` 是规范 UUID，由编辑器生成；用户填写的“参数 ID”对应 `runtime_id`，用于运行时识别。显示名称与这两种身份独立。现有 SDK 校验要求运行时 ID 在参数之间唯一，并拒绝与未解析 CDI 参数条目的运行时 ID 冲突。

相关实现：[参数面板](../crates/editor/src/panels/parameters.rs)、[文档协调](../crates/zipzi-editor-core/src/document.rs)、[编辑命令](../crates/zipzi-editor-core/src/editor.rs)。面板联动沿用 [Document 面板与参数绑定设计](archive/document-panels-design.md)。

## 入口与创建流程

建议在 Parameters 面板顶部提供“＋ 新增参数”，空列表也显示入口。首期不分配默认快捷键。无活动文档、文档忙碌或已有模态对话框时禁用入口，并沿用现有命令可用性规则。

1. 点击入口，记录当前 `DocumentId`，按现有规则结束正在进行的编辑，再打开“新增参数”弹窗。弹窗内的输入只修改草稿。
2. 初始焦点位于名称输入框；名称、参数 ID、取值范围是主要字段，类型、循环、精度和分组可以置于高级选项。
3. 点击“创建”或按 Enter 时，重新校验草稿、文档身份和分组，提交一次创建命令。提交期间禁用重复提交。
4. 成功后关闭弹窗，滚动定位新参数，并将参数焦点及属性检查对象设为新参数。失败时保持弹窗与填写内容，显示可读错误。
5. “取消”、Esc 和关闭按钮均丢弃草稿；点击弹窗外不关闭，避免意外丢失输入。关闭后将键盘焦点还给参数面板。

弹窗沿用现有 GPUI Kit 对话框和主题，不另建界面组件体系。草稿不跨文档复用；提交时若原文档已关闭或活动文档已变化，拒绝提交并提示重新打开创建流程。

## 字段与建议默认值

| 字段 | 建议初始值 | 行为与校验 |
| --- | --- | --- |
| 名称 | 新参数 | 首期建议必填，去除首尾空白；允许重复，允许中文 |
| 参数 ID | `ParamNew` | 可编辑；冲突时初始建议依次使用 `ParamNew2`、`ParamNew3`；去除首尾空白后不能为空 |
| 最小值 | −1 | 必须能表示为有限 `f32`，且严格小于最大值 |
| 最大值 | 1 | 必须能表示为有限 `f32`，且最大值减最小值仍为有限数 |
| 默认值 | 0 | 必须能表示为有限 `f32`，位于闭区间内 |
| 类型 | 普通参数 | 建议提供普通参数与 BlendShape 两种现有类型 |
| 循环 | 关闭 | 保存为现有 `repeat` 字段，两种类型均可设置 |
| 精度 | 6 | 保存为 `decimal_places`，必须是 0–9 的整数 |
| 分组 | 未分组 | 选择已有参数分组；嵌套分组显示完整路径，空分组也可选择 |

用户修改名称后不自动重写参数 ID。用户修改参数 ID 后，提交时出现冲突应报错，不静默换用另一个 ID。首期建议不额外限制 ID 为特定英文前缀或字符格式，以现有 SDK 的身份约束为依据；如需导出格式限制，需另行核实并定义。

切换类型保留用户已经填写的范围和默认值，不静默覆盖。首期不额外提供 BlendShape 范围预设。

创建弹窗使用可往返解析的数值文本，不沿用参数面板的一位小数截断显示。精度字段是现有模型元数据，不应在提交时据此截断用户输入；具体滑条步进沿用现有逻辑。拖动参数的展示方式不在本次需求中重设计。

分组默认“未分组”。当前面板的分组点击是导航操作，没有明确的创建归属上下文，因此首期建议由用户显式选择，不从当前检查对象猜测分组。

## 校验与错误反馈

必填字段编辑后或失焦时显示错误；范围关联错误在相关字段下说明。输入为空、单独负号等尚未完成的文本允许暂存，但不允许提交。校验失败时禁用“创建”；按 Enter 同样不能绕过校验。

| 情况 | 建议提示 | 提交结果 |
| --- | --- | --- |
| 名称为空 | 请输入参数名称 | 保留草稿 |
| 参数 ID 为空 | 请输入参数 ID | 保留草稿 |
| ID 与参数或未解析显示条目冲突 | 参数 ID 已被使用 | 保留用户填写的 ID |
| 数值无法解析或不能表示为有限数 | 请输入有效数值 | 定位对应输入框 |
| 最小值不小于最大值 | 最小值必须小于最大值 | 不自动交换两个值 |
| 范围跨度溢出 | 参数范围过大 | 保留草稿 |
| 默认值越界 | 默认值必须在参数范围内 | 不自动夹紧 |
| 精度非法 | 精度必须是 0 到 9 的整数 | 保留草稿 |
| 分组已不存在 | 所选分组已不存在，请重新选择 | 不降级为未分组 |
| 原文档已关闭或活动文档变化 | 文档已变化，请重新打开新增参数 | 不写入其他文档 |
| SDK 提交失败 | 展示对应业务错误 | 不留下部分创建结果 |

界面预校验用于及时反馈；最终提交仍由 zipzi-editor-core 和 SDK 校验。两次数值校验都必须使用转换后的 `f32`，覆盖转换溢出以及两个不同文本转成相同数值的情况。

## 提交与撤销

建议新增 `parameter.create` 界面命令及带类型草稿的 `EditorCommand::CreateParameter`。界面不直接写 SDK，调用路径为面板对话框、Editor 命令、Document、SDK 编辑事务。

Document 在创建事务中生成 UUID、创建参数并设置分组。建议即使选择未分组也调用 `set_parameter_group(id, None)`，保证新参数进入显示信息；SDK 应保留导入显示信息中的既有条目、分组与扩展。整个创建形成一条“新增参数”历史记录，任一步失败则回滚整个事务。

只有成功提交后才更新文档 dirty 状态、结构投影、参数列表和相关缓存，再应用面板定位及参数聚焦。取消弹窗或创建失败不产生创建历史，不改变参数预览或选择；打开弹窗前按既有规则结束的编辑属于之前的操作。

撤销删除新参数及本次添加的分组成员关系，清理指向已删除参数的焦点和属性检查引用。重做恢复同一个 UUID、所有参数字段和分组关系；焦点按现有历史后的上下文协调处理，不要求恢复已被撤销清理的焦点。

## 创建后的面板状态

新参数追加到当前参数列表末尾，滚动到可见区域。列表没有筛选时必须能直接找到它；若后续加入筛选，创建流程应保证新参数可见。

参数焦点和属性检查对象切换到新参数，沿用 `FocusParameter` 的现有规则。对象选区、活动绑定、画布视口和其他参数的预览值保持原状态；新参数的预览值使用它的默认值。

创建成功不会自动绑定当前对象，不会生成关键形。新参数的直接绑定数量为零，属性面板展示新参数字段；关键形面板继续显示原活动绑定，避免隐式改变编辑目标。

## 首期边界

首期建议交付单个参数创建、现有分组选择、字段校验、定位聚焦，以及撤销、重做和保存重开。普通参数与 BlendShape 的创建字段共用同一流程，类型仅创建参数自身。

绑定对象、生成关键形、创建或整理分组、批量创建、复制参数及参数模板另行设计。本次也不扩展已有参数的类型或运行时 ID 编辑能力。

## 验收场景

1. 空白文档和已有参数文档都能通过面板入口创建参数；无文档和忙碌状态不可创建。
2. 建议 ID 跳过现有参数及未解析 CDI 条目的冲突；手动填写重复 ID 时显示错误。
3. 非法输入、相等或颠倒范围、默认值越界、数值和跨度溢出、非法精度均不能提交。默认值可以等于范围端点。
4. 输入 `0.375` 等高于一位小数精度的默认值，创建后保存的数值不被面板显示规则截断。
5. 分别覆盖未分组、已有嵌套分组、空分组，以及生成和导入两种显示信息来源；保存重开后归属与字段一致。
6. 创建参数和设置分组只有一条历史记录；撤销、重做保持参数身份，并保留原有显示信息条目与扩展。
7. 取消和 SDK 拒绝提交不留下参数、分组成员关系或创建历史。失败后可修改草稿重试。
8. 创建后参数可见且聚焦，属性检查指向新参数；对象选区、活动绑定及其他预览值符合上述规则。
9. Enter、按钮快速连点和重复回调只创建一个参数；文档切换、关闭及分组失效不会产生误写。

实现时用核心回归验证事务、身份、历史和保存重开，用 GPUI headless 检查入口、弹窗校验、取消、重复提交及文档隔离；实际窗口确认键盘焦点和列表滚动定位。

## 首期实现选择

| 选择 | 首期行为 | 影响 |
| --- | --- | --- |
| 首期参数类型 | 同时支持普通与 BlendShape | 类型选择位于高级选项 |
| BlendShape 范围 | 保留填写内容，无额外预设 | 不隐式改变用户数值 |
| BlendShape 循环 | 开放，使用 SDK 现有 `repeat` 字段 | 创建阶段只保存参数自身配置 |
| 高级字段布局 | 类型、循环、精度和分组放在高级选项 | 初始弹窗显示名称、ID 和范围 |
| 名称是否必填 | 必填，初始值为“新参数” | 创建入口提供明确显示名称 |

核心创建与校验见 [参数创建](../crates/zipzi-editor-core/src/parameter.rs)，弹窗见 [创建界面](../crates/editor/src/panels/parameters/create.rs)。核心回归覆盖事务、历史、身份、保存重开、导入显示信息、非法输入与文档隔离；GPUI headless 回归覆盖 Enter、取消、错误恢复、长列表定位，以及类型和分组下拉选择。
