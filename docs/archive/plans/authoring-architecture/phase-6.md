# Authoring 阶段 6 工作流性能与内存对照

2026-11-07 完成，阶段提交为 `64675a53`。[架构方案与阶段索引](../authoring-architecture.md#实施记录)

完成版本在 Mao 工程上的单次编辑与批次明显变慢，改名采样将首要优化点定位到
重复全图校验。保存与历史切换耗时下降，默认可用历史仍为 50 步。

- 两个独立工作树构建同一套 Release 探针。共享 Rust 工作流定义操作、断言和计时边界，
  两个适配器分别调用基线与完成版本的实际 API。两边使用相同的分配计数器。

## 实验设计

在 Apple M4（16 GiB、macOS 27.0.1、Rust 1.99.0）上，对固定起点
`0262b0108b920a2b573c7a3e6d689591566e5099` 和完成版本
`c7ca7fe9b2a05646008c21a3c923bd3a62471ee2` 使用同一计时流程和分配计数器。
两个工作树均以 `--locked --release` 构建，使用默认历史与资源配置，以及同一套
Rust MOC3 解码路径。每个版本先预热一次，再用独立进程交替 AB/BA 跑六组。
范围为 SDK CPU authoring 与工程 I/O。窗口、GPU 和 IPC 由第五阶段的独立门禁覆盖。

输入是本地 `models/local/mao/runtime/mao_pro.model3.json`（21 个文件，输入清单 SHA-256
`f1a0f5a713918bf7c656310f3a77ed81f7804b3d2f7930c8aa03192b509e17dc`）。
两边载入的 260 个网格、6,012 个顶点、128 个参数、7 个动作和 93,560,376 字节解码纹理
一致。探针核对改名、顶点移动、批量创建 32 个参数、Undo/Redo、保存及另存后的 dirty 状态。
重开后核对全部纹理像素摘要、模型数量和 160 个参数，并继续编辑同一个稳定顶点。
本地逐次样本、二进制指纹和输入清单保存在仓库根目录下的
`target/phase6-authoring-workflow/results.json`。原始输出和私有素材留在忽略目录。
[构建与复跑命令](../../../../tools/benchmarks/README.md#authoring-workflow-comparison)

## 改名热点与后续优化

完成版本的改名、移动顶点和创建参数批次分别耗时约为基线的 24.6、43.7 和 17.0 倍。
对完成版本的连续改名另取三秒 CPU 样本。2,224 个主线程样本中，1,116 个落在
`Draft::prepare → DocumentBuilder::freeze → validate_candidate` 下，另一路主要开销位于
批次结束的校验。调用栈显示绑定规范化反复构建基础身份集合并查询动作身份。
样本保存在本地 `target/phase6-profile.18MWwH/rename-sample.txt`。

1. **复用批次校验。** 普通 `Draft::batch` 完成和 `Draft::prepare` 冻结分别调用
   `validate_candidate`，每次在场景初始化前后都校验全图。先验证 Builder 在批次校验后
   至冻结前保持不变时能否复用结果，再单独量化收益。保留预览、无净变化、跨领域引用、
   失败隔离和冻结后的来源语义。
   [Draft](../../../../crates/zipzi-sdk/src/authoring/draft.rs) ·
   [DocumentBuilder](../../../../crates/zipzi-core/src/state.rs)
2. **在单次校验内共享身份索引。** 针对 `base_identity_set` 与 `motion_identity_exists`
   的重复工作，测量普通绑定、场景绑定与跨领域引用的变化。保留身份冲突和前向引用检查。
   [绑定规范化](../../../../crates/zipzi-core/src/model_validation/bindings.rs) ·
   [身份查询](../../../../crates/zipzi-core/src/model_validation/queries.rs)
3. **分解导入与重开。** 对 Model3 导入和 ZIP 重开分别量化解码、模型冻结校验、
   资源捕获与纹理预解码。重开同时比较首个可读快照、读取全部纹理的总耗时和 Rust
   堆存活量，确认优化是否只是把耗时移到下一次读取。现有改名采样只覆盖编辑路径，
   两条加载路径的成本归因待验证。

后续每轮将优化候选与固定的 `c7ca7fe9` 重新配对，继续保留原始 main 一列作为参照。
复用同一输入、Release 模式和历史配置，报告改名、顶点、批次、保存、重开及实际历史容量。
用现有行为用例核对正确性，再用相同探针确认实际收益和有无回归。

## 优化复测

冻结复用当前 Builder 已通过的批次校验，每条写命令都会使该结果失效。场景初始化
实际写入记录时再校验结果。单次校验共享基础身份、绑定身份和动作身份索引，全图通过
身份检查后直接验证绑定和动作的数据与引用。共享的不可变网格记录复用已验证的几何，
仍按候选模型校验属性和引用。

ZIP 重开从私有归档副本读取 PNG，在验证哈希、尺寸和解码上限后直接保留编码字节与
解码像素。重复引用共享该资源。保存和资源接纳只校验已有元数据，观测路径按需计算
像素摘要。导入为每张网格保留独立的图集裁切资产记录，尺寸和像素一致的裁切结果
共享资源，替换后的源图集缓冲在导入返回前回收。

## 原生 Editor UI 对照

在同一台 Apple M4 上，用 `--locked --release --features test-support` 构建
main、完成版本和优化版 Editor。三个版本都走 Rust MOC3 解码，使用同一份 Mao
Model3 输入。ZIP 首帧用同一个由 main 保存的 ZIP。两组对照分别为 main 对优化版、
完成版本对优化版，每组交替运行六对新进程。每个进程独立配置、缓存和 Runtime。

- **首帧。** Model3 导入与 ZIP 重开各启动一次新窗口。计时从 Editor 提交加载请求
  前开始，结束于第一个包含已接受模型预览的 Metal 合成帧实际呈现。报告同时保留
  加载 worker、纹理上传和 GPU 完成时间。
- **Properties。** 拖动 Mesh 的不透明度，预热 10 次、测量 30 次。记录经过验证的
  属性变化、GPUI 事件处理和可关联到该输入的合成呈现。
- **画布变形。** 分别拖动单顶点、八顶点、Warp9 和 Rotation。每项预热 10 次、
  测量 120 次，目标输入频率 120 Hz。
- **动画。** 在原生窗口播放模型中第一个可播放的循环动作，启动后预热 500 ms，
  测量 5 秒。记录评估、渲染、接受预览与合成器呈现间隔。

首帧按进程取中位数和范围。交互按每个进程计算 P50/P95，再取六个进程的中位数。
输入计时从 GPUI 派发开始，呈现以合成器时间戳为准。
[原生窗口探针与配对命令](../../../../tools/benchmarks/README.md#runtime-editor-pairs)
