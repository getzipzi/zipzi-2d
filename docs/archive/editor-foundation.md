# 编辑器基础架构：第一阶段

状态：2026-09-28。五个实施步骤的代码已落地：多文档、后台保存、统一命令与快捷键配置、
Kit Dock 与布局持久化、CanvasView 与基础顶点工具；自动化回归与无窗口原生 Metal 基线已完成。
原生焦点、输入法、Dock 拖拽及视觉表现尚未经人工验收，不以此阻塞实现交付。
当前边界和验证结果见 [实施记录](editor-foundation-implementation.md)、
[文档编辑架构](document-editing.md) 与 [性能记录](editor-foundation-baseline.md)。
下文保留目标约束，涉及原“当前实现”的描述为开工基线。

## 产品范围

Kasane 是 Cubism Editor 的替代品。第一阶段仅做模型制作，包括后续的参数和关键形编辑；
不引入独立动画文档。采用单窗口、多模型标签页，每个模型先只有一个画布视图。

Python 继续作为独立、无界面的 SDK 客户端。现阶段不嵌入 CPython，
也不通过 IPC 向 Python 开放编辑器的活动会话。

本文是第一阶段实现依据；不要求阅读聊天记录。后文标为“首期默认”的细节可直接采用，
类型、模块名称和 crate 划分允许实现时按需调整，所有权、行为与验收约束必须保持。
“后续参数和关键形编辑”仅要求架构留有位置，不要求本阶段交付参数面板或关键形工具。

## 状态归属

| 所有者 | 状态与职责 |
| --- | --- |
| SDK AuthoringSession | 模型、编辑语义、算法、校验、事务、模型历史、项目读写 |
| 文档会话 | SDK 会话、选区、编辑模式、工具交互状态、视口、活动手势、文档任务状态 |
| 窗口工作区 | 文档集合、活跃文档、标签页、共享面板布局、打开关闭协调、命令目标与可用状态 |
| 应用设置 | 主题、语言、快捷键覆盖与恢复默认等偏好 |
| 渲染模块 | GPU 资源、纹理缓存、不可变输出；不承担模型编辑和项目 IO |

文档会话名称为设计概念。

实现 agent 可根据职责内聚、依赖隔离、复用和测试需求，
自行决定使用现有模块或新建 crate，无需为正常的 crate 拆分另行确认。
现有 editor、editor-core、editor-render 是起点，不限制最终 crate 数量；
拆分须保持业务核心不依赖 UI/GPUI、渲染不承担模型编辑和项目 IO，并避免循环依赖。
交付说明中简述新增 crate 的职责与拆分理由即可。

Editor 的应用状态与协调逻辑属于 editor-core；editor crate 仅承担 UI 与平台适配，
包括 GPUI 控件、焦点、原生对话框、宿主任务调度和预览合成。
当前已迁移文档/视口所有权、编辑命令、忙碌状态、加载结果处理、关闭判定与预览版本；
后续多文档与工具协调也在 core 扩展，不能重新堆回 EditorView。

所有模型变更通过 SDK。镜像、自动网格等高层编辑算法也属于 SDK，
不能只把最终 set 操作放进 SDK、算法留在编辑器。相同模型编辑能力应可通过 SDK + Python 完成。
调用方提供必要目标输入；SDK 不依赖 UI 的隐式选区或焦点。

## 历史与连续编辑

- Undo/Redo 只恢复 SDK 模型状态；选区、工具、视口不另设历史栈。
- 每次模型变更后校正编辑器引用，清理已不存在的对象或顶点；这不是恢复旧选区。
- 文本输入保留自身的撤销，由焦点路由区分文本与文档操作。
- 顶点拖动开始时固定目标与编辑基准，移动时更新 SDK 候选，松开提交一次历史。
- Esc、工具或文档切换、选区或参数切换、焦点或指针捕获丢失时，取消未完成的画布手势。
- 视口导航不改变事务目标。无变化的手势不产生历史，也不丢弃 redo。
- 属性输入沿用已有的 Enter/blur 提交、Esc 取消规则；统一协调生命周期不代表所有交互必须采用同一提交规则。

每个文档最多有一个活动交互事务，由编辑器协调。当前 SDK 的 begin_owned_edit
建立独立候选，在 commit_to 时校验版本；它并不提供全局单写锁。
保留这种冲突检测机制，不为编辑器手势而改成强制互斥。

高层 SDK 操作应能组合进同一事务，由调用方定义一个撤销步骤；新增操作时验证其组合和失败语义。

## 工作区与布局

- 文档分别持有历史、保存状态、选区和视口；切换标签页恢复相应状态。
- 图层、属性等共享工具面板跟随活跃文档，切换模型不切换布局。
- 使用当前锁定版本 gpui-kit 的 DockArea/DockSkin，支持窗口内拖拽、标签分组、拆分、调尺寸和折叠。
- 保存和恢复窗口布局，提供重置入口；暂不做独立浮动窗口。
- 文档生命周期归工作区管理，不能依赖 Dock 面板是否存在。隐藏工具面板与关闭模型是不同操作。
- 打开同一路径激活已有文档；关闭按文档处理未保存状态，退出协调所有文档。
- 后台任务与异步结果绑定文档身份，不能通过完成时的活跃标签页确定接收者。
- 预览结果还须校验请求版本，避免切换文档或连续编辑后显示过期帧。

首期默认：editor-core::Editor 承担工作区协调，每个打开的模型有独立文档会话。
使用运行期 DocumentId 区分会话，不能直接以 SDK 模型 UUID 或文件路径充当会话身份：
同一模型的两个文件副本可能有相同 UUID，未保存文档没有路径，另存为会改变路径。
异步操作另带 OperationId，结果仅允许回到仍持有该任务的会话。

新建、打开和导入成功后新增并激活标签页；失败保持当前文档，取消不留空标签页。
项目目录和 manifest 路径先归一化为相同项目身份，重复打开激活已有标签页。
禁止另存为到另一已打开文档的项目位置，提示用户选择其他位置。
关闭最后一个文档后保留空工作区；关闭脏文档提供保存、放弃、取消，
保存失败或取消路径选择时保持文档打开。退出依次处理脏文档，任一步取消则停止退出。
导入操作若会写入已有目录，沿用 SDK 的发布规则及必要的 UI 覆盖确认，不静默覆写。

模型标签页固定在中央 CanvasView 中；首期只让工具面板自由停靠，
不允许把模型拆成多个同时显示的画布组。图层、属性是首期面板，
参数、资源和历史面板不因支持 Dock 而自动纳入交付范围。

## 命令与快捷键

快捷键是第一阶段的正式交付内容。当前 menus.rs 中已有固定的 GPUI KeyBinding、
原生菜单和文本输入优先的 Undo/Redo 路由；后续在此基础上集中管理，不另写一套键盘事件分发器。

### 职责边界

- editor-core 定义稳定的命令标识、参数、业务作用域、可用状态与执行入口。
  编辑、文档、工具和视口命令都应有明确目标，不依赖某个按钮或菜单是否存在。
- 菜单、工具栏和快捷键映射到同一命令，共用业务可用性判断。即使 UI 未及时禁用入口，
  core 仍须拒绝忙碌文档或无效目标上的操作。
- editor 负责将 GPUI Action/KeyBinding、焦点上下文和平台按键转换为 core 命令；
  文本输入操作交给 Kit 控件，隐藏应用、最小化等原生窗口操作留在平台适配层。
- 快捷键偏好属于应用配置；模型文件、SDK 历史和面板布局不保存键位。
  core 不依赖 GPUI 的按键、焦点或窗口类型。

### 作用域与事件处理

明确区分应用/工作区、活跃文档、画布/工具和文本控件上下文。
UI 根据实际焦点与模态状态建立 GPUI 上下文，命令执行时固定具体文档身份。
切换标签页后不得继续向之前的文档派发命令，异步命令完成时也不得重新用活跃标签页猜测目标。

- 模态对话框优先处理输入，底层文档快捷键不能穿透。
- 文本控件拥有文本编辑按键；输入法组合输入、字符输入、剪贴板及文本 Undo/Redo
  不得触发画布工具。文本无可撤销内容时也不能退回文档 Undo。
- 文本输入获得焦点时，打开/保存等工作区命令仍可按明确绑定执行，不能一律禁用所有快捷键。
- 工具单键快捷键仅在相应画布上下文中生效，不通过窗口级 capture_key_down 抢占输入。
- Esc 由当前交互拥有者处理一次：对话框、属性编辑或画布手势；不能同一次按键取消多个层级。
  现有名称输入的 Esc 取消行为必须保留。
- 对自动重复逐命令定义策略：缩放等连续操作可重复，打开对话框、关闭文档和工具切换不重复触发。
  后续按住临时切换工具时必须成对处理按下/释放，并在失焦时清理状态。

### 第一阶段范围

默认键位集中定义，命令显示名称使用本地化 key，命令标识不随语言变化。
原生菜单、工具提示和快捷键清单应展示同一份生效绑定，避免界面提示与真实键位不一致。

| 命令组 | 首期覆盖 |
| --- | --- |
| 文件与文档 | 打开、导入入口、保存、另存为、关闭活动模型、退出 |
| 多文档 | 切换上一个/下一个模型标签页 |
| 编辑 | 文档 Undo/Redo、提交/取消属性编辑；文本编辑沿用 Kit |
| 视口 | 缩放、重置视图 |
| 工具 | 激活首个顶点选择/拖动工具、取消活动手势 |
| 面板 | 显示/隐藏已接入面板、重置布局 |

并非每个命令都必须分配默认按键，未绑定命令仍可以从菜单或按钮调用。
保留现有 macOS 常用键位；接入多文档后，⌘W 改为关闭活动模型，关闭窗口使用独立命令。
画布全选、删除、复制粘贴等命令只有在实际编辑能力落地后才开放，不因存在同名文本操作而自动支持。

首期支持通过配置覆盖、取消绑定和恢复默认，并持久化用户覆盖项；专用图形化改键界面后续实现。
同一有效作用域内的歧义绑定应报告冲突，拒绝本次覆盖配置并保留上一份有效配置，不能靠注册顺序静默覆盖。
不同上下文复用同一按键允许存在，但必须有明确优先级；未知命令和无效键位需给出诊断。
按键解析和平台规范化复用 GPUI，使用当前 macOS 平台验证；暂不实现多段组合键或宏系统。

配置应用以整份覆盖配置为事务：任一条目无效或冲突时拒绝本次配置，保持上一份有效配置。
首次启动没有有效覆盖时使用默认键位。首期允许修改文件后重启生效，不要求热重载。
实现前验证当前锁定版本的 GPUI/Kit 如何安装和移除绑定，以及原生菜单如何展示最终生效键位；
不能仅追加一套新绑定却留下旧绑定仍然生效。发现库限制时先记录具体限制与替代方案。

## 画布、辅助图形与输入

画布采用模型渲染、编辑辅助图形、输入处理三部分分离的架构。
它们共享视口定义与显示版本；逻辑分层不要求独立窗口或多个 Metal device。

| 部分 | 所有者与输出 |
| --- | --- |
| CanvasView | editor：测量画布实际区域、接收输入、处理焦点和捕获、合成模型纹理与辅助图形 |
| ViewportState / ViewportTransform | editor-core：缩放、平移及坐标变换的唯一事实来源 |
| 工具控制器 | editor-core：将画布输入转成选择、手势和 SDK 操作 |
| SceneSnapshot | core 通过 SDK 求值得到不可变模型场景，交给 editor-render |
| OverlaySnapshot | core 输出顶点、线段、选框、手柄和样式角色等纯数据，由 UI 或 renderer 绘制 |
| 模型渲染器 | editor-render：模型材质、纹理、遮罩和最终作品内容，不认识编辑工具或选区 |

辅助图形不写入模型、历史或导出内容。首期使用 GPUI 绘制少量控制点、线和选框，
避免为每个顶点创建独立的 GPUI Entity 或事件监听器；密集网格需要时可转为 Metal 批量绘制，
但不能让工具逻辑依赖具体绘制后端。暂不增加第二套 GPU 设备、CPU 图像回读或 GPU picking。

输入由 CanvasView 统一送入 core 工具控制器。UI 先处理面板、弹窗和文本输入，
只将属于画布的指针事件传入工具；具体工具不直接持有 Window、Entity 或整个 EditorView。
屏幕上的控制柄距离判断属于编辑器交互，几何领域查询优先使用 SDK；
模型变形、关键形处理和变形器逆映射属于 SDK，不能散落在 UI 命中处理里。

### 坐标约定

- 区分窗口逻辑坐标、画布局部逻辑坐标、物理像素和模型源坐标，不用无标注的 Vec2 混传。
- CanvasView 提供实际画布 bounds 和显示 scale factor，不能用窗口宽度减固定侧栏宽度估算。
- core 生成前向/逆向视口变换；renderer、辅助层和命中测试消费同一套变换，
  替换当前 renderer 内部单独计算居中与缩放的方式。明确处理 SDK 求值坐标与模型源坐标之间的转换。
- 控制点尺寸、线宽和命中半径使用逻辑像素，缩放模型不会放大这些交互尺寸。
- 零尺寸或隐藏画布暂停提交渲染；恢复可见或尺寸/scale factor 变化后产生新的视口版本。
- 首期支持缩放、平移和重置，不做画布旋转；重置为居中适配视图。

### 更新与版本同步

模型帧、依赖几何的辅助图形、对应的命中数据需携带同一个
DocumentId + SceneRevision + ViewportRevision。渲染任务另带 RequestId，
场景版本包含未提交候选的变化，不能只用 SDK 已提交版本标识拖动中的所有帧。

悬停、选区高亮和框选矩形变化只更新辅助层，不重新求值模型或上传纹理。
模型编辑使场景失效；缩放、平移、Dock 调整或屏幕倍率变化使视口失效。
单纯视口变化复用已求值场景，避免再次进行与视口无关的模型求值。
连续输入只保留必要的最新待渲染请求，不积压所有鼠标事件的场景副本。

新帧完成前保留上一组匹配的模型画面与几何辅助层，完成后成组切换；
旧文档或过期请求的结果不能覆盖当前画布。悬停命中基于实际显示的匹配数据，
活动拖动继续使用开始时固定的编辑目标与基准；不能因异步帧到达而重新选目标。
纯指针提示可独立更新，但不能将新几何控制点叠到旧模型或不同视口的画面上。
若允许拖动期间导航，按当前逆变换换算指针并保持拖动锚点连续，不重定向事务目标。

## 工具扩展边界

工具控制器管理激活、退出、输入路由、指针捕获和手势结束。
具体工具解释输入，持有临时交互状态，提供光标和辅助图形，通过有限的编辑上下文访问能力，
不直接依赖整个 Editor 根对象。SDK 执行模型算法和事务。

区分工具与编辑模式：选择/移动是工具，基础网格/参数关键形是编辑模式。
后续模式复用交互流程，但使用各自的 SDK 操作与能力校验。

第一个工具为基础网格的顶点选择与拖动：

- 使用稳定顶点 ID，调用已有 EditSession::update_positions；单点和多点由传入集合表达。
- 仅支持无普通参数绑定、变形器、BlendShape 和 Glue 依赖的基础网格。
- 其他网格仍可查看，并说明编辑不可用的原因；不静默修改不可见的基础数据。
- 不改变拓扑或 UV，不在此阶段实现镜像、笔刷或自动网格。
- 命中测试和辅助图形需区分屏幕、画布与模型坐标；不把屏幕像素直接写入 SDK。

首期工具默认只编辑当前选中网格：左键选中顶点，Shift 点击增减选区，
空白处点击清除顶点选区；拖动已选顶点时整体移动选中集合，拖动未选顶点先单选再移动。
使用固定逻辑像素命中半径；重叠候选先按屏幕距离、再按稳定顶点 ID 排序，保证选择可预测。
框选、吸附、镜像、按键微移及拓扑修改留待后续。视口平移可先使用中键拖动，
缩放沿用现有命令；触控板和临时手形工具不是首期工具交付前提。

拖动按开始时的坐标加总位移计算目标位置，不在每次鼠标事件中累计舍入误差。
释放时先应用最终指针位置再提交；回到原位置不产生历史，也不清空 redo。
保存、关闭或切换文档命令先取消活动画布拖动；属性编辑则按既有规则提交。

已核实的限制：update_positions 修改 base_positions，不同步关键形。
普通参数绑定存在时求值使用关键形坐标，修改基础位置可能不会改变预览。
后续支持此类编辑时，先确定 SDK 语义，不在 UI 内补领域算法。

## 保存与性能

第一阶段采用后台保存，保存期间冻结该文档的修改，其他标签页仍可操作。
保存前结束属性编辑；活动画布拖动不直接保存候选状态，应先按工具生命周期结束。
保存失败解除冻结并保留文档及未保存状态。保存成功后才能完成依赖它的关闭请求。
同一文档的写盘操作串行执行。

当前 busy 属于 editor-core 中的单文档 Editor，UI 的 save_to 同步调用 Editor::save，仍会阻塞 UI 线程。
后续需将任务状态移到文档级，并验证 SDK 会话的后台保存移交方式。
暂不开放保存期间继续编辑，也不额外设计快照保存协议。

首期保存实现优先采用所有权移交：core 准备带文档/任务身份的保存任务，
将已结束手势的 Document 暂时交给后台线程，UI 用只读摘要和最后画面显示冻结文档。
任务无论保存成功或返回错误，都必须归还同一个 Document 及结果，保留其撤销历史；
不能通过重新打开磁盘项目重建会话，也不能持有会阻塞 UI 的写锁进行磁盘 IO。
保存期间不能关闭并丢弃该会话；关闭/退出请求须等待任务完成，失败保持打开。
实现第一步用编译检查验证该移交方案的 Send 约束与错误归还路径，再接 UI 调度。
若受 SDK 类型约束阻挡，应报告具体类型和最小调整方案，不能改成直接绕过 SDK 写项目。

性能优先。以 Mao 和 Shirousagi 作为实际工作负载，见 [基准说明](../models/README.md)。
后台标签页停止持续渲染，优先保留近期模型的预览资源；缓存预算和回收策略依据测量确定。
完整模型测导入、渲染、切换和内存；顶点工具用符合编辑条件的基础网格验证。
尚未采集性能数据，不能把资源体积当作运行内存或交互性能结论。

多文档缓存必须隔离不同文档中相同 asset_id 的资源；内容哈希相同的不可变纹理可共享。
当前 MetalSceneRenderer 会清除不属于本次 scene 的纹理，不能直接复用此策略后宣称具有双模型热缓存。
初版缓存策略应根据两模型基线决定，不强制后台模型持续持有全部资源。

布局与快捷键配置使用带版本的独立文件，损坏时回退默认并给出提示；写入使用临时文件后替换。
配置放在 macOS 应用配置目录，测试可注入临时目录，不写进模型项目。
首期恢复面板布局和快捷键，不恢复未保存文档或上次打开的标签页。

## 实施顺序与验收

1. 分离文档会话与工作区，加入多模型标签页及按文档保存/关闭流程。
2. 建立统一命令入口、默认键位与作用域，接入原生菜单、焦点路由和快捷键配置。
3. 接入 Kit Dock 和共享工具面板，面板操作接入同一命令体系。
4. 建立 CanvasView、共享坐标变换、分层失效与版本同步，再接入工具生命周期、基础顶点拖动及工具快捷键。
5. 完成后台保存、布局持久化，并采集双模型性能基线。

验收应覆盖：

- 两个模型切换后选区和视口独立恢复，属性面板指向正确文档。
- 编辑、Undo/Redo、保存和任务结果不会串到其他文档。
- 菜单、按钮和快捷键对同一命令执行相同行为，启用状态及显示键位一致。
- 输入框中的文本编辑和输入法组合输入不触发工具或文档历史；文本 Undo 不会穿透到文档。
- 模态对话框阻断底层快捷键；Esc 只取消当前交互；失焦和按键重复不产生额外操作或遗留状态。
- 切换标签页后命令作用于正确模型；保存中的文档禁止修改，其他文档的快捷键仍正常工作。
- 快捷键覆盖、取消绑定和恢复默认在重启后生效，冲突或无效配置不会破坏上一份有效绑定。
- 调整 Dock、改变画布尺寸和显示倍率后，模型、辅助图形和命中位置保持一致。
- 悬停/选择只更新辅助层，视口变化复用模型场景；用计数或追踪数据证明没有额外模型求值和纹理上传。
- 故意延迟、乱序交付渲染结果时，旧帧不会串到其他文档，也不会与错误版本的辅助图形混合。
- 一次拖动只提交一次历史，取消或无变化手势不产生历史。
- 切换文档、失焦和关闭时没有悬空手势，模型变化后没有失效选区引用。
- 保存一个模型不阻塞另一个模型的操作，失败不会丢失当前文档。
- 重启可恢复面板布局，重置可回到默认布局。
- 记录单模型和双模型的交互、切换及资源占用数据，作为后续回归基线。

纯状态、事务、命令可用性和快捷键配置规则使用自动化测试；原生焦点、输入法、菜单按键显示、
指针交互、Dock 和视觉表现由用户手动验证。
自动恢复、插件系统和更复杂的跨文档能力不属于本轮已确认的交付范围。

## 实现交接与完成标准

按上述顺序逐步交付，每步都保持应用可编译、已有行为可用。先阅读本文件、
document-editing.md、models/README.md，再检查对应源码；不重做已经迁入 core 的 Editor。
不要因拆模块引入通用插件框架、第二套历史或全局事件总线。

开工时先记录单模型现有行为和性能输入，做两项短验证：Kit 的键位覆盖/解除绑定机制，
Document 后台保存的所有权移交。能力存在不代表集成行为已验证；这两项不需要用户重新作产品选择，
但真实库限制必须在相关步骤扩大实现前说明。

| 交付步骤 | 最小验证结果 |
| --- | --- |
| 工作区 | 两个独立会话；打开失败、同路径重复打开、保存失败/取消关闭、异步结果目标错误的测试 |
| 命令与键位 | 可用状态、配置覆盖/取消/冲突/默认回退测试；实际菜单与输入焦点路由手动检查清单 |
| Dock | 保存/恢复/重置布局；损坏配置回退；工具面板关闭不销毁模型 |
| 画布与工具 | 坐标往返、多倍率、显示版本配对、手势取消/提交/no-op 历史测试；原生画布手动检查清单 |
| 保存与性能 | 同一会话后台保存后历史保留、失败原文档归还、其他文档可操作；可复现基线报告 |

运行 cargo test --locked --workspace、cargo fmt --all -- --check 和 git diff --check。
不为代码结构本身写镜像测试；重点验证跨文档隔离、事件优先级、状态转换和失败路径。
沿用项目约定，不通过 computer-use 自动验证 UI；未进行的原生交互验证必须列为待人工验证，不能写成已通过。

性能报告至少记录机器、构建配置、显示倍率、画布尺寸、模型路径、HUD 状态、
采样次数和统计方法；区分首次导入/显示与重复操作，记录帧耗时分位数、切换延迟、进程/GPU 内存。
先采集再提出可执行的性能预算；没有现成阈值不阻止开工，但不能以“看起来流畅”宣告性能验收完成。
受硬件或人工验证条件限制的项目明确标为未验证，并交付复现方法。

交付说明需列出已完成步骤、验证结果、尚未通过的验收项和剩余限制；不要仅以代码编译通过宣告整个阶段完成。
