# 参数与参数组管理设计

状态：2026-10-07 已接入核心命令与编辑器界面。覆盖参数与参数组的新增、编辑、删除，以及它们与属性面板、拖拽排序、撤销重做的关系。

将现有单独的新增参数流程扩展为完整管理能力：参数创建与编辑共用表单和业务校验，参数组具有独立表单；删除参数先检查使用关系，删除分组默认保留成员。所有持久修改通过 zipzi-editor-core 命令进入 SDK 事务。

## 现有实现与缺口

| 层次 | 已有能力 | 本次需要补齐 |
| --- | --- | --- |
| 参数表单 | `ParameterForm`、创建校验、文档隔离、创建后定位 | 编辑模式、目标身份、变化检查、依赖反馈 |
| 属性与检查 | 核心支持参数字段编辑；属性面板展示当前检查对象 | 属性面板提供编辑与删除入口，核心字段编辑与表单共用规则 |
| 分组和排序 | 嵌套展示、空组展示、参数跨组拖动、同级分组排序 | 顶层新建组、组字段编辑、已有子组移至顶层、解散组 |
| SDK | `create_parameter`、`replace_parameter`、`create_parameter_group`、`replace_parameter_group`、`set_parameter_group` | 编辑器业务组合与结构化错误 |
| 删除 | `erase_object` 能删除参数和分组，但拒绝仍被引用的对象 | 区分显示条目与实际使用关系，组合清理和删除事务 |

现有 `replace_parameter` 会用候选参数校验普通绑定、场景绑定、Glue、BlendShape 关键值表及约束。参数自己的 CDI 显示条目也会被 `references_to` 返回，所以“没有绑定的新参数”仍不能直接调用 `erase_object` 删除。

代码依据：[参数创建](../crates/zipzi-editor-core/src/parameter.rs)、[创建表单](../crates/editor/src/panels/parameters/form.rs)、[属性编辑](../crates/zipzi-editor-core/src/document.rs)、[属性权限](../crates/zipzi-editor-core/src/objects.rs)、[排序](../crates/zipzi-editor-core/src/sorting.rs)。相邻 SDK 仓库的 `modules/zipzi-core/src/document/parameters.rs`、`references.rs` 和 `modules/zipzi-sdk/src/edit/cdi.rs` 定义底层行为。

## 操作入口与目标

| 操作 | 界面入口 | 提交后的行为 |
| --- | --- | --- |
| 新增参数 | 保留工具栏现有新增按钮；组菜单提供“在此组新增参数” | 追加到目标组末尾，展开路径、滚动定位并聚焦新参数 |
| 编辑参数 | 参数行右键菜单或更多菜单；属性面板“编辑参数…” | 保留 UUID，刷新字段；跨组时定位到新位置 |
| 删除参数 | 参数行菜单、属性面板操作区 | 展示使用关系；允许删除时确认并执行 |
| 新增参数组 | 工具栏新增分组按钮 | 创建顶层空组并定位、检查新组 |
| 编辑参数组 | 组菜单、属性面板“编辑分组…” | 修改名称、分组 ID；保留已有成员与层级 |
| 删除参数组 | 组菜单、属性面板操作区，文案“删除分组，保留内容…” | 直接参数和直接子组移到其父级，移除该组 |

工具栏新增参数默认未分组，新增组默认顶层；仅从组菜单发起时传入明确的组上下文。延续当前组标题点击展开折叠、信息按钮检查属性的行为。参数滑条和数值输入继续负责预览，编辑入口放在独立菜单中。

“未分组”是虚拟标题，不能重命名、删除或作为分组 UUID 保存；它可以提供新增参数入口，实际归属为 `None`。参数组不增加画布对象选区，也不与参数焦点混为一谈。行菜单捕获点击行的 UUID，全局编辑命令使用当前检查目标，不能因为残留参数焦点而误编辑另一行。

六种操作均要求活动文档可编辑；无文档、保存中、退出中、模态冲突时不可发起。打开弹窗前结束当前滑条交互及待提交编辑。编辑和删除同时检查对象存在性与现有锁定规则。

## 参数表单

复用一个 `ParameterForm`，通过 `Create` 与 `Edit` 模式决定初值、标题和提交命令。表单保留名称、参数 ID、最小值、最大值、默认值、精度、类型、循环和所属组，沿用现有紧凑布局。创建按钮为“创建”，编辑按钮为“保存”。

内部 UUID 始终不可编辑，用户看到的参数 ID 对应 `runtime_id`。编辑初值从模型原始字段读取，不从经过格式化的列表文本或名称回退值读取。数值使用可往返的 `f32` 文本，精度设置不截断保存值。

创建保留现有默认值和建议 ID；编辑时唯一性检查排除当前 UUID，仍排除其他参数和未解析 CDI 条目的 ID。名称和 ID 去除首尾空白后必填，允许重复显示名称。数值必须有限，满足 `minimum < maximum`、跨度有限、默认值在闭区间、精度为 0–9。分组必须仍存在。

| 修改内容 | 建议语义 |
| --- | --- |
| 名称、精度、循环 | 更新参数配置；精度不改变关键值或预览值的数值精度 |
| 所属组 | 保留参数及绑定身份，移至新组成员末尾；沿用拖拽排序的顺序规则 |
| 默认值 | 修改模型默认值；无显式预览覆盖时使用新默认值，已有覆盖保留 |
| 范围 | 保留既有关键值坐标；若新范围让绑定或约束非法则拒绝，并展示受影响对象 |
| 类型 | 无不兼容绑定时允许切换；普通与 BlendShape 绑定不自动转换 |
| 参数 ID | 保留 UUID 与已解析引用，按现有导出机制处理；显示外部调用需要更新 ID 的提示 |

例如把范围从 `[-1, 1]` 改为 `[0, 1]`，而某绑定含 `-1` 关键值，应指出该绑定并拒绝保存。扩大范围不会自动重排关键值。范围和默认值一起提交，避免逐字段修改时经过非法中间状态。

范围改变后，显式预览覆盖在新范围内则保留，越界则夹紧到边界；新默认值不覆盖显式预览。预览不作为新增历史项，撤销重做后按恢复的范围再次协调。既有动作、表情、物理中的数值不做批量重映射，其实际合法性由各领域校验决定。

现有 SDK 的 `PreviewState::retain_parameters` 只移除已删除参数的覆盖，不负责范围夹紧；实现时需补充范围协调，并覆盖提交、撤销和重做三条路径。

属性面板提供完整编辑入口；核心既有的字段编辑命令通过同一业务校验执行单字段补丁。任何入口都不能绕开范围、身份和依赖约束。编辑内容规范化后无变化时禁用保存，核心命令也执行无变化短路。

## 参数删除

建议本次交付“清理自身显示信息后删除未被使用的参数”。仍被使用的参数可以打开删除界面查看原因，但不能提交。自动删除绑定、将多轴绑定降维、烘焙当前形变属于独立操作，不能隐含在删除参数里。

删除界面显示参数名称和 ID，以及按类型分组的使用关系列表。检查必须覆盖普通绑定、场景绑定、Glue、BlendShape 表及约束、组合参数集、动作轨道、表情、物理和 model3 设置；不能只依赖面板当前显示的直接绑定数量。可定位的引用提供跳转，其他引用至少显示类型、名称或路径。

删除自身 `Resolved` CDI 显示条目属于本操作的必要清理；条目携带的扩展随条目删除并可撤销。组合参数集和其他资源引用属于使用关系，保留它们并阻止删除，不静默改写。

执行顺序为：重查目标和使用关系，在同一个 SDK 事务内移除该参数的显示条目，再调用 `erase_object`。底层引用检查作为最终保护；任何失败回滚全部清理。未解析条目、其他参数、分组和其他扩展保持原样。

删除成功清理该参数的预览覆盖、焦点及失效检查目标，沿用上下文协调规则；保留无关对象选区与绑定上下文。确认框明确写“删除参数”，取消为默认安全焦点，输入框里的 Delete/Backspace 不触发对象删除。

## 参数组表单与删除

`ParameterGroupForm` 同样具有创建与编辑模式，只提供名称、分组 ID。UI 暂不开放嵌套创建或父组选择，核心模型及 API 继续支持嵌套。分组拥有自己的内部 UUID 与 `runtime_id`；运行时 ID 在分组命名空间内唯一，不额外要求与参数 ID 全局互斥。名称必填且允许重复。

创建默认名称“新分组”，建议 ID 为 `GroupNew`、`GroupNew2` 等，界面创建时父组始终为 `None`。编辑已有分组仅修改名称和 ID，不隐式改写导入或历史数据中的父组。

已有子分组可拖到顶层分组的前后，或者拖到“未分组”标题处移至顶层末尾。整个分组及其成员一起移动；撤销恢复原层级与顺序。UI 不允许拖拽引入新的嵌套关系。核心创建与更新仍接受合法父组并保留循环校验。

默认删除语义为“解散当前组，保留内容”：直接参数移到父组成员末尾，直接子组按原顺序提升到父组子组末尾，后代仍属于各自的子组。顶层组删除后，其直接参数进入未分组，直接子组成为顶层组。父组原有成员的相对顺序保持不变。

例如 `脸部 / 眼睛 / 瞳孔` 中删除“眼睛”，其直接参数移入“脸部”，“瞳孔”变成“脸部”的子组，瞳孔中的参数不变。界面说明直接参数数量、未解析显示条目数量和直接子组数量，避免用递归参数计数描述实际迁移数量。

一次候选显示信息更新同时迁移所有 `Resolved` 与 `Unresolved` 成员、提升直接子组并移除目标组；不能逐步发布出缺失父组或悬空成员关系。删除组本身的扩展随组删除，其他条目和组的扩展保留。对 SDK 对象生命周期的失效事件需验证；如果直接替换显示信息不能完整处理句柄失效，应封装专用 SDK 操作。

本次不提供“连同所有参数及子组删除”。空组也可以删除，撤销恢复同一 UUID、字段、完整顺序和成员关系。

## 草稿与事务

草稿记录 `DocumentId`、目标 UUID、打开时的持久文档版本，以及创建时的明确分组上下文。预览值变化不应使草稿失效；发生持久修改、目标删除或文档切换时，保留输入并要求重新载入，不自动把旧草稿覆盖到新状态。

“重新载入”由用户明确触发，用最新模型替换草稿并更新版本基线；该动作会丢弃尚未提交的输入，按钮旁说明这一点。创建草稿同样携带版本基线，不能仅依赖 UI 的提交前检查。

按钮、Enter 和菜单使用相同提交路径。提交时再次校验文档、目标、版本、可编辑状态、字段和依赖；用完成状态防止重复回调。失败保留草稿、显示字段错误或带引用列表的业务错误；取消、Esc 和关闭丢弃草稿。弹窗外点击不关闭。

每次操作最多一条历史；参数修改和换组必须属于同一事务，解散组的迁移与移除也必须属于同一事务。新增在提交时分配 UUID，重做恢复同一 UUID。失败、取消和无变化提交不改变 dirty 状态，不生成本次操作历史；打开弹窗前完成的旧编辑仍属于旧操作。

导入文件中的未知扩展需要保留。当前项目导出器会对含不透明扩展的 ID 命名空间变化报错，原生项目保存与外部格式导出并不等价。涉及新建、删除或修改 runtime ID 的操作，在候选结果上检查相关导出诊断，并将新增的不兼容提示给用户；已有诊断与本次新增诊断区分展示。不清除来源快照，也不宣称未知字段已经迁移。本方案允许保留原生项目编辑结果，外部导出继续遵循现有错误规则。

## 代码组织

保持界面命令与持久操作分层。界面命令打开草稿或删除预览，`EditorCommand` 携带完整意图；所有菜单和属性入口共用业务实现。

| 界面命令 ID | 核心操作 |
| --- | --- |
| `parameter.create` | `CreateParameter(draft)`，保留现有命令 ID |
| `parameter.edit` | `UpdateParameter { id, draft, expected_version }` |
| `parameter.delete` | `DeleteParameter { id, expected_version }` |
| `parameter-group.create` | `CreateParameterGroup(draft)` |
| `parameter-group.edit` | `UpdateParameterGroup { id, draft, expected_version }` |
| `parameter-group.delete` | `DeleteParameterGroup { id, expected_version }`，语义为保留内容 |

核心 `ParameterDraft` 供创建和更新复用；`ParameterGroupDraft` 承载三个组字段。用 `ParameterValidationError` 取代仅适用于创建的错误名称，补充目标缺失、版本失效、依赖冲突、父组循环等结构化错误。删除预览是只读查询，不创建历史。

`parameter.rs` 负责参数管理，独立 `parameter_group.rs` 负责组管理。UI 将 `create.rs` 中通用部分提取为 `form.rs`，另设组表单和删除预览。保留已有输入和按钮测试标识，以免破坏创建流程回归；创建与编辑模式使用不同表单根标识。

排序模块提取可组合的候选更新辅助函数，让更新参数加换组只提交一次，避免直接串联两个各自产生历史的公开方法。创建定位扩展成按参数或组定位。组查询提供原始名称和 runtime ID，列表显示名称另行派生。

六种核心操作都接入 `execute_for` 的活动文档保护、命令可用性、中英文文案和上下文协调。SDK 继续作为最终一致性边界，UI 不直接修改模型。先用现有 API 组合完成；确实缺少生命周期或依赖诊断支持时，再补相邻 SDK 仓库的 API 与测试。

## 实施顺序与验收

1. 提取共享草稿、校验和候选排序更新，完成参数编辑，同时保持现有创建流程和属性快捷编辑可用。
2. 实现分组创建、编辑和已有子组提升到顶层，接入菜单与参数创建归属上下文。
3. 完成参数删除预览及事务、分组解散，接入失效引用与预览状态协调。
4. 补齐核心、GPUI headless 和持久化回归，检查真实窗口的焦点、下拉菜单与定位。

| 验收类别 | 必须覆盖的结果 |
| --- | --- |
| 字段编辑 | 保持 UUID；原 ID 不误报重复；中文名称、有限数值、精度边界、无变化提交、多个关联字段一起修改 |
| 参数依赖 | 普通、场景、Glue、BlendShape 分别验证范围与类型冲突；拒绝后原模型与历史不变 |

| 界面 | 创建和编辑字段一致；取消、Esc、Enter、快速连点；过期草稿与跨文档隔离；锁定规则；长列表及折叠路径定位 |
| 上下文 | 编辑后预览保留或按范围夹紧；删除后焦点和引用有效；无关画布选区与活动绑定保持有效 |

## 建议采用的产品边界

本次完整覆盖六种操作及其历史和持久化。参数被使用时阻止删除并提供定位，分组删除只解散当前组，范围修改不自动缩放关键值，类型修改不自动转换绑定。参数复制、批量编辑、级联删除、绑定降维和范围重映射另行设计。


## 实现与验证记录

参数创建与编辑使用 `form.rs`，分组表单使用 `group_form.rs`，删除预览使用 `delete_confirmation.rs`，行菜单及操作路由使用 `management.rs`。新增 `parameter_group.rs` 和 `parameter_export.rs` 分别负责组事务和候选导出诊断。`NewParameter` 与既有创建命令保持兼容；界面创建使用携带版本基线的 `CreateParameterChecked`，共享草稿和校验通过 `ParameterDraft`、`ParameterValidationError` 暴露。

范围变动的预览协调在 zipzi-editor-core 完成，无需改动 SDK。分组解散先迁移成员，再通过 `erase_object` 移除组，保留 SDK 对象生命周期行为。重新载入按钮仅在文档版本变化后出现。导出错误按已有和本次新增区分，原生项目仍可保存。

核心新增 7 项回归，覆盖编辑事务、身份、组排序与层级、删除、预览、文档隔离、导入未解析条目与扩展，以及导出预检查。界面新增 4 项回归，覆盖参数编辑删除、分组管理、取消和草稿重新载入。完整工作区测试通过 260 项、忽略 3 项；另通过真实 Metal 无窗口截图验证，并检查新增参数编辑、创建分组和删除分组弹窗。

### Editor 内的表单对话框复用

`crates/editor/src/ui/form_dialog.rs` 组合 Kit 的 Dialog、DialogFooter 与按钮，提供 `FormDialogView`、`FormDialogState` 和统一的打开入口。业务表单继续持有强类型草稿和控件，不引入动态字段描述或表单 schema。

- 公共层管理 Editing → Submitting → Closed 生命周期。失败回到 Editing 并保留草稿与错误，成功或取消后拒绝再次提交。按钮与单行输入 Enter 走同一入口；下拉选择和多行输入不接入该 Enter 桥接。
- 业务表单通过 `set_validation` 提供校验结果与是否允许提交修改。创建和删除确认无需修改草稿，编辑按标准化后的草稿比较。每次执行命令前仍重新校验，不依赖缓存授权修改。
- 初始输入焦点由调用方指定。删除确认聚焦取消，取消按钮使用 Kit 的 BaseButton 保留调用方焦点句柄。失败由表单定位具体错误字段；Esc 和取消按钮使用 Dialog 的取消流程，遮罩点击不关闭。现阶段沿用直接取消，不额外提示丢弃修改。
- `ParameterDialogSession` 属于参数管理层，负责文档身份、模型版本、可用状态、命令执行和显式重新加载。公共 UI 模块不依赖 DocumentId、参数模型或 EditorCommand。
- 校验与导出诊断在输入变化、源文档/模型版本/可用状态变化时更新。正文和 footer 读取同一结果，渲染不执行候选模型导出。普通重绘不触发重复诊断。
- `ParameterGroupForm` 只处理组的创建和编辑；`DeleteConfirmation` 没有输入实体和 dirty draft，独立展示删除影响和引用。参数删除策略、组嵌套能力及撤销事务保持原有业务规则。

接入其他表单时，实现 `FormDialogView` 的状态访问、提交及错误格式化，在输入/数据源变化后更新校验状态并通知视图，再调用 `form_dialog::open`。当前提交接口同步执行，与 EditorCommand 一致；异步保存应另行设计取消和结果归属协议。

重构验证：新增 4 项 UI 回归，覆盖错误字段焦点与重复 Enter、标准化后无变化的编辑、删除确认的取消焦点与 Enter、源数据变化后的缓存失效和重新加载。完整工作区测试通过 267 项、忽略 3 项；格式与 diff 检查通过，真实 Metal 截图通过，并检查参数编辑、组创建和组删除弹窗。
