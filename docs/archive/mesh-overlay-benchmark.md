# 大网格覆盖层：GPUI Path 与专用 Metal 纹理

本 benchmark 比较三种覆盖层绘制：当前编辑器已合批的 GPUI Path；Metal 边线纹理＋GPUI 顶点标记；Metal 边线与顶点标记的完整纹理。两种纹理方案均交给 GPUI 合成。实验实现位于独立 example；后续正式 editor 已接入完整 Metal 覆盖层，见 [重构说明](mesh-overlay-rendering.md)。正式方案的不可变资源管理与本 benchmark 不同，性能数字不能直接套用。

## 运行

```sh
./scripts/mesh-overlay-benchmark.sh target/mesh-overlay-run 100
# 快速检查：采样 3 次，8×8、32×32 网格，640×400 物理像素
./scripts/mesh-overlay-benchmark.sh target/mesh-overlay-smoke 3 8,32 640x400
```

参数为输出目录、每种实现的正式采样次数、网格单边 cell 数列表、物理分辨率列表。输出目录不能已有 `samples.jsonl`。使用 Release，脚本关闭本次进程的 Metal HUD；正式采样应避开其他编译、GPU 压力任务。无需打开编辑器窗口，不使用 computer-use。

## 对照条件

- GPUI：直接复用生产代码 `mesh_edges::paint_edges`，每 4,096 条边分块；包含坐标变换、PathBuilder tessellation、Scene 排序、实例数据写入及 GPUI Metal 渲染。
- Metal 边线纹理（`metal_texture`）：缓存共享顶点和唯一边索引；vertex shader 为每条边展开两个 butt-cap 三角形，绘制到透明 BGRA8 纹理。之后通过现有 `SurfaceSource::MetalTexture` 交给 GPUI 合成，完整计入这两个 GPU command 的耗时。
- Metal 完整覆盖层（`metal_full_overlay`）：先绘制并 resolve 同样的 4× MSAA 边线，再用单采样 pass 把实例化方形顶点标记画到同一纹理，与 GPUI 无圆角/无边框 Quad 的采样方式一致。两次 pass 在同一 command 内，均计入 GPU 和 CPU 提交时间。GPUI 只合成背景与完整纹理。
- 三者共享同一个 GPUI Metal device/queue 和 headless renderer。固定 1 个逻辑像素线宽、同色半透明、4× MSAA、相同画布 content mask、背景与像素比 2。不会使用无抗锯齿的硬件细线来获得不同画质的速度优势。
- 使用规则三角网格，每个 cell 两个三角形，边去重。两边共用预先构造的边索引，不包含 SDK 求值和拓扑生成。
- `view`：每帧平移、缩放；专用方案沿用 GPU 顶点/索引缓冲，仅更新变换参数。
- `deform`：每帧所有顶点变化，视口固定。变形结果的 CPU 生成对两者共用，位于计时外；专用方案上传新顶点的成本位于计时内。
- 每种负载另测 `handles=false/true`。启用时前两组由 GPUI 绘制全部顶点标记，第三组由 Metal 实例化绘制。普通标记 6×6、悬停标记 8×8 逻辑像素；每 37 个顶点选中一个，悬停索引随帧更新。选中图案固定，由索引计算；未计入任意选中集合的维护/上传。密集网格的标记可能相互覆盖。关闭标记时两种 Metal 方法走相同绘制路径，作为重复对照。
- 三种方法按 ABC、BCA、CAB、CBA、BAC、ACB 六种顺序循环，各预热 10 次；正式采样 30 次时每种方法在每个位置出现 10 次。每帧完成后才复用缓冲及目标纹理；不让任一方通过积压异步 GPU 任务得到虚假的低耗时。

默认网格规模为 208、3,136、12,416、49,408、197,120 条唯一边，分别对应 81、1,089、4,225、16,641、66,049 个顶点。分辨率为 1280×800、2560×1600。

## 计时口径

| 字段 | 包含内容 |
| --- | --- |
| `prepare_ms` | 已求值几何到 GPUI Scene 准备结束；GPUI 包含边线路径构建，Metal 包含变形顶点上传 |
| `overlay_submit_ms` | 专用边线 pass 的 CPU 编码和提交；GPUI 组没有该 pass |
| `gpui_submit_ms` | GPUI 编码、实例缓冲写入与提交 |
| `cpu_submit_ms` | 从准备开始到全部 GPU command 提交返回 |
| `complete_ms` | 从准备开始到最终合成 command 完成等待返回；包含排队与 CPU 唤醒 |
| `overlay_gpu_ms` | 专用边线 command 的 GPU 时间，GPUI 组为 0 |
| `compose_gpu_ms` | GPUI command 的 GPU 时间；GPUI 组包含路径绘制，专用组包含纹理合成 |
| `gpu_union_ms` | 同一帧两个 command 的 GPU 时间区间并集长度，扣除重叠，避免重复计算 |
| `gpu_sum_ms` | 原始 command 时间之和，仅供核对，不能把它当成组合 GPU 延迟 |
| `gpu_span_ms` | 首个 command 的 GPU 开始到最终 command GPU 结束，包含两段之间的间隙 |

使用 Metal `GPUStartTime/GPUEndTime`，检查每个 command 完成状态与时间戳。编译 shader、初始化缓冲和目标纹理、PNG 回读、日志写入均在正式计时之外。额外记录候选方案初始化时间与资源大小。

这是无窗口、单帧在途的渲染完成延迟比较。背景为相同色块，未运行模型本体的 zipzi-render、整个编辑器布局、输入处理或 drawable 呈现；不能把这些结果直接解释为编辑器 FPS 或 input-to-photon 延迟。

## 正确性与输出

每个规模、尺寸、负载、标记配置，在第 0 和 17 帧分别将两种 Metal 方案与 GPUI 原图做原生像素比较，再开始采样。这两帧分别覆盖已选中与未选中顶点的悬停。允许浮点计算/采样边界的少量差异，要求 RGB 平均绝对误差 ≤0.5/255，通道差异 >4/255 的像素比例 ≤1%；未通过即中止。保留两张 PNG、实际误差与未筛选的逐帧数据。

- `metadata.json`：设备、参数、工作负载与采样约定。
- `samples.jsonl`：包含预热的所有逐帧测量、执行顺序（`pair_order` 在新版为 0..2）、路径数量和批次。
- `summary.json`：排除预热后的 P50/P95/P99/最大值和超出 8.33 ms 的样本数。
- `quality.json`、`qa-*.png`：两种候选实现相对 GPUI 的像素比较与原图，包含方法名和帧号。
- `setup.json`：额外初始化成本和显存资源大小。
- `environment.txt`、`build.log`、`run.log`：执行环境与过程记录。

GPUI 原有 headless `render_scene()` 没有返回 command，且每次重新分配路径中间纹理。新增仅限 test/bench 构建的 `submit_scene_for_benchmark()` 返回已提交 command，并按尺寸复用中间纹理，避免该测试入口的分配行为干扰比较。正式窗口渲染流程保持原样。

本实验覆盖固定拓扑的边线覆盖层，不覆盖拓扑增删、随机长边的大量自交、模型纹理/遮罩或后台预览的帧合并。候选实现依靠“上一帧完成再复用”保证单份缓冲和纹理安全；若用于正式异步预览，仍需在途资源管理、模型/覆盖层版本一致性及交互响应验证。

## 2026-09-28 首轮两组实测结果（历史基线）

此归档使用旧版 AB/BA 顺序、固定 6×6 标记，不含悬停变化与第三种方法。以下数字保持原始记录；新版三组结果单独归档，不混合计算。

Apple M4、16 GB、macOS 27.0，Release。每种配置 10 次预热、30 次正式采样，共 2,400 个有效样本。暂停 Dev 应用，每秒监测 cargo/rustc，本轮未检测到并行编译；完成后已恢复 Dev。原始数据、环境和校验值见 [归档](benchmarks/2026-09-28/mesh-overlay/README.md)。

以下均为毫秒，GPUI 指当前已合批的 Path，专用纹理包含 Metal 边线 pass 和 GPUI 合成。

### 只画边线，平移缩放，2560×1600

| 唯一边数 | GPUI 完成 P50 | 专用纹理完成 P50 | 完成耗时比 GPUI/专用 | GPUI GPU P50 | 专用纹理 GPU P50 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 208 | 0.768 | 0.630 | 1.2× | 0.397 | 0.321 |
| 3,136 | 1.324 | 0.679 | 1.9× | 0.528 | 0.376 |
| 12,416 | 4.004 | 0.839 | 4.8× | 0.779 | 0.526 |
| 49,408 | 14.041 | 1.594 | 8.8× | 1.648 | 1.016 |
| 197,120 | 55.879 | 3.266 | 17.1× | 4.153 | 2.595 |

GPU 列使用 command 时间区间并集；它是 GPU 时间戳口径，并非硬件占用率。约 20 万条边时，CPU 准备及提交 P50 从 48.975 ms 降至 0.031 ms，GPU 从 4.153 ms 降至 2.595 ms；完成耗时约 17.1 倍的差异主要来自省去 CPU 路径构建和 GPUI 实例数据准备，不能称为 GPU 本身快了 17 倍。

### 最大规模：197,120 条边，66,049 个顶点

| 分辨率 | 负载 | 全部 GPUI 标记 | GPUI 完成 P50 / P95 | 专用纹理完成 P50 / P95 |
| --- | --- | --- | ---: | ---: |
| 1280x800 | 平移缩放 | 关 | 61.261 / 74.608 | 4.247 / 7.412 |
| 1280x800 | 平移缩放 | 开 | 751.701 / 851.838 | 931.579 / 1041.407 |
| 1280x800 | 全部顶点变形 | 关 | 60.633 / 102.076 | 5.705 / 7.536 |
| 1280x800 | 全部顶点变形 | 开 | 568.905 / 764.496 | 643.351 / 708.169 |
| 2560x1600 | 平移缩放 | 关 | 55.879 / 62.650 | 3.266 / 7.404 |
| 2560x1600 | 平移缩放 | 开 | 746.029 / 862.426 | 903.713 / 1062.746 |
| 2560x1600 | 全部顶点变形 | 关 | 52.847 / 57.652 | 3.616 / 8.454 |
| 2560x1600 | 全部顶点变形 | 开 | 501.016 / 734.001 | 542.928 / 606.839 |

变形组包含专用方案的逐帧顶点上传，仍有明显边线收益。保留全部 GPUI 标记时，两边的 CPU Scene 准备都很重，候选方案甚至更慢：2560×1600 平移缩放组准备 P50 分别为 721.288 ms 和 898.205 ms。两者虽然有相同标记，但边线 primitive 的种类和数量不同，不能假设 Scene 准备成本也相同。此实验定位到 Scene 准备阶段，尚未通过函数级采样确定差异根因。

因此，大规模场景适合继续验证专用 GPU 边线绘制，但只替换边线、保留数万个 GPUI 顶点标记，不能解决完整覆盖层的性能问题。后续应比较标记也批量绘制，以及按可见性/编辑状态减少标记数量的方案。这里的全量密集标记属于压力测试，不能当成实际模型的常态。

40 组像素对照全部通过：最大 RGB 平均误差为 0.00156/255，通道差异超过 4/255 的像素比例最大约 0.0091%；局部最大通道差异为 33/255。使用相同抗锯齿和裁剪，仍允许极少量边界像素差异。

每组只有 30 个正式样本，P95/P99 容易受调度和动态频率影响，P99 等于该组最大值；没有删除异常样本。不同分辨率分段运行，也不能据此推断随分辨率变化的严格单调关系。该结论限于本机、规则网格与这个 headless 测试，不代表完整编辑器 FPS。

## 2026-09-28 三组实测：完整 Metal 覆盖层

新增标记实例化绘制后重新采样三组，含选中颜色和悬停尺寸变化，不复用首轮数字。环境仍为 Apple M4 / 16 GB / macOS 27.0。共 120 个方法配置、3,600 个有效样本；Dev 与监听临时暂停，276 次编译进程检查未发现干扰，结束后已恢复。见 [本轮原始数据与源码快照](benchmarks/2026-09-28/mesh-overlay-full/README.md)。

以下开启全部顶点标记，分辨率 2560×1600，单位毫秒。

### 平移缩放：渲染完成 P50

| 唯一边数 / 顶点数 | GPUI 边线＋标记 | Metal 边线＋GPUI 标记 | Metal 完整覆盖层 |
| ---: | ---: | ---: | ---: |
| 208 / 81 | 0.786 | 0.628 | 0.640 |
| 3,136 / 1,089 | 1.850 | 1.067 | 0.936 |
| 12,416 / 4,225 | 4.690 | 2.298 | 0.976 |
| 49,408 / 16,641 | 29.806 | 28.308 | 1.981 |
| 197,120 / 66,049 | 747.238 | 913.074 | 4.571 |

### 最大规模：197,120 条边＋66,049 个标记

| 负载 | 方法 | CPU 准备及提交 P50 | GPU 区间并集 P50 | 完成 P50 | 完成 P95 |
| --- | --- | ---: | ---: | ---: | ---: |
| 平移缩放 | GPUI 边线＋标记 | 725.342 | 17.074 | 747.238 | 864.763 |
| 平移缩放 | Metal 边线＋GPUI 标记 | 904.989 | 7.252 | 913.074 | 1063.367 |
| 平移缩放 | Metal 完整覆盖层 | 0.059 | 3.957 | 4.571 | 10.295 |
| 全部顶点变形 | GPUI 边线＋标记 | 487.277 | 17.485 | 505.147 | 776.970 |
| 全部顶点变形 | Metal 边线＋GPUI 标记 | 544.934 | 6.670 | 554.059 | 609.826 |
| 全部顶点变形 | Metal 完整覆盖层 | 0.068 | 4.692 | 5.152 | 11.988 |

完整方案的平移缩放完成 P50 为 4.571 ms，变形（包含顶点上传）为 5.152 ms。相比只迁移边线，标记一起迁移后避免了大量 GPUI Scene 准备成本；这支持继续验证完整 GPU 覆盖层。最大规模是非常密集的压力负载，不能把其约百倍的完成耗时差异推广到普通模型。小规模收益很小，且完整方案未必比只迁移边线快。

完整方案的 P95 分别为 10.295 ms、11.988 ms，超过 120 Hz 的 8.33 ms 预算。这个单帧在途的 headless 结果不含模型本体、SDK 求值、窗口呈现与交互响应，也不能承诺稳定 120 FPS。

160 组像素对照全部通过原有容差。完整方案最大 RGB 平均误差为 0.002185/255，差异超过 4/255 的像素比例最大约 0.0091%。个别像素最大通道差异为 208/255，主要新增差异出现在标记绘制；通过全图容差不等于逐像素相同。保留原图供后续检查边界精度，不放宽容差来获得性能结论。

选中图案由固定索引规则生成，悬停通过每帧参数更新；任意选中集合的数据管理、实际鼠标命中、在途纹理复用和真实模型仍待生产接入验证。本次仅扩展 benchmark，没有修改编辑器的正式绘制与交互逻辑。
