# Editor 组件实测记录

日期：2026-09-27。环境：Apple M4、macOS、Retina 2×、gpui-ce fork 的 wgpu → Metal 后端。

运行 `cargo run -p kasane-editor`，点击工具栏 **Components**。组件页提供 Controls / Typography 标签，以及 Compact（760×540）/ Full size（1100×740）窗口尺寸预设。

以下是通过原生窗口实际点击、键盘输入、拖动、滚动和截图观察得到的结果，不是自动化截图快照测试。

| 组件 | 实测操作和观察 | 结果 |
| --- | --- | --- |
| 按钮 | 默认/悬停背景、圆角；Apply 更新状态，随后点击 Disabled 状态不变 | 通过 |
| 标签页 | Controls / Typography 切换，选中背景更新 | 通过 |
| 文本输入 | 初始中英混排；聚焦、End、输入 ` test`、退格，显示 `Layer 01 · 图层 tes` | 通过 |
| 复选框 | 勾选/未勾选图形切换 | 通过 |
| 滑块 | 从 65% 拖到 80%，轨道、圆形手柄、文字和状态同步 | 通过 |
| 下拉菜单 | 独立浮层、边框、阴影；Normal → Multiply；Escape 关闭 | 通过 |
| 场景树 | 展开/折叠、选中第 28 项及选中色 | 通过 |
| 滚动与裁剪 | 30 行列表滚到第 25–30 项，不越过容器；紧凑窗口外层滚动可达底部控件 | 通过 |
| 模态弹窗 | 居中、圆角、阴影、半透明遮罩；背景 Apply 点击不穿透；Confirm 和 Escape 关闭 | 通过 |
| 多语言文字 | 中文、日文、韩文、箭头和勾选符号正常；12 px 与 28 px 字号 | 通过 |
| 长文字 | 固定宽度 260 px 内显示省略号，没有溢出 | 通过 |
| 窗口 resize | 1100×740 → 760×540 → 1100×740，布局、滚动区与渲染持续正常 | 通过 |

本轮没有发现上述场景的 wgpu 渲染故障。接入时修复了上游示例 `TextRun` 缺少 `letter_spacing` 的 API 适配问题；组件按钮显式转移焦点，避免打开弹窗后键盘继续编辑背景输入框。

## 验证边界

- 这些是用 GPUI 元素组装的验证控件，不是完整的生产组件库。滑块和混合模式用于组件状态展示，不改变 Kasane 场景。
- 输入框来自 gpui-ce 示例编辑内核（出处及 Apache-2.0 许可位于 `crates/editor/src/vendor`），只验证了基本输入与退格。中文 IME 组合输入、选区/复制粘贴、撤销、长文本水平滚动未验证。
- 没有补齐完整的键盘导航、Tab 焦点陷阱或无障碍语义。系统 AX 树目前只有原生窗口，组件交互检查使用截图坐标完成。
- 弹窗遮罩只覆盖组件页内容区；不是整个应用级模态。下拉菜单没有自动检测屏幕边缘并翻转方向。
- 未验证 SVG、图片资源、停靠面板、可拖动分隔条、时间轴、其他操作系统或 GPU。

`cargo test --workspace` 继续覆盖现有 Kasane GPU 像素测试；组件交互由本次实机检查覆盖。`cargo fmt --all -- --check` 用于格式检查。
