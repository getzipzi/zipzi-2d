# Document 面板与参数绑定设计

状态：方案已确认，尚未实现。确认日期：2026-09-30。

本文确定文档内容的浏览方式、独立 Dock panel 的划分、跨面板选择与定位规则，以及参数绑定和关键形的展示方式。后续实现以本文为依据；既有状态与编辑架构见 [Document editing](document-editing.md)。

核心方案是：用多个可自由组合的面板表达 Document，同一对象在不同视角中共享身份；通过关系面板追踪跨类型关系，通过参数和关键形面板完成绑定查看与编辑。单个 target 的常规 keyform 绑定最多允许两个参数轴。

## 设计原则

- 每一种树的缩进只表达一种明确关系。部件归属、变形父子关系和绘制顺序分别展示。
- Document 的内容都应有可访问入口，包括未使用对象和附加配置。专用内容不能仅藏在关系详情中。
- “结构、驱动、资源”是内容分类，可用于窗口菜单和默认布局，不是三个固定的大面板。
- 各个 panel 独立注册到现有 Kit Dock。组合由 Dock 管理，不通过一个巨型 panel 内部的固定页签实现。
- 面板联动依赖文档级共享状态，不依赖面板位置、可见性或是否处于同一标签组。
- 模型修改继续通过 SDK；面板排列、折叠、选择、定位和预览状态不另建模型编辑历史。

## 独立面板划分

下表描述目标职责，不表示相应编辑与播放能力已经实现。专用面板提供列表、局部结构和操作入口；标量属性可由共享属性面板编辑，完整跨类型引用由关系面板查看。

| Panel | 内容与职责 |
| --- | --- |
| 部件树 | Part 层级、归属于 Part 的 Mesh 与 Deformer，以及关联的 Offscreen |
| 变形树 | Deformer 父子关系，以及直接受其变形影响的 Mesh |
| 绘制顺序 | 绘制分组、当前参数状态下求值后的前后顺序与合成关系 |
| 参数 | 参数分组、预览值、直接绑定目标、间接影响与绑定入口 |
| 关键形 | 当前目标的具体绑定、一维或二维 keyform，以及当前预览坐标 |
| BlendShapes | 叠加绑定、共享关键值表、约束与目标 |
| Glue | 连接列表、两端 Mesh、顶点配对、强度与驱动关系 |
| Motions | 动作分组、片段、轨道及轨道目标 |
| Expressions | 表情列表、参数条目、数值与混合方式 |
| Physics | 物理组、输入参数、粒子链与输出参数 |
| Pose | 部件切换组、成员与关联部件 |
| 资源 | 纹理、附加文件、资源信息与使用情况 |
| 属性 | 当前选中对象自身的属性；选中文档时展示画布、模型设置、命中区域、显示信息等文档内容 |
| 关系 | 当前对象的归属、引用、直接驱动、继承影响和反向使用关系 |

属性与关系是两个独立 panel，默认可以组合为同一个 Dock 标签组，随时拆开并排查看。

参数与关键形同样是两个独立 panel。它们可以上下排列、左右排列、组成标签组或分别放在画布两侧，不要求始终同时可见。

## Dock 组合与默认布局

默认布局只提供起点，不限制重新组织：

| 位置或分组 | 默认内容 |
| --- | --- |
| 中央 | 保留现有固定的模型标签页与画布 |
| 左侧标签组 | 部件树、变形树、绘制顺序 |
| 右侧标签组 | 属性、关系 |
| 下方区域 | 参数与关键形上下排列 |
| 行为配置标签组 | Motions、Expressions、Physics、Pose，按需显示 |
| 其他专用面板 | BlendShapes、Glue、资源按需打开，可自由归入任意标签组 |

各个工具面板支持现有 Dock 的拖拽、分组、拆分、调整大小、折叠与隐藏；布局保存和恢复沿用现有机制。窗口菜单提供每个面板的独立入口和布局重置。

隐藏面板不清除对象选区、参数焦点、活动绑定或预览值。切换文档恢复对应文档的上下文；窗口布局不随每个文档切换。

## 三种结构视角

### 部件归属

由 Part 的父子关系构成骨架，Mesh 和 Deformer 按各自的部件归属展示。现有 mesh tree 需要补上 Deformer 的部件归属。

Offscreen 显示为对应部件关联的合成对象，并标明类型。Part 自身的可见性、绘制等语义仍保留在属性和关系中，不能按无语义文件夹处理。

没有部件归属的对象进入明确的“未归属”分组。引用缺失和循环等异常需要单独标识，不能无提示地当作普通根节点。

### 变形层级

Deformer 按变形父级组织，Mesh 按直接变形父级挂载。这里的父子关系只表达变形链，不改变对象的部件归属。

无变形父级的对象仍有入口。相同 Mesh 出现在部件树和变形树时，代表同一个对象，不产生副本。

### 绘制顺序

按实际绘制分组与当前参数求值结果展示，并明确标注前景与背景方向。绘制分组可以独立于部件层级，不能直接把部件树的行顺序解释为最终绘制顺序。

该面板首先提供查看与定位。修改基础绘制顺序需要明确的编辑操作；不能通过拖动当前求值后的列表，隐式重写基础顺序或关键形。

结构树中，点击行选中对象，点击展开箭头才折叠。后续支持重挂载时，部件树拖拽修改部件归属，变形树拖拽修改变形父级，分别通过 SDK 校验与提交。

## 关系面板

关系面板跟随当前检查的对象，按语义组织关系：

| 关系类别 | 展示内容 |
| --- | --- |
| 归属 | 部件路径、变形父级等分别列出 |
| 直接影响来源 | 常规绑定、BlendShape、直接变形父级、遮罩、Glue 等 |
| 间接影响来源 | 显示可展开的路径，例如参数 → 绑定 → 父级 Deformer → 子级 Deformer → Mesh |
| 影响目标与使用者 | 子级、驱动目标、遮罩使用者和反向资源引用 |
| 使用的资源 | 纹理、共享关键值表、约束等 |

关系名称必须说明具体作用，例如“使用纹理”“为其提供遮罩”“通过此绑定驱动”。Glue 明确展示 A、B 两个连接端；遮罩展示来源和使用者；这些关系不能伪装成对象归属。

默认展示直接关系，间接影响按需展开。多个路径到达同一对象时，目标计数按对象去重，路径仍可分别追踪。不默认绘制整份文档的全量关系网。

点击关系中的对象或绑定可导航到相应上下文，并支持返回。专用面板与关系面板使用同一份对象和引用信息。

保存的关系与当前生效状态分开显示。对象禁用、权重为零、动作未播放或能力尚未支持，不代表绑定或引用不存在。物理配置要区分输入和输出，动作与表情要能追踪到其写入目标。

## 共享状态与联动

以下状态在活动文档中共享，但不能折叠成一个单一的“选中 ID”：

| 状态 | 含义 |
| --- | --- |
| 对象选区与编辑目标 | 当前选中的模型对象；关键形写入受具体目标与绑定约束 |
| 参数焦点 | 当前关注、查看绑定范围的参数 |
| 活动绑定 | 当前关键形面板正在展示的具体绑定 |
| 检查与导航上下文 | 属性、关系或专用列表正在检查的对象，以及关系导航返回位置 |
| 预览值 | 文档共享的参数值，供画布和参数控件同步使用 |

联动规则如下：

1. 在部件树、变形树、绘制顺序或画布选中同一对象时，各视图同步选中状态；属性与关系展示该对象，参数面板指出相关参数。
2. 点击参数名称或绑定摘要只改变参数焦点与检查内容，保留已有 Mesh/Deformer 选区和编辑目标，不自动选中全部受影响对象。
3. 点击参数下的具体绑定目标，才切换对应编辑目标和活动绑定。关键形面板显示该绑定自己的参数轴与关键形。
4. 从关系或专用面板打开一个绑定，定位到同一个关键形面板，不创建另一套绑定编辑状态。
5. 切换对象、参数焦点或面板，不重置文档预览值。拖动参数修改的是全局预览值，所有相关对象都会受影响；活动绑定只限定当前查看和写入的关键形目标。
6. 不兼容的对象切换应清除失效的活动绑定或显示明确的空态，不能把前一个对象的关键形继续当成当前对象的数据。模型删除、撤销和文档切换时同样校正引用。

联动不能形成相互选择的循环，也不能为了查看参数而不断重置对象选区。控件事件继续绑定创建时的 DocumentId，避免迟到事件写入另一份文档。

## 参数面板

保留滑条、数值输入和预览功能，增加每个参数可展开的绑定摘要，例如：

```text
头部 X    ───●────    15    直接绑定 3 · 间接影响 8
```

摘要中的数字按目标去重，不把关键值数量或路径数量当作对象数量。展开后，直接绑定目标逐项显示对象名称、对象类型、具体绑定、共同参与的参数轴，以及维度和关键形数量，例如：

```text
头部变形器    Deformer    头部 X × 头部 Y    2D · 3×3＝9
前发变形器    Deformer    头部 X             1D · 5
```

间接影响独立展开，显示经过哪个父级变形器等路径。不能将继承父级变化的 Mesh 标为直接绑定目标。

存在活动绑定时，滑条的关键值标记以该绑定的对应轴为准。没有活动绑定时，可以显示跨目标汇总信息，但必须说明它只表示某些目标在该参数值上有关键值，不能据此生成一个用于编辑的 keyform 网格。

常规绑定、BlendShape 叠加和父级继承分别呈现。动作、表情、物理等参数来源也应可通过关系入口追踪。

## 关键形与两轴上限

### 绑定约束

一个 target 的常规 keyform 绑定最多允许两个参数轴。添加第三轴时，UI 阻止操作，SDK 同样校验并返回可读错误，提示“每个对象最多绑定两个参数轴”。不能只依靠界面限制，也不能用多个相互冲突的常规绑定绕过该限制。

这项限制针对单个 target 的常规多轴关键形绑定，不是对象最终受到影响的参数总数。父子 Deformer 可以各自绑定一维或二维参数；BlendShape 叠加和父级继承不会自动合并成当前 target 的更多 keyform 轴。

两轴上限不等于最多九个关键形。每轴关键值数量由绑定决定，总数为各轴关键值数量的乘积。

### 展示与操作

- 一维沿用现有滑条与关键值标记的形态。
- 二维沿用现有二维控制形态；网格数据必须来自当前 target 的具体绑定。
- 始终显示目标名称、绑定类型、轴名称、关键值布局、关键形数量与当前坐标。
- 网格中的每个存储点代表一个完整参数组合。点击关键形同步该绑定全部轴的预览值，保留无关参数值。
- 连续拖动或输入参数值用于插值预览。已有关键形与当前插值位置使用不同标记，不能把插值结果直接标为已存储关键形。
- 从插值预览进入关键形写入时，必须明确具体关键形或创建操作，不能隐式覆盖某个相邻关键形。
- 任意两个参数的联合预览不等于它们共同绑定了同一 target。不能把跨绑定汇总的两组关键值相乘，作为当前对象的可编辑网格。

现有常规绑定要求完整的关键值组合。扩展轴或关键值时，要按 SDK 的完整性规则处理整个组合；不能仅在 UI 上画出缺失节点后假定绑定有效。具体的关键形初始化和生成操作另行设计。

三维切片、三维空间网格及四维以上界面不属于最终方案，不作为后续实现任务。

## 特殊内容的独立入口

Glue、Motions、Expressions、Physics、Pose 和 BlendShapes 都拥有独立 panel，不能只通过某个 Mesh 或参数的关系详情才能找到。未引用、未启用或当前未播放的条目也必须可浏览。

典型导航包括：

- Glue → 两端 Mesh、顶点配对、强度绑定；Mesh → 使用它的 Glue。
- Motion → 轨道 → 参数或部件等目标；参数 → 写入它的 Motion 轨道。
- Expression → 参数条目及混合方式；参数 → 引用它的表情。
- Physics → 物理组 → 输入参数、粒子链、输出参数；参数 → 作为输入或输出使用它的物理组。
- BlendShape → 目标、共享关键值表、约束；共享表或约束 → 使用它的绑定。
- Pose → 部件切换组与关联成员；Part → 引用它的 Pose 条目。

资源面板保留未使用纹理和附加文件。文档级属性入口覆盖画布、模型设置、命中区域、显示名称与分组等元数据。未知或未解析内容保留原始标识和可诊断信息，不虚构已解析目标。

## 实现边界

沿用现有 editor、editor-core 与 SDK 的职责划分：

- SDK 负责持久化模型、编辑语义、两轴限制、事务、引用校验与撤销重做。
- editor-core 负责文档级共享选择、参数焦点、活动绑定，以及供各面板使用的对象与关系投影。
- editor 负责 GPUI 控件、Dock 注册、布局与交互呈现。

需要统一的带类型对象引用和关系索引。关系边区分部件归属、变形父级、绑定驱动、遮罩、Glue 连接和资源使用；从这份信息生成各树、列表和关系详情，不维护多个可独立修改的模型副本。

常规绑定在 UI 中展示参数、目标和关键形之间的联系。多个参数共同参与同一个绑定时，要保留共同绑定的身份，不能仅展开成互不相关的“参数 → 目标”边。

结构和引用投影应按相关文档变更更新；仅预览值变化时更新当前状态和求值结果，避免每次拖动都重新扫描完整文档。隐藏面板不承担必须持续运行的模型逻辑。

## 验收要点

1. 表中所有 panel 都有独立 Dock 身份和窗口菜单入口，能够拆分、组合、隐藏并恢复布局。
2. 属性与关系、参数与关键形分别拆开后，联动行为保持一致；隐藏面板不会丢失上下文。
3. Part、Deformer、参数、绑定、Glue、行为配置和资源都可检查，不再仅 Mesh 能选中查看。
4. 同一对象在部件树、变形树和绘制顺序中可交叉定位；各视角不会混淆父子语义。
5. 参数能列出真实的直接绑定目标，继承影响单列并可追踪路径；从对象也能反查参数。
6. 两个参数分别绑定不同对象时，不会产生虚假的共同二维 keyform 网格。
7. 切换目标后展示该目标的真实轴和关键值布局，保留预览值；关键形点选与参数控件双向同步。
8. UI 与 SDK 均拒绝新增第三参数轴，失败操作不改变模型内容与历史。
9. Glue、Motion、Expression、Physics、Pose、BlendShape 的目标引用与反向引用可导航；未使用条目仍可访问。
10. 缺失引用、未归属、未使用与当前不生效分别可辨认，导航不静默丢失对象。

## 实施前仍需明确的边界

以下事项尚未确定，不影响已确认的面板架构和两轴上限：

- **已有高维文档的兼容策略**：SDK 当前支持更多轴，读取现有工程或导入模型可能遇到三轴以上绑定。需明确是拒绝打开、只读兼容还是显式转换；不得静默丢轴、降维或损坏源数据。两轴写入限制上线前必须明确读写兼容边界。
- **多选批量编辑**：不同绑定布局不能合并成一个虚假网格。相同布局能否批量写入、如何提示部分适用与提交范围，需单独确定；首期可逐绑定检查。
- **关键形创建与初始化**：扩展关键值时如何补齐组合、是否提供生成工具，以及插值状态如何创建新关键形，需单独设计，不从本方案推导隐式生成行为。
- **行为配置的执行工具**：各专用 panel 的入口和关系表达已确定，Motion 播放、时间轴、物理调试等完整工作流的细节不在本文中承诺。
