# 120 Hz 交互优化记录

日期：2026-09-28。目标帧预算 **8.33 ms**。改动同时位于 `kasane-editor` 和相邻的 `kasane-2d`，两边必须一起使用。

## 结果与适用范围

Release 构建下，三个模型/尺寸组合、五种工作负载的完成耗时 P95 均低于 8.33 ms；Mao 完成耗时中位数约 0.62–2.12 ms。GPUI 平移的独立 CPU 测试 P99 为 1.207 ms。

**还不能宣称屏幕端稳定 120 fps。** 4500 个无窗口样本中有 16 个完成耗时超过预算；表中保留所有长尾。测试没有覆盖 AppKit 输入、GPUI GPU 合成、显示提交和扫描输出组成的整条链路，不能把这些阶段各自的分位数相加当作端到端分位数。

### GPUI 主线程（毫秒）

1100×740 逻辑窗口，加载 Mao 并预置实际 Metal 纹理/几何；10 次预热后 100 次真实鼠标移动事件，每次执行 GPUI `draw` 和 arena 清理。测量输入分发、布局、CPU 绘制，不提交 GPUI 的 GPU 合成，也不运行异步预览生产器。

## 已落实的改动

1. **保留场景和 GPU 资源。** 视口变化沿用同一个 `Arc<DrawableFrame>`，不重复同步模型或上传几何；模型变化只更新有差异的顶点/索引。变形涉及多个网格时打包到不可变缓冲块，常规块上限 4 MiB。已有 GPU 提交引用的资源不会被覆盖。
2. **合并 render pass。** 同一目标的连续绘制共享 encoder；需要读取目标的混合模式在 blit 前结束 pass，保持绘制顺序。Replace 直接绘制到输出纹理，移除最终全屏复制。
3. **缓存原始遮罩。** 相同来源的消费者共享遮罩；几何、纹理内容版本、repeat 和密度变化会失效。密度向上取二次幂，连续缩放可以复用，并在超出附件预算时回退精确密度。隐藏消费者不分配遮罩；预算按实际共享资源计数。
4. **限制旧帧积压。** 生产线程最多一个 GPU 命令在途，工作期间的新请求合并为最新请求。允许当前场景已完成的旧视口帧按请求序号单调显示，图像和命中几何使用同一个 transform。编辑、尺寸变化、文档切换和重连仍拒绝不兼容的帧。
5. **收窄界面失效。** 平移、缩放、连续顶点/透明度预览通知画布和独立状态栏；帧到达只通知画布。文档面板保持缓存，首次编辑和提交仍更新文档状态。
6. **优化属性预览。** SDK 增加 `set_mesh_opacity` 和 `ChangeKind::Appearance`，保留已准备的拓扑，继续走标准求值器处理参数/父级外观。编辑事务复用 `PreviewState`，外观变化复用命中几何，透明度预览节流从 16 ms 改为 1/120 秒。

在这次数据中，Mao 热平移每帧为 **1 个 pass、0 次几何上传、0 次遮罩重绘**。全部 260 个网格变形为 **1 次打包顶点上传**；索引沿用已有缓冲。300 次缩放的遮罩重绘从精确密度路径的 4200 次降到 350 次，密度始终不低于请求值。

## 测量方法

- Apple M4，10 核 GPU，16 GB 内存，macOS；本机 Release，未开启 Metal HUD，测量期间没有并行运行本次编译/测试任务。
- 主屏配置为 3840×2160、逻辑 1920×1080、120 Hz；另有 60 Hz 副屏。这是显示配置，不能作为应用实测帧率。
- 每个模式预热 5 次，再保留 300 次；分位数使用 nearest rank。CSV 未过滤异常值。
- Metal 测试的逻辑画布为物理尺寸的一半，scale factor = 2。绘制后直接等待对应命令完成，同一时刻只提交一个预览命令。
- `submit_ms` 从编辑开始累计到 command commit，包含编辑、快照、资源准备和 Metal 编码；`edit_ms`、`scene_ms` 是其中的子阶段。
- `complete_ms` 从编辑开始累计到 GPU 完成等待返回，包含排队和线程唤醒；`gpu_ms` 为 Metal `GPUEndTime - GPUStartTime`，完成后读取。
- `mesh_edit` 和 `deform_all` 对不可变场景做位置变化，包含快照复制与渲染器同步，但不包含 SDK 变形/参数求值。`opacity_edit` 使用真实 Editor/SDK 编辑和场景求值。导入、首次纹理上传、首帧和保存不在热路径样本内。
- 模型来自本地忽略目录，资源不随提交发布。Mao 260 个 drawable；Shirousagi 24 个。

```sh
cargo run --locked --release -p editor-render --example interaction_benchmark -- \
  models/local/mao/runtime/mao_pro.model3.json 300 1280 800

KASANE_BENCH_MODEL="$PWD/models/local/mao/runtime/mao_pro.model3.json" \
  cargo test --locked --release -p kasane-editor --bin kasane-editor \
  canvas_ui_cpu_benchmark -- --ignored --nocapture

./scripts/build-app.sh
```

## 正确性回归与接口约定

最终编辑器 workspace 68 项、Metal 像素测试 12 项、SDK Observe 13 项通过；Core/SDK 的完整回归也通过。默认忽略的 GPUI 性能测试已分别在 Debug 和 Release 显式运行。[验证摘要](benchmarks/2026-09-28/validation.txt)。

- 编辑器 workspace 测试覆盖画布命中/坐标、连续平移、透明度、撤销、文档/尺寸/激活切换，以及 GPUI 原生 Metal 合成。
- Metal 像素回归覆盖 packed buffer 偏移、已有提交的不可变数据、缓存失效、共享遮罩预算、透明与反向遮罩、嵌套 offscreen、目标读取混合及 UV 方向。
- Core/SDK/Observe 回归验证外观修改保留 prepared topology，同时更新求值结果。
- `ChangeKind::Appearance` 是新增枚举分支，下游 exhaustive match 需要适配。`AuthoringSession::document()` 提供只读借用；原 `sync_model` 入口保留，并新增共享快照入口。
- 每个 MetalRenderer 的生命周期必须使用同一个 command queue；成功 encode 后先 commit，再 encode 下一帧。跨帧缓存依赖该队列的执行顺序。无纹理 revision 的宿主每帧重新生成遮罩，以免显示过期内容。

## 尚待完成的 120 fps 验收

在主屏的 Release 应用中测量持续输入到显示提交的完整链路，并继续追踪超预算长尾。GPU 输出/offscreen 纹理仍逐帧分配；复杂嵌套混合、更多模型、长期动画与全量 SDK 变形求值需要各自工作负载的采样。本次结果确认热路径大幅缩短，尚不构成所有场景稳定 120 fps 的保证。
