# Mao 40-instance mipmap-aligned baseline

Environment: Apple M4, macOS, 1280x720, Release builds, 5 second warmup,
15 second sample. Native uses OpenGL; Godot 4.7.2 Mono uses Forward+ / Metal.
Both stacks generate model texture mipmaps and use linear mipmap filtering.

The workload uses 40 independent Mao instances in a 10x4 grid. Compared with
the earlier 20-instance 5x4 workload, this approximately preserves each
model's on-screen size while doubling Core updates, drawable processing,
masking, and draw calls.

| Case | FPS | p50 ms | p95 ms | p99 ms |
| --- | ---: | ---: | ---: | ---: |
| `cubism-native` | 59.99 | 16.56 | 17.70 | 18.52 |
| `ayagami-native` | 40.02 | 25.23 | 26.15 | 26.52 |
| `purism-native` | 85.53 | 10.86 | 14.16 | 14.88 |
| `cubism-godot` | 43.80 | 22.80 | 23.42 | 23.67 |
| `ayagami-godot` | 44.36 | 22.51 | 23.07 | 23.49 |
| `purism-godot` | 59.37 | 16.56 | 17.74 | 20.15 |

All Godot cases reported 3,321 draw calls, 40 mask viewports, 3,041,280 mask
pixels, and zero mask resizes during sampling. None of the six cases reached
the 120 Hz display ceiling.

These are single-run calibration measurements. Use interleaved repeated runs
and compare medians before treating small differences as significant. Native
and Godot results measure different rendering stacks and graphics APIs; compare
Core providers within a host, not Native FPS directly against Godot FPS.
